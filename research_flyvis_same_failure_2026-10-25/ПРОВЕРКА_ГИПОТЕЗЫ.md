# Проверка совпадения причины и одной замены уверенности

25.10.2026, Москва. Первоначальная СВОДКА.md сохранена. Здесь записаны результаты выполненных после неё проверок, а не изменение прежнего вывода задним числом.

## 1. Зависит ли считыватель от правильного образца

Выполнена изолированная подмена всей модели цели: вместо её 68 коэффициентов используются коэффициенты трёх чужих наблюдавшихся объектов. Поисковая активность, рекуррентное состояние, вырезка, нормировка и геометрия остаются общими. Каждая чужая модель пересчитывает все 721 отклик и собственный максимум. Константа регрессии опущена одинаково во всех условиях: на стандартизованную высоту пика и локальный центр она не влияет; это отдельно проверено.

Для строгого сравнения нужны три известных разных наблюдавшихся идентификатора из других обучающих видео с точно такой же маской рамки. Так подобраны 1254 из 2188 эпизодов, 4844 запроса; основной показатель центров считается по 1545 строкам с положительной меткой на всех 26 видео. У остальных строк каждого варианта проверено воспроизведение исходного ответа; они не выданы за строгий контроль личности.

| Представление | Полезные центры со своим образцом, среднее по видео | С тремя чужими образцами, среднее по видео | Парная разность, п.п., 95% ДИ | Видео с положительной разностью |
|---|---:|---:|---:|---:|
| D | 26,49% | 9,91% | +16,58 [11,60; 23,64] | 26 из 26 |
| Штатная C | 26,52% | 8,65% | +17,87 [11,68; 26,43] | 26 из 26 |
| Вход глаза R1 | 8,11% | 7,10% | +1,00 [−2,04; 3,50] | 16 из 26 |

Источник: runs/z13_template_swap_20261025/recovery1/report.json → arms → D/C/R1 → per_video и paired. Первичные карты, центры, признаки полезности и интервалы проверены независимо: independent_audit.json в том же каталоге. Для каждого варианта воспроизведены все 8326 исходных строк. Завершение: controller_result.json, exit_code=0, all_owned_ended=true. Научный итог опубликован коммитом `5e39f3ab939aaeaeee934f1182fcaed1a1a4515d`.

Вывод: правильный образец существенно помогает действующему считывателю на представлениях C и D. Общее объяснение «текущий фильтр игнорирует образец» этим сравнением не поддерживается. Случай Goroshin et al. нельзя автоматически считать установленной причиной наших ошибок и основанием переноса их вспомогательного обучения.

Ограничения: правильная история остаётся в общем состоянии сети; проверяется добавочный вклад модели цели. Чужие объекты не подобраны по одному классу и внешнему сходству. Поэтому не доказано различение похожих экземпляров одного класса. R1 с интервалом, включающим ноль, нельзя объявлять не использующим образец. Это не новая модернизированная версия и не прирост HOTA.

Большой средний вклад образца также не исключает переключения на заметный объект в отдельных трудных кадрах. У Goroshin et al. случайный образец тоже ухудшал общую метрику; их механизм не означает полного игнорирования образца во всех кадрах. Этот опыт подтверждает средний вклад образца, но не опровергает механизм статьи для конкретного подмножества наших ошибок.

## 2. Исправляет ли отказ контраст в выбранной точке

Проверена одна фиксированная замена: стандартизованный отклик своего фильтра в его максимуме минус средний стандартизованный отклик трёх чужих фильтров в этой же колонке. Центр и последствия его применения не меняются. Все последствия взяты из сохранённого точного разбора первого сопоставления, а не из ошибки центра.

На одинаковых 4844 диагностических запросах отбирается ровно 49 ответов каждой формулой. Ничьи разрешаются по номеру строки; подбора коэффициента или порога по результату нет.

| Представление и формула | Полезные вмешательства | Вредные | Нейтральные | Неизвестные |
|---|---:|---:|---:|---:|
| D, прежняя высота пика | 0 | 0 | 49 | 0 |
| D, новый контраст | 1 | 2 | 46 | 0 |
| C, прежняя высота пика | 0 | 0 | 49 | 0 |
| C, новый контраст | 3 | 1 | 45 | 0 |
| R1, прежняя высота пика | 0 | 0 | 49 | 0 |
| R1, новый контраст | 0 | 3 | 44 | 2 |

Источник: runs/z13_specificity_gap_20261025/report.json → counts. Основная разность D нового контраста с прежним баллом: −0,0485 п.п. [−0,1949; +0,0694]; ключ paired/Dgap-D_height. Метрика каждого видео — число полезных минус число вредных вмешательств, делённое на число всех известных допустимых запросов; затем берётся среднее по видео. Нижние границы всех четырёх обязательных сравнений не положительны, primary_pass=false. Итоги по отдельным видео, состав отбора и интервалы независимо пересчитаны из rows.json. Завершение: controller_result.json, exit_code=0, all_owned_ended=true.

Эта фиксированная формула не прошла критерии и не продвигается к обучению или HOTA. Большое изменение карты при подмене образца не означает, что простая разность откликов распознаёт полезность поправки для сопоставления. Числа C и R1 не спасают основной исход D.

Это ретроспективная проверка при фиксированной доле отбора на строгом подмножестве, использующем известную наблюдавшуюся личность для построения подмены. Она не является готовым правилом допуска без разметки и не заменяет калибровку только на обучающей части.

## 3. Что установлено и что остаётся

Установлен существенный вклад образца в нахождение центра C/D. Проверенная замена оценки уверенности не дала подтверждённой пользы для сопоставления. Полная причина ненадёжного вмешательства этим не установлена: остаются разрыв между качеством центра и назначением, доступность правильного кандидата и обучение отказу в реальных состояниях трекера.

Проверка текущего кода установила два различия, существенных для следующей правки. scripts/z13_data.py:label_frame возвращает kind=−1 при неизвестной исходной личности или неприемлемом расстоянии до её определения. scripts/z13_train.py:train и scripts/z13_spatial_train.py:train обучаются только на kind≥0. Поэтому неизвестные исходные образцы не становятся автоматически примерами отказа. При этом неизвестная личность не доказывает ложность детекции: превращать все такие строки в отрицательные метки нельзя.

Второе различие: tracking/z13_ridge_localizer.py строит наблюдаемую гауссову цель и гребневую модель по образцу, затем получает уверенность из стандартизованной высоты пика. Обучаемый отдельный вариант отсутствия цели из исходного Readout в tracking/z13_readout.py в этот путь не входит. Это факт об интерфейсах; его причинный вклад в плохой отказ пока не измерен. Наличие отрицательных колонок внутри наблюдаемой рамки не равно обучению на поисковых кадрах без нужного объекта.

Старое считывание с отдельным вариантом отказа также не дало подтверждённой общей пользы стенду. Поэтому наличие такого выхода само по себе не является исправлением; простой возврат прежней головы из этих наблюдений не следует.

Следующий обоснованный узел — проверить обучение отказу для трёх разных событий: правильный образец без цели в поиске, заведомо неверный образец и чужой похожий объект. Это ближе к различию N/H в SiamMOT, чем гипотеза полного игнорирования образца. До нового обучения нужны проверяемые правила меток и отличие от уже испытанных оценок полезности; новая реализация пока не объявлена готовой.

Прежние ошибки запуска и их источники сохранены; восстановление не изменяло научный код, допуски и исходный срок. Архитектурная схема показывает новую формулу жёлтой испытанной ветвью. В подборку подтверждённых улучшений она не добавляется. Сравнение правильного образца с намеренно подменённым — диагностический контроль, а не улучшение относительно прежнего считывания.

Для обоих шагов прирост HOTA, процент к основному стенду и доля измеренного потолка не определены.
