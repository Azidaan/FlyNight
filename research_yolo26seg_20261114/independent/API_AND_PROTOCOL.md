# 1. Установленный путь выполнения

Проверены файлы установленного Ultralytics 8.4.84 без импорта модели и без запуска видеокарты. Готовая экземплярная сегментация YOLO26 поддерживается. Точка входа — `YOLO(absolute_checkpoint_path).predict(source=bgr_numpy, ...)`, а не `track()`. Для проверки исходных пикселей необходимо явно установить `retina_masks=True`: `models/yolo/segment/predict.py`, метод `construct_result`, масштабирует рамки к оригиналу и вызывает `utils/ops.py::process_mask_native`. На выходе `result.masks.data` имеет форму N×H×W исходного изображения; `result.boxes.xyxy`, `cls` и `conf` относятся к тем же индексам. При отсутствии объектов `masks=None`; пустые предсказанные маски удаляются вместе с соответствующими рамками. Нельзя считать число таких удалений восстановимым из конечного результата без отдельной регистрации промежуточного этапа.

Входный массив OpenCV имеет порядок каналов BGR. `engine/predictor.py::preprocess` сам переставляет BGR в RGB для массива изображения. Повторная перестановка перед `predict` исказит цвет. Для воспроизводимости явно сохранить `imgsz`, `conf`, `iou`, `max_det`, `retina_masks`, `rect`, `half`, `device`, `classes`, `agnostic_nms`, а также фактическое `end2end` модели. Метод `predict` по умолчанию задаёт `conf=0.25`, `batch=1` и `rect=True`; это не тождественно пустому значению `conf` в общем YAML. Настройки фиксируются до результата и не меняются после просмотра масок.

При `end2end=True` локальная `utils/nms.py::non_max_suppression` фильтрует по уверенности и ограничению числа результатов; обычный порог пересечения NMS не используется. В native-постобработке масок применяется фиксированное условие logit>0; дополнительных подбираемых порогов для диагностического опыта не требуется.

Установленные исходники содержат местные изменения: `process_mask_native` обрабатывает увеличение масок порциями с бюджетом 32 000 000 пикселей; `detect/predict.py` поддерживает переопределение IoU для TrackTrack. Поэтому номер пакета не заменяет контрольные суммы фактических файлов. Не обновлять пакет ради опыта.

# 2. Готовые веса и обучение

Официальные `yolo26n-seg.pt` уже обучены сегментации на COCO и допускают первоначальную проверку без собственного обучения. Имя входит в `GITHUB_ASSETS_NAMES`, а установленный загрузчик использует выпуск `ultralytics/assets` `v8.4.0`. Для паспорта требуется точный URL и SHA скачанного файла, а не только имя. В момент первичного чтения веса YOLO26-seg под `weights` не найдены; скачивание выполняет основной агент. Источник готовых масок: [Ultralytics, Instance Segmentation](https://docs.ultralytics.com/tasks/segment).

Основной обученный детектор YOLO26 можно использовать как источник рамок и классов, но рамка не определяет принадлежность каждого пикселя. Простой перенос рамок в разметку масок обучал бы прямоугольники вместе с соседом и фоном. Стандартная разметка Ultralytics для сегментации требует многоугольник отдельного объекта. Официальная автоматическая разметка объединяет детектор с отдельным SAM: детектор даёт рамки, SAM — предполагаемые маски. Эти маски остаются псевдоразметкой и нуждаются в проверке; ранее SAM слил машины в 2179. Источник: [формат данных и автоматическая разметка Ultralytics](https://docs.ultralytics.com/datasets/segment).

Обучение сегментации только по рамкам возможно как отдельный метод слабой разметки: BoxInst использует специальные ограничения проекций маски на рамку и согласованности соседних пикселей. Это иной обучающий эксперимент, а не переключение режима готового детектора. Перенос весов детектора в новую сеть сегментации может инициализировать совпадающие слои, но не обучает отсутствующую масочную часть. В локальном `nn/tasks.py::load` загружается пересечение совместимых параметров. Первичный источник метода: [Tian et al., BoxInst](https://arxiv.org/abs/2012.02310).

# 3. Предлагаемое назначение без подбора порогов

Предложено до получения новых результатов: сохранить все маски, рамки, классы, уверенности и их индексы. Для исходных ROI (сохранённых областей сравнения) построить матрицу геометрического IoU рамок. Ограничение классов задаётся заранее по соответствию названий, поскольку индексы классов COCO и собственного детектора могут различаться. Для каждой маски допускается не более одного ROI, для каждого ROI — не более одной маски; общее назначение максимизирует сумму IoU. Фиктивные пустые варианты имеют нулевой балл. Назначение с нулевым пересечением считается пропуском. При равных баллах используется фиксированный порядок исходных индексов; равенство регистрируется как неоднозначность. Малое положительное IoU не объявляется доказательством правильного объекта.

До общего назначения сохраняются лучшие варианты каждой строки. Если два ROI предпочитают одну маску, фиксируется конкуренция за маску. Это ещё не доказательство слияния физических объектов: две рамки сами могут перекрываться. Непосредственное доказательство смешения — попадание пикселей ручных видимых ядер двух объектов в одну автоматическую маску. Показать абсолютные числа и доли, не вводить новый подбираемый порог «достаточного» слияния. Отсутствующая маска считается отказом и остаётся в знаменателе; незаметная замена полной рамкой запрещена.

Указанная процедура — рекомендация до запуска. Фактически выбранное правило основного агента должно быть зафиксировано в протоколе. Независимый аудит проверит именно зарегистрированное правило и отдельно отметит расхождение с рекомендацией; результатом нельзя задним числом оправдать изменение правила.

# 4. Независимые числа

Для каждой автоматически выбранной маски вычисляются доля покрытия ручного видимого ядра цели, число и доля пикселей ядра соседа, перекрывающих объектов, фона и неопределённой области. Ручное ядро является подмножеством видимой машины; низкую долю пикселей автомаски внутри ядра нельзя автоматически назвать низкой точностью полного контура. Неизвестные пиксели сохраняются неизвестными. Числа считаются на одинаковой исходной сетке изображения, после проверки размеров, типа и диапазона значений маски.

Косинусное сходство пересчитывается из сохранённых векторов в float64; проверяются конечность, нормы и соответствие индексов. На одинаковой истории сравнивается разность сходства со своим и чужим кандидатом. Отдельно учитываются отказы и решения, полученные после зарегистрированных ограничений. Локальное ранжирование не выдаётся за судьбу ID полного трекера.

Время полного пути измеряется с синхронизацией CUDA до и после, после отдельно учтённого прогрева. Сохраняются все повторы и их порядок; медиана и 95-й процентиль пересчитываются независимо. Поле `result.speed` само по себе не включает все этапы чтения, копирования масок, назначения и последующего извлечения признаков. Пиковая выделенная и зарезервированная видеопамять измеряются с явным сбросом статистики пиков и фиксацией уже загруженных моделей. Малый вес checkpoint-файла не равен малому пику памяти процесса.

# 5. Граница проведённой работы

На этом этапе выполнены только чтение локальных исходников, сверка первичных источников и подготовка независимых правил аудита. Пакеты, веса и общие документы проекта не менялись; видеокарта данным агентом не использовалась. Новая сеть в данной ветви ещё не объявлена полезной.
