# Одна проверка цели обучения выборщика кандидатов

23.10.2026. Предложение по итогам исследования. Не регистрация запущенного опыта, не разрешение расходовать новый бюджет. Перед исполнением нужна отдельная карточка с хешами, точными критериями, стоимостью и сроком по Москве.

## 1. Вопрос и действие

Улучшит ли выбор центров на той же FlyVis замена метки «точен и лучше Калмана» на «точен относительно цели», при прежней проверке реальной полезности? Меняется обучение узла, который выбирает выходной центр. Внешний фильтр над прежним центром не добавляется.

Старая метка для известного присутствующего объекта: `err <= 0.25*scale AND err < err_pred`. Новая: `err <= 0.25*scale`. Для `kind=0` оба варианта имеют нулевые метки; `kind=-1` исключается из обучающей потери. Это локализационная цель, а не полноценная разметка идентичности всех соседей. Сам порог 0,25 не меняется. Метрика успеха при оценке сохраняет оба старых условия.

## 2. Единственное изменяемое условие

Использовать существующий комплект candidate_data104, без объединения с картами balanced/hinge. Контроль — именно прежний выборщик на тех же 104 видео, а не одна из лучших найденных позже версий. Фиксируются нормировка, точки кандидатов, входы, архитектура, начальные параметры и сида 0/1/2, последовательность обучающих примеров, оптимизатор, скорость, число обновлений и предъявлений. В опыте104 бюджет равен прежним 50 проходам по числу известных строк fit20; это не 50 полных эпох по104.

Веса положительного класса взять из прежнего контроля. Их пересчёт вслед за новой долей положительных был бы дополнительным условием. Не перенастраивать их после исхода. Возможный неудачный вес — ограничение этой одной проверки, а не повод незаметно расширять подбор.

Нужно восстановить старые упаковку, предсказания и контрольные строки из сохранённых моделей. Обучение завершённых контролей повторять лишь при необходимости парной проверки воспроизводимости, не автоматически.

## 3. Не более трёх подготовительных проверок

### 3.1. Мишень и смысл меток

Только на обучающих104: число близких к цели кандидатов, становящихся отрицательными исключительно из-за Калмана; распределение по видео; число случаев без какого-либо близкого кандидата. Не объявлять малое или большое число причиной результата без парного опыта. Если метки везде совпадают, остановить эту замену как тождественную контролю.

### 3.2. Воспроизведение и отсутствие утечки

Проверить хеши, состав видео, отсутствие пересечения104/train26/dev35/75; воспроизвести сохранённые выходы старого контроля с заранее назначенным допуском и неизменным выбором кандидата. Все новые метки используются только при обучении. Неизвестные исходы не заполнять интерполяцией, разметку будущих кадров не включать во входы модели.

### 3.3. Стоимость

Короткий замер чтения кэша и нескольких шагов обучения, без вердикта об эффективности. Рассчитать полный бюджет D/C/R1, активности/карты, трёх сидов и анализа. Записать реальный предел и независимое завершение своего дерева до ближайшего буднего07:40МСК. До замера не обещать минуты или часы. Если бюджет не согласован или не помещается, подготовку сохранить и не запускать большой этап.

## 4. Сравнения

Для каждого D/C/R1 сравнить новую и старую цель при тех же входах. Обязательно оставить вариант без дополнительных сырых векторов активности: он всё ещё читает карту мухи. Настоящий контроль без ядра — R1, а не этот вариант. Основное решение не выбирать по лучшему сиду; показывать три сида и заранее заданный ансамбль.

Основной функциональный показатель — прежняя средняя по видео доля полезных центров среди `kind=1`. Основное сравнение заранее фиксируется для ветви с активностью D; результат ветви только по карте не подставляется вместо него после просмотра. Предлагаемый минимальный эффект D_new − D_old: не менее2п.п. при положительной нижней95%границе. Это заимствованный практический порог прежнего опыта выбора кандидатов, не оценка статистической чувствительности и не эквивалент HOTA.

Одновременно новая D должна превзойти сильный старый вариант чтения только карты и R1 с той же новой целью; нижние границы парных интервалов положительны. Сравнение D_new с C_new и с прежним считыванием C обязательно публикуется: преимущество над R1 не устанавливает пользу обучения ядра D. Не менять главное сравнение на C после просмотра D. Если улучшилась C, это отдельный частный результат, а не спасение критерия D.

Дополнительно: точность выбранного центра без сравнения с Калманом; прежняя полезность; строгое ухудшение центра; известная недоступность цели глазу; неизвестные исходы. Доли отбора1/2/5% показывать с исходными знаменателями, одинаковой квотой и обработкой равных баллов. Балл BCE не называть калиброванной вероятностью. Увеличение новых обучающих положительных не изменяет критерий полезности при оценке.

Единица доверительного интервала — видео. train26 уже многократно использован: результат поисковый. Дополнительные интервалы показываются как отдельные описательные сравнения, без заявления общей 95% гарантии по всей таблице. Отрицательный либо пересекающий ноль интервал не доказывает отсутствия информации в ядре.

## 5. От локализации к стенду

Положительный функциональный исход ещё не решает допуск поправок. Для следующей стадии потребуется отдельная фиксированная политика. Нельзя объявить верхний1% по всей проверочной выборке исполнимым причинным порогом или считать 50% полезных гарантией безопасности.

Сохранить прежнее правило90% полезных при не менее50 вмешательствах, если речь идёт об этом критерии отказа; не ослаблять его из-за результатов нового узла. Порог на обучающих предсказаниях не является независимым подтверждением. Для честной калибровки понадобится заранее выделенная по видео часть train или предсказания вне обучающей складки, одинаково для новой и контрольной версии. Все104 уже использовались в обучении старого выборщика: «свободная калибровочная выборка» не возникает автоматически. Соответствующая дополнительная стоимость должна войти в отдельный бюджет. Dev35 не использовать для настройки.

После заморозки допустима проверка переноса на dev35, затем стенд в согласованных вариантах: без поправки, прежняя D, новый узел на R1, новый узел на D; C — контроль штатной мухи. Изменение интерфейса вмешательства не совмещать с изменением считывателя в одном сравнении. Если исследуется защита сопоставления Калмана, сначала отдельный одинаковый контроль без FlyVis.

Практический критерий HOTA сохранить: новаяD − стенд не менее+0,10 пункта совокупной HOTA и положительная нижняя95%граница парной разности по видео; преимущество над прежнейD и над тем же узломR1. Предъявить сравнение со штатнойC. AssA, IDSw, вред отдельным видео и скорость обязательны как пояснение. Несколько сидов обучения проверяют до выбора по dev, не выбирают лучший по HOTA. Отложенные75 остаются однократной финальной проверкой после фиксации.

## 6. Решение по исходу

Если изменённых меток нет — данная проверка не нужна. Если новая цель не улучшила прежнюю полезность — эта версия не принимается; причинная гипотеза не подтверждена. Если улучшила только точность без пользы относительно Калмана — частный эффект, не решение задачи. Если локализация и отказ проходят, но HOTA не проходит практический критерий — стенд не улучшен в требуемой мере.

Архитектурный запасной вариант — обучаемое межкадровое соответствие по KeepTrack. Перед ним нужен отдельный протокол: частичные истинные соответствия, неизвестные пары, отличие размеченных5Гц от входных30Гц, проверка координат и маски недоступности. Синтетическое удаление кандидата обучает отсутствию соответствия, но не имитирует все реальные перекрытия. Полную сложную сеть не строить без проверки наличия нужных обучающих пар.
