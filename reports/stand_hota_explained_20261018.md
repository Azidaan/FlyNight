# 1. Состав стенда и роль исследуемой модели FlyVis

Стенд решает задачу многообъектного трекинга: обнаруживает объекты в видеопоследовательности и сохраняет их идентификаторы между кадрами. Исследуемый компонент — модель зрения мухи FlyVis. Детектор YOLO26, трекер XYWHByteTrack и модуль сопоставления внешности MASA образуют окружение для проверки пользы её модернизации.

| Компонент | Назначение в нашем стенде | Отношение к FlyVis |
|---|---|---|
| YOLO26s | Находит объекты и выдаёт рамки, классы и оценки уверенности. | Внешний детектор, общий для сравниваемых вариантов. |
| XYWHByteTrack | Предсказывает положение объектов, сопоставляет обнаружения с траекториями, создаёт и завершает траектории, сохраняет идентификаторы. Это адаптация ByteTrack с независимыми шириной и высотой рамки в фильтре Калмана. | Базовый трекер, в который подключена проверяемая поправка FlyVis. |
| MASA-R50 | Извлекает признаки внешности объектов. В нашей процедуре сшивки сходство этих признаков вместе с геометрией, простой внешностью и входом глаза помогает связать разорванные части траектории. | Сторонняя модель, не являющаяся частью FlyVis. |
| FlyVis со считывателем | По образцу объекта и последовательности наблюдений предлагает положение центра потерянного объекта. При прохождении порога заменяет центр прогноза перед сопоставлением. | Исследуемый компонент. В рассмотренном опыте он дополняет трекер, а не заменяет его. |

MASA — сокращение от *Matching Anything by Segmenting Anything* («сопоставление произвольных объектов с использованием сегментации»), Li et al., CVPR 2024. Метод обучает признаки для узнавания одного объекта на разных изображениях. В нашем стенде используется готовая модель MASA-R50 на основе ResNet-50: по рамке объекта получается числовое описание его внешности. Сегментация SAM в нашей процедуре извлечения этих признаков не запускается. Источник метода: [статья MASA](https://arxiv.org/abs/2406.04221).

Например, если после перекрытия трекер присвоил вновь найденному объекту другой номер, процедура сшивки может связать конец прежней траектории с началом новой. MASA предоставляет признак сходства внешности для этого решения; она не гарантирует правильного восстановления номера. Сшивка выполняется по собранным фрагментам траекторий, поэтому итоговые числа учитывают дополнительную обработку после покадрового трекинга.

# 2. Что обозначают варианты A, B, C и D

Вариант A — исходный стенд без поправки положения по FlyVis. Вариант B — контроль с небольшой временной нейронной сетью без FlyVis. Вариант C использует штатное замороженное ядро FlyVis и обученное считывание. В варианте D дообучены ядро FlyVis и считывание положения объекта.

Таким образом, D действительно включает модель мухи, но обозначает весь проверяемый модуль «ядро FlyVis + считывание», а не отдельную нейронную сеть другой природы. В приведённых результатах D — конкретная пространственная версия З13 v2, использованная в опыте, завершённом 15.10.2026. Более поздние изменения считывания в эти числа не входят.

Сравниваемые системы «XYWHByteTrack + MASA» и «XYWHByteTrack + D + MASA» используют одинаковые детекции и одинаковую процедуру сшивки. Во второй системе дополнительно допускается поправка центра потерянной траектории по сигналу D. Скорость, размер рамки, ковариация фильтра Калмана и правила сопоставления напрямую этой поправкой не заменяются. В сшивке обеих систем используется одна и та же модель пары; её признаки не включают активность ядра FlyVis.

# 3. Сопоставимые результаты нашей проверки

Проверка выполнена на одних и тех же 35 видео набора разработки BDD100K MOT с обработкой исходных кадров около 30 кадров/с и оценкой на кадрах с разметкой. HOTA — общая метрика, учитывающая качество обнаружений и сохранения соответствий объектов между кадрами; IDF1 — метрика правильности присвоения идентификаторов. Для обеих метрик большее значение лучше. Переключения ID — случаи ошибочной смены идентификатора; меньше лучше.

| Вариант системы | Поправка потерянного объекта | Сшивка с признаками MASA | HOTA | IDF1 | Переключения ID |
|---|---|---|---:|---:|---:|
| XYWHByteTrack, без сшивки | Нет | Нет | 61,3361 | 69,2640 | 1990 |
| A: XYWHByteTrack + сшивка с MASA | Нет | Да | 61,6548 | 70,3778 | 1726 |
| B: тот же стенд + временная сеть без FlyVis | По сигналу контрольной сети | Да | 61,6576 | 70,3749 | 1733 |
| C: тот же стенд + штатная FlyVis с обученным считыванием | По сигналу FlyVis, ядро заморожено | Да | 61,6551 | 70,3677 | 1745 |
| D: тот же стенд + дообученная FlyVis со считыванием З13 v2 | По сигналу FlyVis, ядро дообучено | Да | 61,6727 | 70,4179 | 1721 |

Числа в таблице — общие метрики по совокупности видео. Для проверки эффекта D отдельно рассчитана средняя парная разность HOTA по видео с 95%-м доверительным интервалом: каждое видео сравнивается само с собой в двух вариантах системы.

| Проверяемый эффект | Средняя разность HOTA по видео | 95%-й доверительный интервал | Вывод по этому опыту |
|---|---:|---|---|
| D − A: польза добавления всего модуля D | +0,0087 | [−0,0299; +0,0561] | Улучшение не подтверждено. |
| D − B: преимущество над временной сетью без FlyVis | −0,0281 | [−0,1518; +0,0706] | Преимущество не подтверждено. |
| D − C: польза дообучения ядра FlyVis | +0,0078 | [−0,1338; +0,1188] | Преимущество не подтверждено. |

Разность общих значений HOTA для D и A равна +0,0179 пункта, или +0,029% относительно A. Она отличается от средней разности по видео: общая HOTA рассчитывается по объединённым статистикам оценщика, а средняя парная разность даёт каждому видео одинаковый вес. Во всех трёх парных сравнениях доверительные интервалы включают ноль. Следовательно, этот опыт не подтверждает повышение качества полного трекинга за счёт D; он также не доказывает равенство вариантов или бесполезность FlyVis.

Набор разработки использовался неоднократно, поэтому эти результаты не являются независимой итоговой проверкой. Улучшение локализации объекта в более поздних опытах оценивается отдельно и не заменяет измерение HOTA полного трекера.

Условия вмешательства: [протокол опыта](/E:/Dissertation/runs/z13_shared_masa_hota_v1_20261015/full/protocol.json). Реализация поправки: [SpatialLocalizer](/E:/Dissertation/tracking/z13_spatial_localizer.py). Признаки сшивки: [stitch_eval_v2.py](/E:/Dissertation/scripts/stitch_eval_v2.py), `HEADS["base_masa"]`.
