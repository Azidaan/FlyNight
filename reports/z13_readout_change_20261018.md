# Правка модели цели: постановка и проверенные основания

18.10.2026. Действие согласовано автором: доработать узел модели цели, чтобы проверить возможность превзойти прежний считыватель на той же D. Длительное обучение ядра не выполняется.

## 1. Что измерено до правки

Источник — `runs/z13_readout_overlap_20261018/report.json`; строки групп — `cells.json`. Сопоставлены 8326 строк, из них 1786 положительных. Проверены уникальность ключей, одинаковые видео, метки, размер цели и ошибка опорного прогноза. Неизвестные исходы не считаются ошибками.

| Результат локализации | Число положительных строк |
|---|---:|
| Оба считывателя дают полезный центр | 105 |
| Полезен только прежний считыватель | 209 |
| Полезна только новая модель цели | 180 |
| Ни один не даёт полезного центра | 1292 |

Новая модель добавляет полезные центры на 24 видео, но теряет ответы прежнего считывателя на 25 видео. В группе потерь медиана ошибки нового узла составляет 0,435 размера цели против 0,141 у прежнего; в 22 случаях ошибка нового превышает один размер цели. Это не только пересечение границы критерия на ничтожную величину. Оно не доказывает переключения идентичности: ошибочную цель по этим строкам не определяли.

Оракульный выбор полезного ответа между двумя центрами дал бы 494 полезных строки вместо 314. Такой выбор использует истинную разметку. Это только описание множества доступных ответов, не реализованный прирост и не потолок HOTA. Переключатель на train26 не подбирался.

## 2. Выбранная гипотеза и одно изменение

В `scripts/z13_target_model.py:fit_predict` регрессионная цель равна единице во всей наблюдаемой рамке. При этом итоговая мера требует точного центра. Из кода следует, что центр и край рамки имеют одинаковый желаемый отклик; из этого не следует, что именно эта особенность вызвала измеренные потери.

Кандидат `tracking/z13_target_center.py` заменяет только регрессионную цель: плавный гауссов пик у центра последней наблюдаемой маски. Ширина по каждой оси — четверть занятого маской размера, с нижней границей половины шага решётки. Размер восстанавливается по занятым колонкам; текущий прогноз Калмана и будущая разметка при построении цели не используются. Это приближение наблюдаемой рамки на решётке, а не истинная рамка кадра поиска.

Опора — [DiMP, §3.1 и §3.6](https://arxiv.org/html/1904.07220): регрессия отклика относительно центра, гауссова целевая карта; в §3.6 приведена ширина 1/4 размера цели. Мы переносим только принцип центрированной цели. Полная DiMP дополнительно обучает функцию потерь, признаки и оптимизатор; её прирост на других данных к этой пробе не относится.

Сильнейшее возражение: признаки отдельной колонки могут различать внешний вид объекта, но не положение относительно его центра. Тогда новая цель будет труднее для линейной модели и ухудшит результат. Это проверяемая версия, не повод заранее считать исправление полезным.

## 3. Сравнение и условия продвижения

Протокол — `runs/z13_target_center_20261018/protocol.json`. D, штатная C и вход глаза R1; для каждого на одних и тех же признаках считаются исходная бинарная и новая центрированная цели. Нормировка общая внутри пары. Коэффициент регуляризации (ограничения величины весов) выбирается для каждого варианта по той же сетке на прежних 20 видео train104. Все 26 видео оценки сохраняются. Подбор формы гауссовой карты по train26 не выполняется.

Перед интерпретацией исходная бинарная модель должна воспроизвести сохранённые ответы; код отказывает при несовпадении строк, выбранного коэффициента или превышении записанного допуска центров и баллов. Контроль без мухи — та же правка на R1. Он ограничен собственным набором пространственных и временных признаков и не доказывает роль коннектома.

Для продвижения кандидат на D должен иметь положительную нижнюю границу 95%-го парного по видео интервала относительно прежнего считывателя D и относительно бинарной модели цели D. Это поисковый критерий, не доказательство практической полезности для трекера. Значение 2 п.п. не трактуется как постоянная разрешающая способность train26. Дополнительно сохраняются ошибки и состав ответов при одинаковой доле отбора 1/2/5%; балл высоты пика не является калиброванной вероятностью присутствия. Поле `harmful` из прежней служебной функции означает известный исход, не выполнивший критерий полезного центра; это не измеренный вред HOTA.

## 4. Готовность и ограничения

Четыре теста узла проверяют точное воспроизведение бинарной модели, перенос центра вместе с наблюдаемой геометрией, невырожденность для одной колонки, отказ при пустой маске и способность решения восстановить заданный центр на синтетических признаках. Два теста диагностики проверяют разбиение и отказ при несопоставимых данных. Это технические тесты, не научный результат.

Первый CPU-замер завершился ошибкой загрузки весов на CUDA: `benchmark_controller_result.json`, код 1. Научных предсказаний не получено. Журнал и статус сохранены. Отдельный служебный запуск `scripts/z13_target_center_cpu_recovery.py` явно запрещает выбор CUDA перед импортом FlyVis; прежние научные файлы и их хеши сохранены. Причина — выбор устройства при импорте, а не свойства модели цели.

Окончание и стоимость повторного замера проверять по `recovery_benchmark_result.json` и `benchmark.json`. Результат полного сравнения существует только при наличии `report.json` и успешного `recovery_full_result.json`. Никаких выводов об эффекте этой правки до них делать нельзя. Контроллер завершает только собственное дерево процессов по сроку; текущие результаты этапов сохраняются.

## 5. Итог подготовки

Повторный CPU-замер завершён с кодом 0, рабочее дерево процессов закончило работу (`recovery_benchmark_result.json`). На 16 эпизодах обе цели посчитаны за 12,421 с для 544 кадров с учётом дополнения пакетов. Оценка полного сравнения — 7804,5 с, около 130 минут (`benchmark.json`). Это грубое масштабирование двух пакетов; R1 консервативно оценён как FlyVis, время загрузки не включено. Прежние 20 минут не подходят, полный прогон не запускался.

Готовая команда после отдельного согласования CPU-бюджета до 3 часов: `.venv/Scripts/python.exe scripts/z13_target_center_recovery_controller.py --budget 10800`. Запускать фоном с приоритетом Idle, отдельно открыть `scripts/z13_readout_monitor.ps1 -Run E:\Dissertation\runs\z13_target_center_20261018`. Перед запуском сохранить разрешение автора и состояние `starting`, чтобы консоль не приняла итог старого замера за итог нового прогона. Логи полного контроллера имеют отдельный префикс `recovery_full`; результаты измерения времени не затираются. Процессорная проверка не обучает ядро, но решает модели цели для каждого эпизода и выбирает регуляризацию на обучающей подвыборке.

HOTA не измерялась. Процент прироста правки и доля потолка пока не определены.
