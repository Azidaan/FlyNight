# Узел узнавания цели среди похожих соседей: что говорит литература и как проверить пользу мухи до GPU

Дата: 26.10.2026. План поиска — `outline.yaml`, поля — `fields.yaml`, разборы — `results/C01…C11_*.json`
(все прошли проверку полей; неуверенные значения помечены `[uncertain]` в каждом файле).
Чужие числа (AUC, HOTA, IDF1, rank-1) не переносятся в ожидаемую пользу нашего стенда.

## Исходная точка (числа проекта)

- Идеальное узнавание цели с тем же решением о переносе: +2,836 п.п. [+1,873; +3,831] на train26
  (`runs/z13_hybrid_fly_confirm_20261026/report.json`, `paired.true_identity-baseline`).
- Внешний вид MASA без мухи: +0,660 [+0,035; +1,302]; запас над ним ≈ 2,18 п.п.
- Прибавка мухи D к внешнему виду: +0,107 [−0,176; +0,400]; D − R1 −0,042; D − C −0,095.
- В событиях (полезные минус вредные переносы, подсчёт агента C03 по `counts`): база 39, база + D 45,
  идеальное узнавание 167 — муха закрыла 6 из 128 (≈5% запаса). AUC при этом закрыла ≈23% разрыва до 1 (C04):
  общий AUC плохо предсказывает пользу.

## Короткий ответ

1. **Литература предсказывает наш нуль.** Движение побеждает внешний вид только там, где объекты выглядят
   одинаково (DanceTrack, SportsMOT — C06) или где есть другой датчик (событийная камера — C11).
   Над сильной моделью внешнего вида добавка движения ≈ 0 (видео-ReID на MARS — C05).
   Самое близкое к нам: QDTrack, табл. 5, **BDD100K val** — добавление IoU/движения к внешнему виду
   ухудшило 50,8 → 49,8–50,1 mIDF1 (C10).
2. **Это похоже на избыточность, а не на «заглушение» слабой ветви.** Теория дисбаланса модальностей
   требует совместно обучаемых кодировщиков; у нас обе ветви заморожены, а сырой вход глаза R1 даёт тот же
   прирост AUC, что и муха (+0,006 против +0,008). Балансирующие методы усилили бы R1 так же, как муху (C02).
3. **Ветвь с α поверх MASA на сохранённых признаках ничего нового не даст**: бустинг по склейке уже может
   представить ту же функцию. α от нуля ускоряет обучение, но не меняет итог (ReZero), а большой α вредит
   (Tip-Adapter, CLIP-Adapter). Новое α добавляет только путь градиента в ядро мухи (C01).
4. **Дообучение ядра мухи на узнавание не опирается ни на одну работу.** Коннектом в FlyVis доказанно
   повышает биологическое правдоподобие, но не качество задачи; там, где был контроль, небольшая обычная сеть
   не уступала (C08). По неравенству обработки данных обученная муха не может знать больше своего входа:
   GPU оправдан, только если сырой вход глаза несёт заметно больше, чем сохранённые признаки мухи (C03, C04).
5. **Биология выбора одной цели — это история пути (прогноз положения), не внешний вид** (стрекоза CSTMD1,
   C09). Это у стенда уже есть (Калман, глаз на прогнозе). Путь лобулы (LC11/LC12/LC18) можно собрать
   из выходов FlyVis по FlyWire 783 (вклад 34 типов FlyVis во входы 0,46–0,61; T4/T5 ≤ 0,002 — расчёт агента,
   `results/C09_support/lc_inputs_flywire783.json`), но LC10a — нет; проверка требует новых карт активности (GPU).

## Математическая проверка до любого GPU (сведена из C02–C04, C06–C08, C10–C11)

Только CPU, только сохранённые признаки; оценка на fit104 с разбиением по видео; train26 уже использован
один раз — любое новое обращение к нему считается вторым и требует согласия автора.
Наименьший различимый эффект на 26 видео ≈ 0,42 п.п. (C04, по разбросу `base_D-base`).

- **Ш1. Где лежит запас.** Польза идеального узнавания по слоям (зазор MASA, темнота/пересвет/окклюзия, класс).
  Стоп роли А, если в спорном слое верхняя граница запаса < 0,42 п.п.
- **Ш2. Взаимодополняемость ошибок.** В спорном слое: «MASA ошибся — муха права» минус обратное
  (точный критерий Мак-Немара), против R1, C, скорости/геометрии и перемешанной мухи того же размера.
- **Ш3. Уникальная информация.** Условная V-информация: прирост логарифмического правдоподобия от D сверх
  [MASA + R1] против нулевого блока, бутстрэп по видео. Теоретическая оценка PAC здесь бесполезна (C03) —
  только повторные выборки.
- **Ш4. Оракул сочетания.** Истинная личность только там, где права муха, а внешний вид нет, → через тот же
  шлюз → верхняя граница пользы. Стоп, если < 0,42 п.п. или не выше того же для R1.
- **Ш5. Оракул памяти (роль Б).** Банк только из истинных меток; стоп роли Б, если верхняя граница < 0,5 п.п.
- **Ш6. Разброс ансамбля (роль Г).** Условный прирост каждой из 50 готовых моделей `flow/0000/000–049` без
  обучения; если ни одна не лучше R1 и разброс мал — дообучение 734 параметров не обосновано.
- **Ш7. Потолок входа (роль Г).** Сеть без мухи равной/большей ёмкости на кадрах R1; если вход несёт не больше
  сохранённых признаков — GPU не запускать.

Переход к GPU — только если Ш1–Ш4 проходят с порогами, записанными до расчёта, и Ш6/Ш7 оставляют место.
Пороги 0,42 и 0,5 п.п. — предложения агентов, не правила проекта; их утверждает автор.

## Расхождения и неподтверждённое

- Число спорных запросов на train26 различается по определению: 409 запросов с целью и хотя бы одним
  соседом среди размеченных строк (C03) и 501 «цель + сосед» по MASA, из них 61 с соседом выше цели (C10).
  Пересчитать единообразно при регистрации проверки.
- Пересчёт «событий» в п.п. (≈62% запаса для +2 п.п.) — грубая пропорция без весов по видео.
- Ряд таблиц восстановлен после потери галочек при извлечении текста (DanceTrack табл. 2, CSAM табл. 3).
- Препринты 2026 г. в C08 (FlyHack, ConnectomeX, распознавание с замороженной FlyVis) прочитаны только по
  страницам arXiv.

## Чего нельзя заявлять

- Нельзя заявлять, что FlyVis добавляет узнавание цели сверх внешнего вида: в литературе и в наших данных
  опоры нет. Ближайшие чужие заявки — SpikeMOT (импульсная рекуррентная модель движения для ассоциации на
  событийной камере) и CSAM (движение событий над замороженным трекером); ни одна не использует модель мухи
  с коннектомом на RGB с равными контролями без мухи (C11) — сомнение в новизне работу не останавливает.
- HOTA ничем из этого не измерялась.
