# 1. Рабочее состояние Tracker 1,0

Начало работы: 12.09.2026. Контрольный коммит до изменений: 3472a05 (`Tracker 1,0`), отправлен в GitLab/main.

Задание: измерить пользу избирательного использования слабых детекций для рождения и продолжения треков; после проверки резерва оценить обучение с весами по возрасту. Результат должен учитывать ложные рамки, ложные рождения и ошибки личности. Рост балла сам по себе результатом не считается.

# 2. Подтверждённая проблема реализации

Установленный Ultralytics: 8.4.84. В BYTETracker._second_association при fuse_score=True используется стоимость 1 − IoU × confidence и порог 0.5. При track_high_thresh=0.25 все кандидаты второго прохода имеют confidence < 0.25, поэтому стоимость больше 0.75 даже при IoU=1. Второй проход не может принять ни одну такую детекцию. BoT-SORT наследует этот код.

Минимальный пример выполнен: одинаковая рамка в двух кадрах, оценки 0.9 и 0.2. В первом кадре получен трек 1; во втором вывод пуст, трек переведён в lost. Это проверка реализации, а не результат на BDD100K.

В исходной реализации ByteTrack второй проход использует IoU без умножения на confidence: https://github.com/ifzhang/ByteTrack/blob/main/yolox/tracker/byte_tracker.py . Поэтому вариант с IoU во втором проходе вводится как отдельный инженерный контроль, не как научная новизна. Установленный пакет и исторические результаты не изменяются.

# 3. Протокол следующего измерения

Детектор: существующий кэш runs/det_cache_ctl_960, metadata: weights/baseline_seed42/best.pt, imgsz=960, conf=0.01, iou=0.7. Все кадры, включая пустые, должны учитываться. Кэш содержит 200 val-видео. Это диагностические данные, не независимый итоговый тест новой модели.

Основной трекер: BoT-SORT с компенсацией движения камеры, без ReID. Первая обязательная пара: установленное поведение против IoU во втором проходе при остальных одинаковых параметрах. Эталонные восстановления сравниваются с этим дополнительным контролем отдельно.

Сопоставление детекций с эталонными объектами: один к одному, одинаковый класс, IoU не ниже 0.5; сначала обслуживаются кандидаты выше рабочего порога. Crowd-области не считаются объектами. Реальные выходные траектории оцениваются отдельно от наличия детекции.

Журнал должен различать создание неподтверждённого трека, подтверждение, продолжение, восстановление, потерю, удаление и отклонение кандидата. Идентификаторы разметки используются только для диагностики и выбора эталонных кандидатов; трекер получает только рамки, классы, баллы и маску допуска.

Первое появление на первом кадре видео отделяется от появления внутри видео. Возраст считается в исходных кадрах разметки. Ошибки и задержки считаются также для объектов, не получивших правильного трека ни разу.
