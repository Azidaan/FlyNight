# AGENTS.md — правила для любого агента в проекте E:\Dissertation

Этот файл самодостаточен. Если пользователь говорит «прочитай AGENTS.md» —
прочитать целиком и дальше действовать по нему без дополнительных вопросов.
Файла CLAUDE.md в проекте нет намеренно: правила подключаются явно, этой фразой.

## 1. Что это за проект

Диссертация: устойчивый многообъектный трекинг (BDD100K MOT) при слабом
освещении, пересвете, окклюзии и сложном фоне. Детектор YOLO26 обучен и
зафиксирован; исследования идут на стороне трекера (FlyVis, `XYWHByteTrack`,
раздельная уверенность `q_det / q_match / q_birth / q_alive`) и на стороне
обучения детектора (взвешивание по возрасту объекта). Всё окружение
(Python, пакеты, веса, кэши) — строго внутри `E:\Dissertation`.

Главный документ — `dissertation/ЕДИНЫЙ_ПЛАН.md`: хронология, все измеренные
числа, что закрыто и почему, методические правила ([[05 План/6. Методические правила|раздел 6]]) и запреты
([[05 План/8. Запреты|раздел 8]]). Они действуют для агента так же, как для автора.

## 2. Журнал экспериментов: три файла, три роли

| файл | роль | кто пишет |
|---|---|---|
| Git | факты о коммитах | только пользователь (коммит — с его разрешения) |
| `dissertation/ЕДИНЫЙ_ПЛАН.md` | хронология, интерпретация, «Журнал изменений» | агент дописывает запись в журнал **после** фактически сделанного |
| `experiments/project_history.json` | кураторский каталог: направления, карточки экспериментов, связи с коммитами и источниками | агент — по правилам ниже |
| `experiments/metrics_glossary.json` | словарь метрик и терминов | агент — до первого использования метрики |

Окно «История проекта» (`scripts/project_history_window.py`, кнопка в панели
«Запусти меня») только показывает эти источники. Оно ничего не запускает и не
меняет; в него не добавляются действия, изменяющие Git, план или `runs/`.

## 3. Правила записи эксперимента (обязательны)

1. **Каждый эксперимент — карточка** в `experiments/project_history.json`
   (`experiments[]`). Поля `id`, `title`, `area`, `state` обязательны.
   `area` — id из `areas[]`; новое направление сначала добавляется туда.
2. **Состояние — одно из десяти:** `planned`, `ready`, `running`,
   `completed_positive`, `completed_negative`, `inconclusive`, `closed`,
   `infrastructure`, `superseded`, `unknown`. Отрицательный результат — это
   `completed_negative`, а не ошибка и не «unknown». Закрытое по заранее
   записанному критерию направление — `closed`.
3. **«Ожидалось» пишется до прогона, «получено» — после.** Поля `expected`,
   `done`, `obtained`, `decision` заполняются только тем, что подтверждено
   планом, отчётом или артефактом. Если подтверждения нет — поле остаётся
   пустым: окно покажет «Не подтверждено». Догадка в поле — нарушение.
4. **Каждое число — с адресом источника.** Метрика в `metrics[]` имеет вид
   `{"key", "value", "baseline", "subset", "source", "locator"}`, где `source` —
   путь внутри проекта (JSON/CSV/отчёт), `locator` — ключ JSON (`tiled.HOTA`)
   или строка CSV (`метрика=HOTA;col=значение`). Индексатор сверяет число с
   источником и помечает расхождение. Число без источника не записывается.
5. **Каждая метрика описана в словаре.** `metrics[].key` обязан быть ключом
   или алиасом из `experiments/metrics_glossary.json`. Новая метрика сначала
   получает запись в словаре: `title`, `ru` (что это, по-русски), `better`
   (`higher` / `lower` / `none`), при возможности `full`, `unit`, `range`,
   `tool` (чем считалась), `caveat`, `source`. Термины (ReID, DIS, q_match…) —
   в ветке `terms` с полями `title`, `ru`.
6. **Связи с Git — только настоящими hash.** `commits[]` и `commit_links` —
   короткие (7+) или полные hash существующих коммитов. Незакоммиченная
   работа коммитом не называется; пустой коммит-метка (как `3472a05`)
   отмечается как метка, а не как реализация.
7. **Доказательства — ссылками, не копиями.** `evidence[]` указывает на
   раздел плана (`{"kind":"plan_section","ref":"dissertation/ЕДИНЫЙ_ПЛАН.md","locator":"[[05 План/3.9. Измерения 09–11.09 (стенд 960, полный val где указано)|§3.9]]"}`),
   коммит, JSON, CSV, отчёт или каталог `runs/`. Большие тексты и таблицы в
   каталог не дублируются.
8. **Критерии приёмки** записываются в `acceptance[]` до прогона
   (`{"criterion", "met": null}`), после — `met` ставится в `true`/`false`
   с `evidence`. Не выполненный критерий не удаляется.
9. **Проценты к baseline** окно считает само из `value`/`baseline`/`better`;
   ноль пишется нулём. В отчётах — правило 6.9 плана: сводка «эксперимент →
   метрика → % к baseline → доля измеренного потолка».
10. **После любой правки каталога или словаря — проверка:**
    ```
    python scripts/validate_project_history.py
    python -m pytest tests/test_project_history.py -q
    ```
    Красный тест или `FAIL` валидатора означает, что карточка не принята;
    исправляется каталог, а не тест.
11. **Запись в журнал плана** (`## Журнал изменений` в `ЕДИНЫЙ_ПЛАН.md`) —
    только о фактически выполненном и проверенном, с датой и московским
    временем в формате `**ДД.ММ.ГГГГ, ЧЧ:ММ MSK** — тема`, подзаписи
    `*ЧЧ:ММ, тема.* текст` (подзапись другого дня: `*ДД.ММ, ЧЧ:ММ, тема.*`).
    Hash коммита в тексте — в обратных кавычках: `` `4690dad` ``. Так журнал
    разбирается парсером окна и связывается с Git.

## 4. Чего не делать

- Не создавать коммиты, не выполнять `reset`, `checkout`, `clean`, `stash`,
  `pull`, `fetch`, не менять ветки без отдельного разрешения пользователя.
- Не трогать чужие незакоммиченные файлы; перед коммитом показать
  `git status --short` и перечислить, что войдёт.
- Не запускать обучения, TrackEval и обработку видео ради интерфейса или
  каталога; долгие расчёты — только по правилам плана ([[05 План/9. Инфраструктура|раздел 9]],
  `Start-Process` с приоритетом Idle).
- Не сравнивать прогоны, отличающиеся более чем одним условием; не
  объявлять прирост без разброса и доверительного интервала; не переносить
  знак с коротких прогонов на полные (план, [[05 План/6. Методические правила|разделы 6]] и 8).
- Не подавать отрицательные результаты как пункты новизны; не обосновывать
  новизну отсутствием публикаций.
- Не вставлять текст из Git, плана или JSON в HTML без экранирования; не
  проверять пути через `startswith` — только `Path.resolve()` +
  `relative_to(E:\Dissertation)`.

## 5. Где что лежит

- `evaluation/project_history/` — модель, чтение Git, разбор плана,
  каталог, обход артефактов, индекс и кэш (`.cache/project_history/`),
  фильтры, безопасный рендер.
- `scripts/project_history_window.py` — окно (`--selftest` снимает
  скриншоты в `ui/project_history_screenshot*.png`).
- `ui/project_history.html` — интерфейс без внешних ресурсов.
- `tests/test_project_history.py` — тесты; `scripts/validate_project_history.py` — валидатор.
- `experiments/results/*.csv`, `runs/*/*/summary.json`, `*.md` в корне —
  артефакты, на которые ссылаются карточки.

## 6. Как отчитываться

Перед каждым шагом — что будет сделано; после — что сделано и чем это
доказано (вывод команды, путь к файлу, число из источника). В конце любого
отчёта об эксперименте — сводка в процентах к baseline. Работа не
останавливается из-за сомнений в новизне: сомнение называется кратко и
фиксируется в `cannot_claim` карточки.
