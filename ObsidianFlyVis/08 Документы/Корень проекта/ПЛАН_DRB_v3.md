# План реализации DRB v3 — поэтапный

Стратегия: блок перестаёт быть «добавкой к признакам» и становится **операторами шеи**,
а карта качества получает три внешних потребителя. Четыре компонента, у каждого своя
мишень и свой источник уверенности:

| # | компонент | что делается | откуда уверенность | мишень |
|---|---|---|---|---|
| 1 | Замена слияний в шее | интерполяции FPN → частотные фильтры FreqFusion-класса, радиальные кольца как ядро | FreqFusion, TPAMI 2024 (arXiv 2408.12879), официальная прибавка на детекции | строгое AP, границы |
| 2 | Амплитудная аугментация обучения | подмена амплитуд день↔ночь между кадрами, фазы сохраняются | FDA-школа: arXiv 2105.11120, AmpMix (PR 2023), FOUND 2025 | индекс деградации |
| 3 | ВЧ-вспомогательный лосс | supervision высокочастотной полосы признаков от масок рамок GT | свободная ниша — поиск публикации не нашёл | строгое AP мелких |
| 4 | Карта качества наружу | пересчёт баллов детекций + шум наблюдения Калмана + кондиционирование TTA | UA-Track, TT-WA (TCSVT 2025), TTN (ICLR 2023) | IDF1, ночь |

Принцип честности: всё, что не является блоком (данные, аугментации, расписание,
разрешение, сиды, протокол оценки) — идентично для обеих рук (baseline / с блоком).
Различие рук ровно одно: наличие частотных операторов шеи и потребителей Q.

## Метрики и критерии успеха (записываются ДО первого прогона)

### Система метрик

1. **PRIMARY — ночное строгое AP мелких объектов** (`AP_small` при IoU 0.50:0.95,
   ночной поднабор). Самая стабильная метрика из измеренных (СКО контроля ±0.0005),
   и единственная клетка, где механизм блока совпадает с болезнью набора.
2. **IDF1 ночью**, усреднённый по классам как в официальной таблице BDD100K MOT
   (mMOTA/mIDF1 = среднее по 8 классам; eval.ai leaderboard). Приведение к
   классоусреднённому виду обязательно — иначе числа несопоставимы с чужими.
3. **Индекс деградации**: ΔAP(ночь − обычные условия) внутри каждого размера объекта.
   Меньше — лучше. Мера робастности, главный аргумент против возражения о составе
   поднаборов.

### Правило фиксации чекпойнта

Сравниваются **обе точки** (`best.pt`, `last.pt`) обеих рук, но победитель
определяется по `last.pt` — модели после полного расписания. Обоснование
фиксируется заранее: сценарий использования «обучили N эпох, взяли то, что вышло»,
без подглядывания в валидацию.

### Пороги успеха (n = 3 сида на руку, пары по сидам)

- PRIMARY: во всех трёх парах сидов значение блока выше значения контроля
  **и** разница средних ≥ +0.0015.
- IDF1: среднее блока ≥ контрольное + 0.4 п.п.
- Индекс деградации: у блока минимум на 10% относительных меньше.
- Успех направления: выполнен PRIMARY, или (IDF1 И индекс деградации одновременно).
- Провал: PRIMARY ниже контроля хотя бы в одной паре и оба вторичных не выполнены →
  v3 закрывается, в текст идёт отрицательный результат с таблицами.

### Бюджет счёта

Финальная ставка: 2 руки × 3 сида × ~27 ч = **~162 GPU·ч ≈ 7 суток подряд**.
Экономия: стартовать парами по сидам (сид 42 → гейт → сиды 123/2024).

## Этап B. Частотные операторы слияния в шее (ядро работы, 1–2 недели кода)

Референс: FreqFusion (TPAMI 2024). Суть адаптации под проект: свои радиальные кольца
(`models/drb/fga.py`, параметризация колец уже переносима по разрешению) вместо
их offset-based ядер — проще, дешевле, и это самостоятельный заявляемый вариант.

### B1. Два модуля

- [ ] `models/neck_v3/freq_upsample.py` — замена билинейного апсемплинга:
      повышение разрешения, затем depthwise-свёртка с ядром низкочастотного кольца
      (адаптивность — выбор отсечки кольца по канальному дескриптору, 1 скаляр
      на канал; НЕ свободная маска на каждый отсчёт спектра).
- [ ] `models/neck_v3/hf_enhance.py` — обострение границ перед слиянием:
      фиксированный ВЧ-характеристика + обучаемый вклад по каналам через поправку
      `y = x + g ⊙ (H(x) − x)` (форма с поправкой — доказанно безвредна при g→0),
      ограничение g сигмоидой ±небольшой потолок.
- ❌ Запрещено проектировочно: мультипликативные маски на каждый отсчёт спектра
  (четырежды сошлись к нейтрали), поканальные быстрые LR на предобученных каналах.

### B2. Интеграция в модель

- [ ] Использовать существующий паттерн обёртки слоя шеи (`models/yolo_neck/neck_drb.py`,
      класс `DRBWrappedLayer` + `DRBTrainer.get_model`) — обёртывать теперь не только
      слои P3/P4/P5, но и операции Upsample/Concat в шее (индексы head.f читаются
      динамически, для yolo26s это [16, 19, 22]).
- [ ] Конфиг руки: `training/configs/drb_v3.yaml` — побайтовая копия baseline.yaml,
      отличия только вставкой модулей. Контрольная рука остаётся на `baseline.yaml`.
- [ ] Регрессионный тест в `tests/test_drb.py`: прямые проходы четырёх форм карт
      (ловушка прямоугольных пачек на проверке уже однажды стоила пяти падений —
      тест обязателен), тождественность при нулевых g, битовая идентичность
      отключённого блока против чистого neck.

### B3. Замер стоимости

- [ ] Инференс батч 1, fp16, 640×640: не хуже baseline +3 мс. Операции шеи —
      depthwise 3×3-класс, FFT не нужен вовсе (в отличие от старой FGA).
- ✅ Критерий приёмки: стоимость ≥ требуемых 30 к/с, параметры блока < 50k.

### B4. Обкатка (12 эпох, сид 42, пара рук)

Только проверка работоспособности, НЕ выводов (урок хроники: короткие пробы для
утверждений непригодны):

- [ ] Обучение доходит до конца, α-логи пишутся (`drb_alphas.csv`-аналог);
- [ ] loss снижается, нет NaN под autocast;
- [ ] mAP50 после 12 эпох в пределах ±0.02 от известного контроля 12 эпох
      (0.4254±0.0144) — грубый тест «не сломано»;
- ✅ Если провалено: фиксировать причину, чинить, повторять. Лимит — два цикла;
  дальше вернуться к переработке B1.

## Этап C. Амплитудная аугментация (параллельно с B, 3–5 дней кода)

### C1. Реализация

- [ ] `training/augment_amp_swap.py`: с вероятностью p=0.5 на пару изображений
      батча — смешение амплитудных спектров `A = β·A_i + (1−β)·A_j`, фазы остаются
      собственными; β ~ U(0.3, 0.7); FFT в fp32 под autocast (паттерн уже есть в
      `models/drb/fga.py`); работа на изображениях 640 после геометрических
      аугментаций, до HSV.
- [ ] Модуль автономен и подключается ОДИНАКОВО в обе руки:
      в `DRBTrainer.build_dataset` и в baseline-trainer тем же флагом конфига
      (`amp_swap: {p: 0.5}`) — это условие зеркальности, проверить отдельно.
- [ ] Пары брать осмысленно: с вероятностью 0.7 партнёр — кадр из другого
      поднабора условий (обычные↔ночь, дождь↔ночь) — тогда аугментация работает
      именно синтезатором погоды, а не просто шумом.

### C2. Проверка механизма до обучения (без GPU)

      должно заполнить промежуток между дневным и ночным. Если заполняет —
      синтез погоды работает; если нет — крутить β, не запускать обучение.

### C3. Обкатка (12 эпох, обе руки)

- ✅ Дальше аугментация фиксируется навсегда в обоих основных конфигах.

## Этап D. ВЧ-вспомогательный лосс (5–7 дней, поверх B)

Свободная ниша: опубликованной схемы «частотная развязка + supervised локализация»
поиском не найдено — потенциальный пункт новизны.

### D1. Конструкция

- [ ] Цель вспомогательной задачи: маска границ. Строится из GT-рамок уровня P3:
      двоичная маска контура bbox (периметр рамки, расширение 1 px), downsample до
      размера карты.
- [ ] Предсказание: высокая полоса признака ветки box-regression P3, выделенная
      фиксированным лапласианом 3×3 (≈ одно кольцо высоких частот).
- [ ] Потеря: L1(HF(признак), маска_границ), вес λ: разминка 0 → 0.05 за 20 эпох
      (частотный принцип: сначала крупные структуры).
- [ ] Точка вмешательства: свой loss-класс поверх стандартного
      DetectionLoss (переопределение в тренере — тот же приём, что `get_model`).
- [ ] Контрольная рука учится БЕЗ этого лоса (это часть блока, честно).

### D2. Приёмка

- [ ] Тест: лос = 0 при идеальном предсказании; градиент доходит до нужного тензора;
- [ ] λ=0 битово совпадает с контролем;
- ✅ Единственный критерий окончательного эффекта — PRIMARY-метрика финальной пары.

# Обоснование (почему v3 именно такая) — со всеми источниками

**Главный вывод поиска:** направление верное, а МЕСТО блока в архитектуре было неверным.

1. На срезе BDD100K-Night текущий уровень задаёт частотная работа: **NF-DETR-L, 2025** —
   82.1 AP50 / 58.6 строгого AP, +3.5…+3.7 над трансформерами без частотного механизма
   (https://pmc.ncbi.nlm.nih.gov/articles/PMC12196686/). **FE-YOLO** (Digital Signal
   Processing, 2025) — Fourier-блок внутри YOLO, расширяющий амплитуду спектра
   (компенсация яркости/контраста), обучение сквозное
   (https://www.sciencedirect.com/science/article/abs/pii/S105120042500377X).
   Общее у победителей: управляют АМПЛИТУДОЙ, обучаются вместе с сетью, стоят там,
   где частотная информация ещё жива.
2. **FreqFusion (TPAMI 2024)** — показано, что лучшие частотные операции в шее — это
   замена самих операторов слияния пирамиды: апсемплинг → адаптивный НЧ-фильтр (против
   дрожания признаков внутри класса), параллельно ВЧ-фильтр для границ. Код:
   https://github.com/Linwei-Chen/FreqFusion , статья: https://arxiv.org/abs/2408.12879
3. **Свободная ниша новизны:** регрессионные лосы (SIoU https://arxiv.org/abs/2205.12740,

   «частотная развязка + supervised локализация» как опубликованная схема не найдено.
4. **Спектральная аугментация подтверждена школой FDA → AmpMix → FOUND:**
   https://arxiv.org/abs/2105.11120 ,
   https://www.sciencedirect.com/science/article/abs/pii/S0031320323001747 ,
   https://arxiv.org/abs/2511.10352 — амплитуда несёт условия съёмки, фаза — содержание.
5. **Трекерная сторона:** UA-Track называет малый размер объекта главным источником

## А.1. FreqUp — замена `nn.Upsample(2×)` в шее

**Принятое решение (закрывает развилку из раздела «Где кодер упрётся», п.1):**
фильтрация в спектре гладким радиальным окном, а ядро-свёртка — ЗАПАСНОЙ вариант.
Ключевое отличие от прежней FGA: адаптация входит через **форму поправки**
`y = x_up + g ⊙ (Filt(x_up) − x_up)`, поэтому ЛЮБОЙ фильтр безопасен на старте
(g ≈ 0) и не может «испортить» предобученную шею даже при неудачной отсечке.

```python
# models/neck_v3/freq_upsample.py
class FreqUp(nn.Module):
    """Апсемплинг 2× + gated НЧ-коррекция (спектральный вариант, по умолчанию).

    t_raw: (C,) — отсечка кольца t_c = f_lo + (f_hi−f_lo)·σ(t_raw)
    g_raw: (C,) — вклад g_c = g_max·σ(g_raw), старт g_raw = −4 (g ≈ 0.07·g_max)
    ВАЖНО: оба — вектор по каналам, НО вклад проходит через СКАЛЯРНОЕ g на канал,
    применяемое к РАЗНОСТИ — поканальное масштабирование признаков, ломавшее
    голову в старом DRB, здесь невозможно (см. замер 20.08 в хронике).
    """
    def __init__(self, channels, f_lo=0.11, f_hi=1.0, g_max=0.3, tau=0.06):
        # частоты нормированы на r_max = sqrt(0.5) (диагональ half-спектра rfft2)
        self.t_raw = nn.Parameter(torch.full((channels,), -4.0))  # старт t ≈ f_hi
        self.g_raw = nn.Parameter(torch.full((channels,), -4.0))  # старт почти-тождество
        # сетка радиусов НЕ буфер-параметр: считается на каждый forward под
        # фактическую (H, W) — прямоугольные пачки валидации поддержаны
        # (тот же приём, что band_idx persistent=False в models/drb/fga.py)

    def forward(self, x):                       # x: (B, C, H, W)
        up = F.interpolate(x, scale_factor=2.0, mode='nearest')   # исходная операция шеи
        X  = torch.fft.rfft2(up.float())        # fp32 под autocast — паттерн fga.py
        r  = radius_grid(up.shape[-2:], up.shape[-1]//2 + 1, device=x.device)  # (1,1,H,Wh)
        t  = (self.f_lo + (self.f_hi - self.f_lo) * torch.sigmoid(self.t_raw)).view(1,-1,1,1)
        W  = torch.sigmoid((t - r) / self.tau)  # гладкое окно: r<<t ⇒ 1, r>>t ⇒ 0
        filt = torch.fft.irfft2(X * W, s=up.shape[-2:]).to(x.dtype)
        g    = (self.g_max * torch.sigmoid(self.g_raw)).view(1,-1,1,1)
        return up + g * (filt - up)
```

- Параметры: **2C на модуль** (два уровня: C=256 на P4-слияние, C=128 на P3-слияние
  для yolo26s ⇒ 768 чисел суммарно). ✔ логарифм цены: меньше 50k с запасом.
- f_lo/f_hi/tau — константы по умолчанию; менять ТОЛЬКО через конфиг, не в коде.
- Группа оптимизатора: `t_raw, g_raw` исключить из weight decay и дать LR ×10 —
  механика уже есть в проекте (прецедент собственных групп DRB в `training/train_drb.py`).
- **Запасной вариант B** (если спектральный на прямоугольных пачках даст нестабильность
  под autocast, несмотря на fp32-островок): ядро K=7, дискретизованное из идеального
  НЧ-круга `k[n] ∝ J1(2π f_c r_n)/r_n` (jinc), нормировка суммы = 1, `f_c` дифференцируем;
  свёртка depthwise с padding=3. Развилка B/A фиксируется флагом конфига `freq_variant`.
- ⚠ проверить при кодировании: проходит ли forward под `torch.autocast('cuda', fp16)`
  на 4 формах карт (64×80→128×160 и т.д.) — тест обязателен до обучения (ловушка
  прямоугольных пачек уже однажды стоила пяти падений).

## А.3. Амплитудный миксер — `training/augment_amp_swap.py`

```python
def amp_mix(img_i, img_j, beta):          # float32 в [0,1], (3,H,W), размеры равны
    Fi, Fj = torch.fft.rfft2(img_i), torch.fft.rfft2(img_j)   # по (H, W)
    amp = beta * Fi.abs() + (1 - beta) * Fj.abs()
    out = torch.fft.irfft2(amp * torch.exp(1j * Fi.angle()), s=img_i.shape[-2:])
    return out.clamp_(0, 1)
```

- **Точка подключения:** обёртка датасета `AmpSwapDataset(base)` с переопределённым
  `__getitem__`: после штатной сборки кадра (включая мозаику) с p=0.5 применяется
  `amp_mix(кадр, кадр_партнёр)`. Партнёр: с вероятностью 0.7 — случайный кадр из
  противоположного пула условий, иначе случайный по датасету; β ~ U(0.3, 0.7).
- **Пул условий:** на train собрать словарь `путь→условие` из атрибутов BDD100K
  (файл атрибутов train-разметки; ⚠ проверить наличие в `data/`, при отсутствии —

```python
class V3DetectionLoss(v8DetectionLoss):
    def __init__(self, model, lam_max=0.05, warmup=20):
        super().__init__(model); self.lam_max, self.warmup, self.epoch = lam_max, warmup, 0
    def set_epoch(self, e):   # вызов из колбэка on_train_epoch_start тренера
        self.lam = self.lam_max * min(1.0, e / self.warmup)
    def __call__(self, preds, batch):
        base, items = super().__call__(preds, batch)
        aux = self._hf_loss(self.model.neck.last_p3, batch)   # скаляр, /число GT-рамок
        return base + self.lam * aux, torch.cat([items, (self.lam * aux).detach()[None]])
```

## А.5. Карта качества в Калман — точный путь (проверено по 8.4.84) ✔

Факты по установленной версии:
- `ultralytics/trackers/utils/kalman_filter.py`:
  `KalmanFilterXYAH.update(mean, covariance, measurement, confidence=None)` —
  **параметр существует**, внутри `project(..., confidence)` масштабирует шум
  измерения как `max(1 − confidence, 0.05)` (NSA-Kalman) — дословно из docstring.
- `byte_tracker.py`: треки строятся как `self.track_class(xywh, s, c)` — класс трека
  параметризуем полем инстанса `track_class`.
- НО `STrack.update()` вызывает `kalman_filter.update(...)` БЕЗ confidence —
  поэтому стандартный путь не масштабирует шум. Патч точечный:

```python
# tracking/lqa_guided_tracker.py (расширение существующей обёртки)
class HybridSTrack(STrack):
    slot: int = -1
    registry: ClassVar[list[float]] = []          # ŝ текущего кадра, порядок = порядок results
    def update(self, new_track, frame_id):
        conf = HybridSTrack.registry[self.slot] if self.slot >= 0 else new_track.score
        self.mean, self.covariance = self.kalman_filter.update(
            self.mean, self.covariance, self.convert_coords(new_track.tlwh), confidence=conf)
        # далее — копия тела родителя (state, is_activated, score)
class HybridByteTracker(LQAByteTracker):          # LQAByteTracker уже прокидывает kwargs
    def __init__(self, *a, mode='q', kappa=0.3, **kw):
        super().__init__(*a, **kw); self.mode, self.kappa = mode, kappa
        self.track_class = HybridSTrack
    def update(self, results, img=None, feats=None, **kw):
        conf = results.conf
        if self.mode == 'off':  HybridSTrack.registry = None   # родительский STrack
        elif self.mode == 'conf': HybridSTrack.registry = list(map(float, conf))
        else:                   HybridSTrack.registry = [hybrid(c, q, self.kappa) for c, q in zip(conf, q_ranks)]
        self.track_class = STrack if self.mode == 'off' else HybridSTrack
        return super().update(results, img=img, feats=feats, **kw)
```

- `hybrid(c, q, κ) = c + κ·(rank_q − c)`, κ=0.3 по умолчанию.
- `slot` назначается при создании трека: порядок `results` в кадре известен в момент
  построения списка треков — QSTrack получает индекс; реестр перезаписывается каждый
  кадр ДО super().update(). Инвариант: длина реестра == число детекций кадра.
- **Три режима абляции ровно такие:** `off` (родительский STrack, шум не масштабируется
  вовсе), `conf` (NSA по чистой уверенности — отдельный режим, НЕ равный off),
  `q` (гибрид). Сравнение трёх режимов на фиксированном детекторе — готовая таблица.
- q по рамке: переиспользовать готовую агрегацию минимума + ранжирование внутри
  уровня из `tracking/q_aggregation.py` (написана на этапе 9.5) — НЕ писать заново.
- ⚠ подтвердить при кодировании место конструирования треков в 8.4.84
  (строка `return [self.track_class(xywh, s, c) ...]`) и что `slot` можно передать —
