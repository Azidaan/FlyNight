# F4 Адаптеры с нулевой инициализацией и параллельные ветви, которые не ломают готовую систему

↑ [[07 Исследования/Фундаментальные проблемы/Фундаментальные проблемы|Фундаментальные проблемы]]

> ControlNet zero conv, zero-init адаптеры для замороженных сетей; как отделить «вредно» от «бесполезно»; муха → нулевая свёртка → P3 замороженного YOLO26.

## Механизм
1) Why zero-init: a frozen pretrained network sits in a good basin; any new branch with random weights adds a random perturbation to its features at step 0, the loss jumps, and the large early gradients either destroy the new branch's useful structure or (if the backbone is unfrozen) the backbone itself. Zero-initializing the LAST layer of the branch (ControlNet 'zero convolution', LLaMA-Adapter zero gating, ViT-Adapter injector gamma=0, ReZero alpha=0, LoRA B=0, zero-gamma BN in residual blocks) makes the combined model exactly equal to the frozen baseline at init, so training can only move away from the baseline if the gradient says the branch helps. 2) Why it still learns: for y = x_base + W*f(x) with W=0, dL/dW = (dL/dy)*f(x) which is non-zero as long as the branch feature f(x) is non-zero and correlated with the residual error; dL/df = W = 0, so the branch body gets no gradient at the very first step but does as soon as W moves. This works only with ONE zero factor in the product. If two factors are zero (a zero gate times a zero conv, or a sigmoid gate saturated at 0, or a gate multiplied by a zero-initialized mask), every factor receives zero gradient forever: a 'dead' branch, not a useless one. 3) Harmful vs useless (the key distinction): after training a zero-init branch, three different situations produce the same 'gate ~ 0' picture: (a) DEAD - no gradient reached it (wiring, double zero, detached tensor, frozen by optimizer param groups, weight decay with no data gradient); (b) USELESS - gradient exists but averages to ~0 because f(x) carries no information about the residual error that the base does not already have (redundancy; for the fly over its own input this is guaranteed by the data-processing inequality - a deterministic function of the 721 facets cannot add information over the facets, only easier-to-use structure); (c) HARMFUL - gradient is consistently negative (pushing W toward 0 against weight decay or past 0), i.e. adding f(x) increases loss, typically because f(x) is out-of-distribution noise for the frozen downstream layers. Zero-init guarantees 'no worse than baseline at init', but it does NOT guarantee no harm after training: the branch can still overfit and the base can still drift if unfrozen. 4) Placement: an additive residual adapter must target a feature map with matching spatial stride and comparable semantic level; ViT-Adapter and LLaMA-Adapter both found that injecting everywhere is not best (LLaMA-Adapter: 30 of 32 layers 83.85 vs all 32 layers 81.03 on ScienceQA). For YOLO26, the input to the detector must stay the raw frame (the Г3 result shows any change of the input distribution hurts a frozen detector); the side signal must enter as an additive zero-init residual on a feature map (P3, stride 8), not by replacing pixels. 5) Sudden convergence: ControlNet reports that zero-conv training shows a 'sudden convergence' - outputs ignore the condition for thousands of steps and then switch abruptly (reported as typically under 10K steps [uncertain exact number]); short probes can therefore wrongly conclude 'useless' if they stop before the switch.

## Решения из литературы
Numbers from literature (all vs the same frozen/strong base): LLaMA-Adapter ablation on ScienceQA val - zero-init gated attention 83.85 vs random-init 40.77 (+43.08; random-init is near random choice 39.83), with 1.2M trainable params on frozen LLaMA-7B; insertion depth: 10 layers 55.95, 20 layers 73.36, 30 layers 83.85, all 32 layers 81.03 (more injection points is not monotonically better). ViT-Adapter (zero-init injector gamma) on COCO Mask R-CNN 1x, ViT-S: plain 40.2 AP_box -> +SPM/extractor 43.4 -> +injector 44.2 -> full 44.7 (+4.5 AP_box, +2.8 AP_mask); ViT-B 45.8 -> 49.6 AP_box (+3.8). Note: this is a weak plain-ViT base; gains against strong detectors with native multi-scale features are much smaller [uncertain]. ControlNet: Gaussian-initialized conv instead of zero conv gives visibly worse images in the ablation (qualitative/user-study, no single number) [uncertain on numeric form]; zero conv allows training on a single RTX 3090Ti with small datasets (<50K pairs) without destroying SD. Practical recipe distilled from these: (1) exactly one zero factor - zero-init the final 1x1 conv, keep the gate/scale at 1 or keep a learnable scalar at 0 but then init the conv randomly; (2) exclude adapter scale from weight decay (weight decay otherwise wins against a weak data gradient and drives it to 0, cf. DRB 4/4 neutral masks); (3) higher LR for the adapter (5-10x base) [uncertain optimal factor]; (4) verify bit-exact equivalence with the baseline at step 0 (same mAP on val to 4 decimals) and verify non-zero gradient norm on the zero layer at step 1; (5) inject at one or two well-chosen levels, not everywhere; (6) train long enough to pass 'sudden convergence' and log the adapter output norm.

## Что сделать с мухой
Place: FlyVis runs on the RAW video (several consecutive frames, its own retina-lamina front-end that already fixes the fly's night drop +0.016), while YOLO26 keeps receiving the unchanged raw frame - this removes the Г3 input-shift problem by construction. Hex column outputs (e.g. T4/T5 direction channels, Tm/Mi intensity-contrast channels; column scale ~13 px, cannot be changed) are resampled to a square grid and fed through a small 1x1/3x3 conv stack whose LAST 1x1 conv is zero-initialized, then ADDED to P3 (stride 8; 80x80 at 640, 120x120 at 960) before the neck. Stride 8 is the closest match to a 13 px column; P4 (stride 16) is the alternative if P3 is too fine. What is frozen: stage A - YOLO26 fully frozen (backbone, neck, head), BN in eval mode; train only the adapter + optionally the 734 fly parameters (with truncated backprop through the fly ODE). This answers 'can the fly add anything a frozen detector can use' without any risk to the base. Stage B (only if stage A is positive) - unfreeze neck+head with LR x0.1. Training details: no weight decay on the zero conv and its bias; adapter LR 5-10x; auxiliary per-branch loss (fly-only objectness heatmap at P3, see F5) so the branch learns even when the main loss ignores it; log ||adapter output|| / ||P3|| every N iterations. Cost: dense fly 1.2 ms/step at 1/16 density, 15.8 ms at full density on RTX 5070 - precompute fly features to disk for the train set to keep training at detector speed. Make 'harmful vs useless vs dead' decidable: after stage A, evaluate with the adapter scale fixed at {0, 0.5, 1, 2}; monotone rise of loss with scale = harmful, flat = useless, the stage-A gradient log at 0 = dead.

## Тест до постройки
All on already-collected data (val caches, 107/70 held-out videos), no detector training: (1) Residual-information probe: take frozen YOLO26 P3 features and the fly features at the same grid cells; label cells by the detector's own failure type at the 0.25 threshold (missed GT at night, 'below-threshold' candidate that is a TP, false positive). Fit a linear/logistic probe from P3 alone and from P3+fly; the gain in AUC of P3+fly over P3 is the upper bound of what a zero-init adapter can extract. Controls in the same probe: P3+tavg3, P3+raw facets (721 inputs), P3+shuffled-connectome fly. If P3+fly does not beat P3+raw facets, the adapter cannot beat the input either (data-processing inequality). (2) Model-stitching test (Bansal et al. 2021): train only a 1x1 stitching conv from fly features into P3 position with the detector frozen for ~1 epoch-equivalent on cached features; if the stitched model is not within noise of baseline when it REPLACES nothing but ADDS - the representation is incompatible. (3) CKA/partial correlation between fly channels and P3 channels: high CKA = redundancy, adapter will learn ~0. (4) Step-0 checks: bit-exact baseline mAP with adapter attached; non-zero grad norm of the zero conv on one batch. (5) Oracle: feed the adapter an oracle map (GT-box night mask at P3) - if even the oracle with a 1x1 adapter on a frozen detector gives < +1 pp night recall at equal FP, the location (P3 additive) itself is wrong.

## Потолок
Target loss: night threshold losses 21.0% vs 15.5% day - gap 5.5 pp of GT; blindness 4.5% day and night (equal, so not night-specific). Ideal adapter on a frozen detector can at most close the night-specific threshold gap: <= +5.5 pp night recall at equal FP (100% of the gap), and DetA moves little because cars are 83% of night boxes and car AP is already 0.817/0.816 night/day. Realistic ceiling from literature for an extra input channel even when it carries genuinely new physics (thermal): +0.3..+0.9 AP (project D4); for a deterministic function of the same RGB input the expected value is ~0 (plan K9: 'expectation ~0'). Estimate: 0..+1 pp night recall at equal FP, i.e. 0-18% of the measured night-vs-day threshold gap [uncertain].

## Где обязано помогать
Must help: night (dev+test night, raw recall at equal FP 0.7552), age-0 objects (birth), small objects at night, occluded GT. Must not harm: day recall at equal FP within its CI (0 +/- ~1 pp), overall mAP50 on val7 and 70 held-out videos, FP count fixed at the 0.25-threshold FP of the baseline. Because the adapter is zero-init and stage A keeps the detector frozen, any day degradation is a direct sign of harm (case c).

## Отрицательный контроль
Must all run through the SAME adapter, same epochs, same LR: (1) adapter with zero input (pure capacity/extra-training control); (2) baseline fine-tuned the same number of iterations without adapter ('ctl', exists in the project); (3) non-biological matched control: tavg3 or DIS-flow channels into the same adapter; (4) raw facet input (721) into the same adapter - the fly must beat its own input; (5) shuffled-connectome fly (exists: -0.044 AP fly-alone) - gain must vanish; (6) temporally shuffled frames into the fly - removes motion, tests whether gain is temporal. Only gain(fly) > gain(best of 3,4) with CI excluding 0 can be credited to the fly.

## Вклад ветви
Log per epoch: ||W_zero|| and ||adapter_out||/||P3|| ratio; grad norm of the zero conv (0 => dead); sign of mean dL/dscale (negative persistent => harmful); scale-sweep evaluation {0,0.5,1,2} at checkpoints; per-subset recall with adapter on/off at each checkpoint (ablation by epoch catches the DRB-type sign flip).

## Минимальный эффект и стоимость
Frozen-detector inference comparisons (stage A eval, Г3 style): paired bootstrap over videos gives half-width ~0.8 pp recall at equal FP (tavg3 -1.97 [-2.79; -1.22]), so MDE ~1 pp with one run each. Training noise: seed spread 0.0144 mAP at 12 epochs (DRB era) - with only the adapter trainable the variance should be much smaller [uncertain], but Ultralytics seed does not change anything when fine-tuning from the same weights (rule 6.12) so seeds must be set manually (data order). Use 3 runs per arm: MDE ~2.8*sigma*sqrt(2/3) ~ 0.033 mAP if sigma=0.0144, ~0.007 if sigma=0.0031 (100-epoch control). Cost on RTX 5070 12 GB: fly feature precompute for train set (1400 videos at 5 Hz, ~16 ms/frame at full density) ~ several hours once [uncertain]; stage A 2-epoch probe ~1-2 h each (cf. K5 ~1 h); 3 arms x 3 runs ~ 10-15 h GPU; full 12-epoch run ~4.3 h each.

## Вердикт для проекта
SECONDARY but actionable. Zero-init does not explain why the fly carries little new information (that is redundancy - F5/data-processing inequality), but its absence explains two concrete failures: DRB's dead branch (w=0 in 896 channels from wiring/no gradient, mis-read as 'useless') and Г3 (fly replaced the input of a frozen detector, -9.45 pp night). Priority: medium - implement the residual-information probe (diagnostic 1) first (~0 GPU hours, cached features); build the P3 zero-init adapter (K9) only if P3+fly beats P3+raw-facets and P3+tavg3 in that probe. Expected gain if built: 0..+1 pp night recall at equal FP.
