## Механизм
A pipeline metric is a composition of stages, and the gain from improving one stage is bounded by how much of the total error that stage owns and by how the final metric aggregates stages. Amdahl's law (Amdahl, AFIPS 1967) states the speed-up form: if a fraction p of the total is affected and that part improves by a factor s, the total improves by 1 / ((1 - p) + p / s), so as s -> infinity the gain is capped at 1 / (1 - p). Goldratt's theory of constraints (The Goal, 1984) is the operational version: throughput of a chain is set by its constraint; improving a non-constraint changes nothing measurable. For tracking, HOTA = sqrt(DetA x AssA) (Luiten et al., IJCV 2021), so the marginal value of each factor is dHOTA/dDetA = 0.5 x sqrt(AssA / DetA) and dHOTA/dAssA = 0.5 x sqrt(DetA / AssA): at roughly equal DetA and AssA, one point of either is worth ~0.5 HOTA, but which factor can actually move by a point is the question. Errors also have a strict hierarchy: an object that is never detected (FN) cannot be associated, so association improvements act only on the detected fraction; an FN is invisible to every downstream module. Oracle analysis makes p measurable: replace one stage by ground truth and measure the final metric (Hoiem et al., ECCV 2012 'Diagnosing Error in Object Detectors'; TIDE, Bolya et al., ECCV 2020, which defines one oracle per error type and the change dAP_o = AP_o - AP, with all oracles together reaching 100 AP). Two traps follow: (1) an oracle ceiling is not an accessible gain - the gap between the oracle and the best real algorithm for that stage matters more (in this project the association oracle is large, +47% AssA, but the spread across real association algorithms is small); (2) oracles interact - fixing stage A changes the ceiling of stage B (Tracktor's Oracle-reID gives 0.0 MOTA but +10.0 IDF1 while Oracle-ALL gives +10.7 MOTA, mostly through FN: -11,745). MOTRv2 (Zhang et al., CVPR 2023) is the field-level illustration: end-to-end MOTR was 'inferior mainly due to poor detection'; supplying a strong detector's proposals moved DanceTrack test HOTA from 54.2 to 69.9, with DetA 73.5 -> 83.0 and AssA 40.2 -> 59.0 - the weak link was detection, and fixing it also raised association.

## Решения из литературы
1) Oracle ladder before any module (standard in MOT papers): Tracktor (ICCV 2019, MOT17 FRCNN public detections, base 61.5 MOTA / 61.1 IDF1 / FN 42,903 / IDSw 1,747): Oracle-Kill +0.7 MOTA, Oracle-REG +1.4 MOTA / +5.6 IDF1, Oracle-MM +0.9 / +5.2, Oracle-reID 0.0 / +10.0, Oracle-MM-reID +0.9 / +13.9, Oracle-MM-reID-INTER +2.6 / +15.9 (FN -6,769), Oracle-ALL +10.7 / +22.5 (FN -11,745). Lesson: identity oracles move IDF1, only detection-side oracles move MOTA/DetA, and the biggest share is FN. 2) Error-type decomposition with isolated oracles for detection: TIDE (ECCV 2020) - cls / loc / both / dupe / bkg / missed, each fixed by its own oracle, dAP_o reported; plus FP/FN oracles; the method's point is to fix errors in isolation so contributions are comparable. 3) Bottleneck-first redesign: MOTRv2 (CVPR 2023) diagnosed detection as MOTR's weak link and bootstrapped it with YOLOX proposals: DanceTrack test HOTA 54.2 -> 69.9 (+15.7), DetA +9.5, AssA +18.8; BDD100K MOT val 43.6 mMOTA / 56.5 mIDF1 vs Unicorn 41.2 / 54.0. 4) Metric-structure analysis: with HOTA = sqrt(DetA x AssA) and DetA ~ AssA ~ 58-61, each point of DetA is worth ~0.5 HOTA; so the question becomes 'which factor can I move by a point at all'. 5) Prioritisation rule (expected value): priority = (accessible ceiling, i.e. best realistic minus current, not the oracle) x P(success from a pre-build probe) / cost; DeepMOT shows the accessible gain of 'better training of an already-good stage' is small (Tracktor +0.2 MOTA, +1.5 IDF1 on MOT17) compared with replacing a weak stage (GOTURN +9.8 MOTA). 6) Per-subset oracles: run the oracle on the subset you claim (night, age-0, occluded) and on the rest, since the bottleneck can differ by subset (here: night threshold losses 21.0% vs 15.5% by day).

## Что сделать с мухой
Point the fly at the measured constraint: detection recall at a fixed FP budget for night and age-0 objects, i.e. the threshold step (confidence ranking of weak true candidates vs false candidates), not association, not motion, not blindness. Concretely: (A) fly as an extra trainable input channel / P3 side branch of YOLO26 (zero-init residual, trained by the detection loss; see F7/F8), evaluated by night recall at equal FP and DetA; (B) fly as a per-candidate rescoring feature only if a pre-build probe shows it separates true from false weak candidates beyond YOLO's own score and the 30 Hz background-relative motion that already failed (Г0б-30); (C) for the dissertation's 'fly science' line, association-side fly experiments can continue, but they must be reported against their own small ceiling (stitching ~ +0.8 HOTA already taken by geometry), never as a HOTA path. Frozen in the first pilots: tracker (cascade + deferred birth + stitching), evaluation protocol, equal-FP operating point; trainable: the fly branch (+ detector head in the second stage). Before any of this, build the missing detection-side oracle (see pre_build_diagnostic) so the fly's target has a measured ceiling.

## Тест до постройки
All on cached detections and TrackEval, no training. 1) Detection oracle ladder on the current stand (val7 + 70 held-out videos, by night/day and age 0): (i) 'return threshold losses' - add every GT-matched candidate that YOLO26 produced with 0.01 <= conf < operating threshold (keeps YOLO's own box; this is the ceiling of any rescoring, fly or not); (ii) 'remove FP' - drop all unmatched outputs above the threshold; (iii) 'fix localisation' - snap matched boxes to GT; (iv) 'return blindness' - insert GT boxes not covered by any candidate (ceiling of a better detector). Report DeltaDetA, DeltaAssA, DeltaHOTA for each and the night/day split. This gives p for Amdahl's law for each fly placement. 2) Accessible-ceiling check: for rescoring, the realistic upper bound is an oracle-trained rescorer on YOLO's own features (logistic probe on neck features at candidates, trained on train videos with GT labels, evaluated held-out); the fly can only be judged against the gap between this probe and YOLO's score. 3) Sensitivity check: perturb each stage by a fixed small amount (e.g. +1 pp night recall at equal FP via the oracle on a random 1/4 of losses; -10% IDSw via oracle IDs on a random 10% of switches) and measure DeltaHOTA; the ratio is the transfer coefficient of each stage. 4) MDE gate: compare the expected fly gain (from 2) with the MDE of the primary metric; if expected < MDE, do not build.

## Потолок
Measured: association oracle +23.0 IDF1 / AssA 49.79 -> 73.40 (+47%) on the old ByteTrack stand, but accessible association spread 5.78 mMOTA vs detector swap 24.13 (2.9-4.2x); prediction oracle +6.47 IDF1 (+12.7%); geometry stitching already +0.79 HOTA with appearance/fly not significant above it. Not yet measured (must be built first): detection-side oracles. Arithmetic estimate for 'return all night threshold losses': if night threshold losses are 21.0% of night GT and day 15.5%, returning only the night excess (5.5 pp of night GT) at zero FP raises night DetRe by up to ~5.5 pp; with HOTA ~ sqrt(DetA x AssA) and DetA moving by roughly half of DetRe [uncertain], that is ~ +1.4 HOTA on night videos and less overall - i.e. the detection threshold step is the largest reachable lever, but a realistic fly rescorer captures a small fraction (literature-based DetA +0.1..+0.6 [uncertain]).

## Где обязано помогать
Must help on the constraint subset: night, age-0 objects (night age-0 recall at equal FP 0.39 vs 0.65 overall night), occluded at night, and candidates in the 0.01-0.25 confidence band (the threshold-loss band). No-harm: day recall at equal FP, FP count at the operating point (gain must be at equal FP), AssA and IDSw of the final tracker (a detection gain that adds fragmented short tracks can lower AssA), car class separately (83% of night boxes).

## Отрицательный контроль
For every oracle-guided module: (1) a 'random oracle' control - apply the same number of fixes (returned candidates, removed FPs) chosen at random rather than by GT, to separate the effect of volume from the effect of correctness (the plan notes oracle IDF1 partly reflects output volume); (2) for the fly module: the same placement with shuffled connectome and with an equal-capacity non-fly feature; (3) YOLO's own score / features as the matched baseline for any rescoring (the fly must beat YOLO's neck-feature probe, not only YOLO's raw score); (4) DIS-based motion with identical retina input for any motion claim.

## Вклад ветви
For bottleneck work this is per-stage, not per-weight: after each training checkpoint run the cached evaluation and log DeltaDetA, DeltaAssA, FN, FP, IDSw relative to the stand; a module meant for the threshold step must show its gain in FN at equal FP (not in IDSw); inside a trained fly branch also log gate value and gradient-norm ratio (see F7) and an epoch-wise ablation.

## Минимальный эффект и стоимость
HOTA: paired bootstrap CI half-width ~ 0.7 HOTA for the combined tracker (+0.80 [+0.08; +1.44]), MDE ~ 1.0 HOTA - most realistic fly effects are below it, so the primary metric must be the constraint-level metric (night recall at equal FP, MDE ~ 0.25-1.1 pp depending on subset) with HOTA as secondary. Detection oracle ladder: CPU-only on cached detections + TrackEval, minutes per variant (association is offline and takes seconds; TrackEval per variant a few minutes) - essentially free, ~1 day of code. A rescoring probe on cached neck features: ~1-2 h GPU for feature extraction once (with Idle priority), then CPU. Any detector-side fly training: 2-3 h per 2-epoch arm at 960 on RTX 5070 12 GB (12 epochs ~ 4.3 h), 4-5 arms ~ 10-15 h; requires user permission.

## Вердикт для проекта
Primary - this is the single best explanation of why most ideas did not reach HOTA: they were aimed at stages that own a small share of the error (association, motion, blindness, neck feature quality) while the measured constraint is detection recall at the threshold step (FN 15,763 vs IDSw 2,221; DetA flat; detector 2.9-4.2x association). Highest priority and cheapest fix: build the detection-side oracle ladder on cached outputs (no training), then put the fly only where its accessible ceiling exceeds the MDE. Novelty doubt: oracle/bottleneck analysis is standard practice (Tracktor, TIDE, MOTRv2); it is method, not novelty - record in cannot_claim.
