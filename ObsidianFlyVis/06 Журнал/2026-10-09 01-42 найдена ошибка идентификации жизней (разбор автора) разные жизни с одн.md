# 2026-10-09 01:42 — найдена ошибка идентификации жизней (разбор автора): разные жизни с одним номером трекера смешивались в `life_filter_oracle_v1` и `life_filter_head_v1`

↑ [[06 Журнал/Дни/2026-10-09|2026-10-09]]

*Ошибка.* Трек, потерянный и вернувшийся с прежним номером, даёт в `signatures.npz` несколько записей жизней с одним `track_id` (проверено: dev — 49 652 записи / 41 304 номера, повторов 8 348; train — 196 216 / 159 592, повторов 36 624). Я относил рамки выхода к жизни по номеру, а не по записи и интервалу кадров: в `scripts/life_filter_head.py` словарь `pos = {tid: i}` оставлял последнюю запись номера и складывал в неё рамки всех его жизней; `scripts/stitch_realness.py:life_features` собирал строки по номеру без интервала; удаление шло по номеру (`drop_tids`); оракул `scripts/life_filter_oracle.py` группировал по номеру. Пример: 019efe88-bbc2a4ac, номер 8 — записи 0–129, 134–135, 139–140, 141–221; жизни 0–129 (3 верных, 5 ложных) и 141–221 (0 верных, 8 ложных) получили общую метку 0. Совпадение «52 ложные жизни» у головы и оракула ошибку не выявило — одна и та же группировка. Смежная ошибка: в признаках цепочки (`scripts/chain_filter_head.py:chain_task`) строки трекера собирались по номеру для каждой жизни цепочки — номер с несколькими жизнями учтён несколько раз (счётные признаки завышены).

*Ограничение прежних выводов.* [life_filter_oracle_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Flife_filter_oracle_v1): +0,33 HOTA — эффект удаления групп по исходному номеру, не потолок удаления отдельных жизней. [life_filter_head_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Flife_filter_head_v1): не чистая проверка мухи на отдельных жизнях. Карточки цепочечных фильтров — оговорка о дублировании строк, влияние не измерено. Числа сохранены.

*Решение.* Уникальный идентификатор жизни — номер записи в `signatures.npz` (с номером трекера и интервалом кадров); рамка относится к записи с тем же номером и кадром в интервале, неоднозначные — отдельно; признаки — строго внутри интервала записи; проверки — номер 8 (две разные метки) и удаление ложной жизни с сохранением настоящей того же номера. Затем — [life_filter_oracle_v2↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Flife_filter_oracle_v2) на dev и, при выполнении критерия, [life_filter_head_v2↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Flife_filter_head_v2). Новый проход FlyVis не нужен.
