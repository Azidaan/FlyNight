# 2026-10-11 11:57 — поправка к выводу `class_gate_v1`; решение автора о следующем действии

↑ [[06 Журнал/Дни/2026-10-11|2026-10-11]]

*Ошибка.* В предыдущей записи и отчёте: «основной вред большого буфера — возвраты на объект того же класса, когда своего объекта нет». Это версия по проверяемым событиям (принадлежность проверена у небольшой части долгих возвратов), а не установленная причина. Для остановки правки достаточно того, что запрет по классу не помог.

*Решение автора.* Следующим — не А3 (перекрытия: не показано, что FlyVis распознаёт заслонение лучше признаков соседних рамок; риск снова улучшать ByteTrack без вклада мухи), а короткая попытка исправить саму муху: считывание движения T4/T5 по области рамки и по широкому полю (принцип клеток HS/VS), движение сцены и объекта — раздельно. Одна рабочая версия модуля без загрузки FlyWire; сравнение: трекер без движения, штатная FlyVis, FlyVis с новым суммированием, DIS (внешний ориентир) в найденной схеме 5 Гц; сначала стоимость и критерий, затем перенос рамки и HOTA по видео. Если новая муха не обходит штатную и не перестаёт вредить трекеру — остановиться без новой цепочки диагностик. Дорогой проход GPU — после отдельного согласования.
