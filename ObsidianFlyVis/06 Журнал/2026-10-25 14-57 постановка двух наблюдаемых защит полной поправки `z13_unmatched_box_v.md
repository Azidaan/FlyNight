# 2026-10-25 14:57 — постановка двух наблюдаемых защит полной поправки `z13_unmatched_box_v1`

↑ [[06 Журнал/Дни/2026-10-25|2026-10-25]]

*Действие.* Test two observable application contracts for the existing target-model full-box output. Full-strength action is permitted only if the original first-stage assignment left this row unmatched; stricter free rule also requires proposed detection not assigned to any other row. This is an application-boundary experiment, not an intrinsic modernization of FlyVis or a service fix.

*Метод и фиксированные условия.* Same original maps, region selection, NULL, support and full-XYWH proposal as prior prototype. Three fixed contracts perD/C/R1/geometry: unconditional full strength, unmatched-only, unmatched-and-free. Both new contracts use original baseline assignment computed before any intervention. No GT or labels in admission. Same complete assignment after one-row replacement. No alpha sweep: active alpha1, alpha0 only exact regression control. No calibration/selection: every contract uses alpha1 fixed before run. Fit20 replay is reported as development audit; indices1 are fixed and written before evaluate26. Original Dold retains original saved tau. All three contracts/all controls reported. No conditional threshold estimated on26.

*Критерии до прогона.* For either of2preregistered guards: Dguard-baseline mean>=2pp; every matched lower97.5%video interval>0 against baseline, unconditional Dfull, original Dold, same C/R1/geometry guard, and differential guard effects D-C and D-R1. Bonferroni for two guard alternatives: bootstrap5000seed1 quantiles0.0125/0.9875, field ci975. A better guard than a catastrophic unconditional policy is insufficient without absolute benefit and FlyVis-specific controls.

*Причина.* Prior fixedalpha0.25 missed246useful full-box actions after choosing a potentially helpful box, but unconditional alpha1 had severe harm. This changes only admission of the same full-strength output based on pre-existing assignment, not weights/pooling/NULL threshold, and compares against that exact unconditional alpha1. New explicit author request25Oct: continue testing after these findings.

*Возражение.* The original tracker may be correctly unmatched when no compatible detection exists. A new box can create a false match or steal from a valid neighbor. The free rule may remove useful recovery of a detection incorrectly held by another track. Both guards may give the same effect without FlyVis, which would be an application improvement only. Reused26 was seen to formulate this new hypothesis; no independent validation claim.
