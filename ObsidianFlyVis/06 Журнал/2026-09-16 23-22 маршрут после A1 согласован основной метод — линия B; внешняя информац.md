# 2026-09-16 23:22 — маршрут после A1 согласован: основной метод — линия B; внешняя информация о FlyVis.

↑ [[06 Журнал/Журнал изменений|Журнал изменений]]

*Решение пользователя (6.5).* Вариант 1 принят: линия B (`XYWHByteTrack` + раздельная событийная уверенность `q_det`, `q_match`, `q_birth`, `q_alive`) — основной метод диссертации; FlyVis закрыт как исследованная ветвь с отрицательным результатом (глава «исследованное направление», не новизна); цель 3 и сборка линии A не открываются; цель 5 — необязательная платформа абляций; очередь: 1 (сдвиг кандидатов как часть выборки `q_match` цели 4) → 4 → 6 → 7 → 8. Отметка внесена в [[05 План/1. Тема, стенд и состояние на 11.09.2026|разделы 1.6]] и 3 плана целей. Проверка FlyVis для `q_alive`/`q_birth` возможна позже отдельной карточкой на выборках цели 4, не блокирует линию B.

*Внешняя информация (устное сообщение, не доказательство).* Руководитель пользователя на работе независимо пробовал FlyVis как обучаемую вспомогательную ветвь в задаче retrieval (UAV/спутник, замороженный бэкбон StripNet-S, обучаемый входной адаптер → обучаемая сеть мухи → проекция 512, сумма с обычной головой с обучаемым весом): «граф дорогой, только float32, float16 теряет качество», «замедление в 8 раз», «не может быть моделью», «R1 mAP 56 % на 1 эпохе» без контрольного числа той же модели без ветви мухи. Оценка для диссертации: независимо подтверждает измеренные здесь ограничения по скорости и точности вычислений и вывод «FlyVis не может быть ядром трекера»; их конструкция — дообучение коннектома, которое план 1.2 исключает как разрушающее аргумент биологической ограниченности; число без парного контроля (без ветви / shuffled) неинформативно; домен (статичный retrieval) не переносится на временную ассоциацию. Новых оснований для повторного входа в FlyVis не даёт.
