# 1.4. Трекинг — память личности и надёжное сопоставление

Кандидаты для развития всей системы. Наличие статьи и исправного авторского кода не подтверждает пользу на нашем стенде.

Т1–Т12 здесь номера кандидатов ветки Трекинг; это не исторические этапы Т1–Т5 раздела7.8 Единого плана и не Б1–Б3.

Приоритет для первой изолированной проверки — управление записью памяти с сильным простым контролем. Раздельные роли памяти и обучение различению конкурентов — следующие возможные ступени; запуск этой записью не разрешается.

Т1 — Обновлять память по надёжности наблюдения — Deep OC-SORT

Т2 — Различать историю цели и похожих соседей — KeepTrack

Т3 — Разделить недавнюю память и опоры против соседей — DAM4SAM

Т4 — Обучать устойчивую память вместе с сопровождением — MeMOTR

Т5 — Проверять сомнительные соответствия по альтернативам — U2MOT

Т6 — Обновлять представление объекта с учётом других треков — Multi-track pooling

Т7 — Сохранять несколько путей памяти вместо раннего выбора — SAM2Long

Т8 — Учить решение на состояниях после собственных ошибок — DAgger

Т9 — Хранить устойчивые прототипы и краткую память — HMP

Т10 — Различать объекты более сильными признаками — MASA-Detic

Т11 — Узнавать экземпляры разных классов — MGOR

Т12 — Сохранять личность через последовательность соответствий — ScaleTrack
