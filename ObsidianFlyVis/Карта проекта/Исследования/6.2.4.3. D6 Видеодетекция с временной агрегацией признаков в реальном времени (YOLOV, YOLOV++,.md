# 6.2.4.3. D6 Видеодетекция с временной агрегацией признаков в реальном времени (YOLOV, YOLOV++, StreamYOLO, TransVOD)

> Временная агрегация признаков в одностадийных детекторах реального времени 2022–2026 (YOLOV, YOLOV++, StreamYOLO, LongShortNet, DAMO-StreamNet, TransVOD); приросты на ImageNet VID, Argoverse-HD, BDD100K; что помогает именно слабо уверенным, заслонённым и только что появившимся объектам; стоимость; может ли рекуррентная муха с памятью быть временным модулем вместо внимания.

## Суть
Video object detectors keep a single-frame detector and add a module that borrows evidence from other frames. Two families matter for a real-time YOLO. (1) Candidate-level aggregation (YOLOV 2023, YOLOV++ 2024): after the dense head, select the foreground candidates (YOLOV++ keeps all above conf 0.001), and refine each candidate's class score by attention over candidates from reference frames; the base detector stays frozen and only the head projections + aggregation module are trained. This is directly a confidence-repair mechanism for weak but real candidates - the project's THRESHOLD loss. (2) Feature-level fusion of the previous frame in the neck (StreamYOLO 2022, LongShortNet 2023, DAMO-StreamNet 2023): concatenate current and previous FPN features and train to forecast the next frame for streaming latency. TransVOD (2022/23) does the same with spatio-temporal transformers on Deformable DETR. Gains are large on ImageNet VID (+6 to +9 AP50 over YOLOX/PPYOLOE/FCOS bases, +10-12 mAP on fast-moving objects, +3.9 AP on the occlusion-heavy OVIS), but the default YOLOV setting samples reference frames from the whole video (offline, non-causal), and the streaming works' sAP gains largely come from forecasting, not from better per-frame detection. A recurrent memory (ConvGRU/LSTM) is a third, cheaper option; the fly is such a recurrent conv network.

## Место мухи
Three placements, in decreasing order of cheapness. (a) Fly as the affinity/memory signal in YOLOV-style candidate re-scoring: YOLOV refines a candidate's score by attending to similar candidates in reference frames; the project's fly signature already carries object identity (+0.14 AP over geometry in association, topology matters +0.044 AP vs shuffled), so it can serve as the similarity key to find the same object in past frames and pull its confidence up (causal, past frames only). Here the fly is not the temporal module but the identity feature that makes temporal aggregation correct under night appearance noise. (b) Fly as the recurrent temporal module instead of attention: FlyVis is a recurrent convolutional network with cell-type-specific time constants; run on P3-resolution columns it holds a short memory (tens to a few hundred ms; on the order of 3-10 frames at 30 Hz) [uncertain: effective memory of the trained time constants]. Its state (lamina L1/L2 adapted contrast, T4/T5 motion, Tm/TmY mid-level) can be concatenated to the P3 feature, StreamYOLO-style, but injected via zero-conv to keep the base intact. This is the PermaTrack argument: a ConvGRU over the video made the prior-detection heatmap redundant and beat CenterTrack (Track mAP 60.3 -> 62.4). The fly cannot replace attention for long gaps (occlusions of seconds), because its time constants are short - that remains the tracker's job. (c) Fly at the candidate level as a feature for the aggregation module: append fly features of each candidate (from the existing per-track foveal eyes) to the YOLOV candidate feature before attention. Why sensible: the dominant loss is under-confidence of real candidates at night; temporal aggregation is exactly the published mechanism that raises scores of weak candidates by agreement across frames, and the fly adds a night-robust identity/motion key. The decisive control is the same aggregation with the detector's own features (YOLOV default), with geometry/IoU only, and with DIS-propagated boxes.

## Какую потерю закрывает
Primary: THRESHOLD loss (21.0% night vs 15.5% day; night confidence deficit +0.098). YOLOV/YOLOV++ operate on candidates already present above a very low threshold (0.001) and re-score them; that is precisely 'candidate exists but confidence too low'. Occlusion: on OVIS (severe occlusion) YOLOV++-S +3.9 AP and +9.6 AP50 over YOLOX-S - the strongest published evidence for occluded objects with this family; relevant to the 5.4x night occlusion penalty. Fast motion / blur: mAP_fast +12.3 for YOLOV++-S (50.0 -> 62.3). BIRTH (age 0): weak - temporal aggregation needs past observations of the same object; at its first frame there is nothing to aggregate in a causal setting; YOLOV's reported gains use global (including future) reference frames, which are unavailable online. Partial help only for objects that were visible but sub-threshold in earlier frames (the age definition counts from first annotation) [uncertain: how often age-0 objects were sub-threshold candidates before]. BLINDNESS (4.5%): not addressed - candidate-level aggregation cannot create a candidate that is absent at conf 0.01; feature-level neck fusion (StreamYOLO) could in principle. Small objects: streaming sAP_s rises modestly (StreamYOLO-L 13.8 -> DAMO-StreamNet-L 16.1, but vs different baselines).

## Пересечение с чужими работами
Temporal aggregation in one-stage detectors is well established (YOLOV, YOLOV++, StreamYOLO, LongShortNet, DAMO-StreamNet, TransVOD, YOLOFT), and recurrent memories (ConvGRU in PermaTrack, ConvLSTM in mobile video detectors, LSTM in event-based RVT) are standard. No work was found that uses a connectome-constrained fly optic-lobe model as the temporal/recurrent module or as the affinity key in candidate aggregation of a detector [uncertain: search not exhaustive]. Note also that the project's own tracker cascade (buffers + deferred birth + stitching) is already box-level causal temporal aggregation, and it left DetA unchanged (58.21 -> 58.17); any claim must show that feature-level aggregation adds what box-level aggregation did not. cannot_claim: candidate re-scoring by cross-frame attention, frozen-base fine-tuning of the aggregation module, FPN-level previous-frame fusion, recurrent memory as a temporal module - all borrowed. Claimable only if gates pass: the fly as a night-robust identity/memory signal for causal temporal re-scoring, beating the detector's own features and IoU at equal information.

## Результаты у авторов
ImageNet VID (30 classes, AP50, base trained 7 epochs on 1/10 of VID frames + DET; 3090 GPU, FP16): YOLOX-S 69.5 (1.4 ms) -> YOLOV-S 77.3 (4.0 ms) -> YOLOV++-S 78.7 (5.3 ms); by motion speed mAP slow/medium/fast: YOLOX-S 76.8/66.8/50.0, YOLOV-S 82.3/75.1/58.6, YOLOV++-S 83.7/77.0/62.3; YOLOX-L 76.5 -> YOLOV-L 83.6; best YOLOV++ with FocalNet-L 92.9 AP50 at 27.6 ms (93.2 with REPP post-processing). Other bases: PPYOLOE-S 69.5 -> 75.6, PPYOLOE-L 76.9 -> 82.9, FCOS 67.0 -> 74.1. Reference frames (YOLOV++-S): global sampling from the whole video Fg = 4..39 -> 75.7..78.7 AP50; local consecutive frames Fl = 4..39 -> 70.5..74.1 AP50 (i.e. local frames give only +1.0 to +4.6 over the 69.5 base, global +6.2 to +9.2). YOLOV paper: 3 global frames already beat 39 local frames. OVIS (occlusion, 25 classes): YOLOX-S 39.0 AP / 59.8 AP50 -> YOLOV-S 41.7 / 66.1 -> YOLOV++-S 42.9 / 69.4; YOLOX-SwinT 49.3 -> YOLOV++-SwinT 53.2. Compute: naive YOLOX-L + attention over all 8,400 anchors x 4 frames needs 12.1 GB and 50.2 ms; candidate selection makes it ~1-4 ms extra. StreamYOLO (Argoverse-HD, 30 Hz driving video, moving camera, sAP with real-time constraint, YOLOX-L base 31.2 sAP): fusing previous frame at input -0.9 sAP, at backbone -0.7, at FPN +3.0; element-wise add -0.4, concatenation +3.0; predicting the next frame instead of offsets: offsets -0.2, next-frame +3.0; full StreamYOLO-L 36.1 sAP (+4.9). LongShortNet-L 37.1, DAMO-StreamNet-L 37.8 sAP (small-object sAP_s 13.8 / 15.2 / 16.1). TransVOD: +3-4 mAP over the Deformable DETR single-frame baseline; TransVOD++ 90.0 AP50; TransVOD Lite 83.7 AP50 at ~30 FPS on V100. XS-VID (extremely small): StreamYOLO 33.4 AP vs YOLOv8-L 33.6 - streaming fusion gave no gain over a modern single-frame YOLO on tiny objects.

## Проверка против сильной базы
Weak to moderate. The ImageNet VID bases are deliberately short-trained (7 epochs, 1/10 of frames) older detectors (YOLOX, 2021), so +7 to +9 AP50 partly reflects a weak base; with stronger backbones the absolute gain shrinks but persists (YOLOX-SwinT -> YOLOV++-SwinT on OVIS +3.9 AP). The large ImageNet VID gains rely on global (non-causal) reference frames; with local frames the gain is +1 to +4.6 AP50. StreamYOLO compares to YOLOX-L under the streaming metric; its gain mixes latency forecasting with detection, so it does not show better offline detection. On extremely small objects StreamYOLO did not beat YOLOv8-L. No result on BDD100K or on night conditions was found; no seed variance reported in YOLOV/YOLOV++/StreamYOLO. Equal-information control (same frames, simpler aggregator) partly exists: StreamYOLO's input-concat and element-wise add variants are worse than the base, i.e. the gain depends on where and how fusion is done, not on more frames per se. Independent reproductions: YOLOV/YOLOV++ numbers are reused in later VOD papers as baselines [uncertain: no independent re-training found].

## Разрез по условиям
ImageNet VID by motion speed (slow / medium / fast). OVIS for occlusion. Argoverse-HD by object size (sAP_s/m/l) and, in StreamYOLO's extension, by velocity (VsAP). XS-VID by object size. No night split, no overexposure split, no first-appearance analysis, and no BDD100K results found for this family.

## Дешёвая проверка
Gate 0 (hours, no detector training), on runs/det_cache_ctl_960 (baseline seed42, 960, 200 val videos, conf>=0.01), night-heavy subset first (val7 + dark val videos). Causal training-free YOLOV analogue: for each candidate at frame t, find matches among candidates of frames t-1..t-k (k = 3, 6, 15 at 5 Hz labelled frames or 30 Hz cached frames) by a similarity key and compute an aggregated score s' = s_t + w * f(matched past scores). Keys to compare at equal k: (i) IoU after constant-velocity shift (geometry only), (ii) DIS-propagated box IoU, (iii) fly signature cosine from the existing foveal eyes, (iv) shuffled-topology fly signature. Fit w and f on dev videos, evaluate on test videos. Measures with video-bootstrap 95% CI: candidate TP/FP AUC vs raw score (0.9025 reference), night recall at the operating threshold at fixed FP, separately for age 0, age 1-9, age 10+, and occluded objects. Pre-registered pass: (1) best key raises AUC by >= +0.005 over raw score (CI > 0); (2) fly key beats geometry and DIS keys by >= +0.003 AUC or >= +2 pp night recall for occluded objects at fixed FP (CI > 0); (3) shuffled fly loses >= half of the fly gain. Additionally, (4) compare against the tracker: apply the existing cascade's deferred-birth/buffer logic on the same candidates; if Gate-0 aggregation does not beat it in DetA on val7, the feature-level route is unlikely to reach DetA and should be stopped. Gate 1 (one day): frozen YOLO26s best.pt + YOLOV-style aggregation head (only head projections + aggregation trained, as YOLOV does), causal 4-8 past frames, 3 seeds x short schedule, check night mAP50 against 0.3772 +- 0.0031 and the head's attention entropy (is aggregation used?).

## Стоимость у нас
Gate 0: a few hours on CPU/GPU using cached candidates and existing fly signatures (no new fly runs if the signature cache covers val7 + subset). Gate 1: YOLOV trains only the head projections + aggregation with a frozen base for 150K iterations at batch 16 on a single 2080Ti/3090 [their setting]; on the RTX 5070 with YOLO26s at 640 and 4-8 reference frames per sample, an equivalent run is roughly one 12-epoch-equivalent (~4-6 h) per seed [uncertain]; 3 seeds ~15 h. YOLO26 is NMS-free, so YOLOV's candidate selection must use the one-to-one head outputs or the one-to-many head before selection - an engineering adaptation, not drop-in [uncertain]. Inference: +1-4 ms per frame for candidate aggregation at S size (YOLOX-S 1.4 -> 5.3 ms on 3090), dominated by attention over ~100 candidates x reference frames; a fly recurrent module at P3 costs much more unless re-implemented as a batched hex-conv RNN (per-eye fly now ~150-390 ms/frame per process). StreamYOLO-style FPN fusion: negligible inference overhead (+0.75 ms on V100) but requires re-training the neck (12 epochs ~4.3 h per seed).

## Ожидаемый эффект
Under causal (online) constraints and a strong, fully trained YOLO26s, expect much less than the ImageNet VID numbers: the local-frame results suggest +1 to +4.6 AP50 over a weak base, so for BDD100K night perhaps +0.005 to +0.02 mAP50 over 0.3772 [uncertain]. The mechanism should show up as fewer THRESHOLD losses for objects already seen (age >= 1) and for occluded objects at night, not for age-0 births and not for blindness. Translation to the tracker is the critical question: the existing box-level temporal logic did not move DetA (58.21 -> 58.17), so feature-level aggregation must add new evidence (feature similarity under night noise); a DetA change of +0.3 to +0.8 would already be a good outcome [uncertain]. If the fly is used only as the similarity key (placement a), the effect is bounded by how much better the fly key is than IoU/DIS for re-identifying the same weak candidate over 1-6 frames; the fly signature's identity value (+0.14 AP over geometry) suggests it could help where boxes are ambiguous (crowds, occlusions).

## Риски
1) Non-causal evaluation trap: YOLOV/YOLOV++ defaults use global reference frames from the whole video; only causal past-frame results are valid for the online tracker. 2) Overlap with the tracker: box-level temporal aggregation is already in the cascade and gave no DetA; double counting temporal evidence (detector + tracker) can inflate FP (8,242 now). 3) DRB lessons: 12-epoch seed spread 0.0144 mAP exceeds the plausible effect - frozen base and >= 3 seeds with CI; do not extrapolate to 100 epochs (DRB sign flip); verify the aggregation branch is used (attention entropy, weight norms) to avoid a 'branch without gradient'; report time overhead (DRB +17%). 4) Wrong fusion point hurts: StreamYOLO input-level concat -0.9 sAP and element-wise add -0.4; fuse at FPN/candidate level, with zero-init. 5) Weak-base inflation in the literature: gains against 7-epoch YOLOX do not transfer in size to a fully trained YOLO26s. 6) Fly memory is short; long occlusions are beyond its time constants. 7) NMS-free head of YOLO26 complicates YOLOV's candidate selection. 8) Licences: Ultralytics AGPL-3.0; YOLOX Apache-2.0; YOLOV/StreamYOLO/DAMO-StreamNet repo licences to be checked before reuse [uncertain]; flyvis MIT.
