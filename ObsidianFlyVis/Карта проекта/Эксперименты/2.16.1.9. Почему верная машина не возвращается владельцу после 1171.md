# 2.16.1.9. Почему верная машина не возвращается владельцу после 1171

Состояние: завершён с положительным результатом. Код: `ownership_conflict_2179_20261114`.

Чем вызван отказ свободной рамки 1176 и почему защита занятых рамок мешает в следующих кадрах?

1176: по всем пикселям пересечение прошлой и текущей масок 6135/18130 = 0.3384, по оцениваемым 5949/6604 = 0.9008. Изменение только строки 2179 с использованием эталонной области дало рамку 111813. В последующих пяти кадрах отдельное снятие защиты одного владельца возвращает верную рамку в 4 случаях. Источник: research_ownership_conflict_2179_20261114/result.json. По кадрам: 1182 — фактические номера на целевой машине 2445, 112732, без защиты {'rid': 112732, 'correct': True}; 1188 — фактические номера на целевой машине 2445, 113753, без защиты {'rid': 113753, 'correct': True}; 1194 — фактические номера на целевой машине 2445, 114726, без защиты {'rid': 114726, 'correct': True}; 1200 — фактические номера на целевой машине ［［2445, 115587], [2777, 115607］］, без защиты {'rid': 115587, 'correct': True}; 1206 — фактические номера на целевой машине 2777, 116404, без защиты {'rid': None, 'correct': False}. Источник: result.json, later, native_ownership.

Низкое совпадение двух прогнозов и высокое совпадение каждого из них с официальной видимой целью измеряются на разных пикселях. Защита занятого наблюдения предотвращает кражу верного номера, но сохраняет и уже случившийся переход владельца на другую машину; обе ситуации проверяются раздельно.

Не снимать защиту массово. Следующим применимым условием может быть проверка собственной истории текущего владельца до его перехода; эталонная карта исключений для трекера недоступна.

Пример 2179 и шесть точных кадров, не оценка переноса. Контрфактические решения не меняли события рабочего трекера.
