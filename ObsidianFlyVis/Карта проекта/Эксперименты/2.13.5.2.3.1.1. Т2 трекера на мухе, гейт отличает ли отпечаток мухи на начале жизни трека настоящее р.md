# 2.13.5.2.3.1.1. Т2 трекера на мухе, гейт: отличает ли отпечаток мухи на начале жизни трека настоящее рождение от ложного

Состояние: завершён с отрицательным результатом. Код: `fly_birth_gate_v1`.

Добавляет ли отпечаток мухи на начале жизни трека различение настоящих и ложных рождений сверх геометрии и сверх своего входа?

runs/fly_birth_gate/summary.json. Рождений в train 38756 (настоящих 67%). AP на test 35: геометрия 0,8375, + муха 0,8353, + вход 0,8266, + вход + муха 0,8248, + внешность 0,8356. Разности test: муха − геометрия −0,0021 [−0,0103; 0,0054]; (вход + муха) − вход −0,0019 [−0,0087; 0,0048]; внешность − геометрия −0,0019 [−0,0069; 0,0021]. val7: муха − геометрия 0,0001 [−0,0078; 0,0054].

На начале жизни трека отпечаток мухи не различает настоящее и ложное рождение (≈ 0 и на test, и на val7); внешность тоже ничего не добавляет — решает геометрия с уверенностью детектора. Вероятный узел: глаз мухи на рождении только что «включился» — отпечаток начала жизни усреднён по 1–5 первым кадрам, своей истории у глаза ещё нет, тогда как «объект ещё здесь?» работает на длинной истории жизни. Потолок рождения мал (+0,21 HOTA, detection_oracle_ladder_v1).

Оба критерия не выполнены → completed_negative для этой реализации; Т2 в виде «голова мухи на рождении» не строится. По правилу 6.15 узел — момент считывания (нет истории у глаза); замена — решение о подтверждении рождения по отпечатку мухи через N кадров предварительной жизни (в схеме отложенного рождения N = 2–3), что требует снимка сигнатуры в середине жизни (пересборка сигнатур ≈ 3 ч GPU). Учитывая потолок +0,21 HOTA, приоритет низкий — сначала Т3 (сопоставление по отпечатку).

Что муха бесполезна для рождения вообще (проверено только начало жизни, 1–5 кадров); одна модель (000).
