# 2.17.3.1. Гейт рамок: сглаживание траектории и выбор рамки на выходе трекера (без обучения)

Состояние: неопределённый результат. Код: `box_smoothing_v1`.

Сколько из потолка «точные рамки» (+5,4 HOTA) достаётся простым уточнением рамки по траектории?

HOTA test stand 58.469 → det 58.715; cascade_deferred 59.139 → det 59.408.

Любое сглаживание рамок по траектории вредит, и тем сильнее, чем шире окно (ma15 −2,6): при движущейся камере рамки быстро меняются, среднее отстаёт от объекта (тот же механизм, что у накопления кадров в Г3). Рамка детекции точнее оценки Калмана: замена даёт +0,30 HOTA на всех 35 видео test (на итоговом трекере +0,31), val7 тот же знак. Рычаг «точные рамки» (+5,4) сидит в регрессии рамки детектора, а не во временном усреднении; временное уточнение возможно только с компенсацией движения.

Критерий 1 формально не выполнен для stand (+0,296 при планке +0,3, хотя 35 из 35 видео и ДИ > 0); на итоговом трекере cascade_deferred +0,314 — выше планки. Критерий 2 выполнен (тот же знак на val7). → inconclusive по букве критерия; практический вывод — выдавать рамку детекции для сопоставленных треков (бесплатный приём линии B). Сглаживание закрыто. Остаток потолка рамок — в детекторе (разрешение обучения, голова рамки) или в уточнении рамки по кадрам с компенсацией движения.

Что временное уточнение рамок бесполезно вообще: проверено только усреднение без компенсации движения.
