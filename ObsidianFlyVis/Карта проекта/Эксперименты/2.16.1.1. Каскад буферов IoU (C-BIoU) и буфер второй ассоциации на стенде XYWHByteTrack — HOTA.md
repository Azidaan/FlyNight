# 2.16.1.1. Каскад буферов IoU (C-BIoU) и буфер второй ассоциации на стенде XYWHByteTrack — HOTA на обучающих видео

Состояние: завершён с положительным результатом. Код: `cbiou_cascade_v1`.

Добавляет ли каскад буферов что-то сверх одиночного буфера 0,5?

dev / test / val7 HOTA: стенд 61.336 / 58.469 / 54.573; буфер 0,5 61.766 / 59.121 / 54.680; каскад 0,3→0,6 61.810 / 59.106 / 55.076 (IDF1 test 68.350 против 66.965 у стенда; IDSw test 2221 / 2034 / 1968). Бутстреп по видео: каскад − стенд на test ΔHOTA +0.745 ДИ [+0.220; +1.487], ΔIDF1 ДИ [+0.699; +2.918]; каскад − буфер 0,5: test ΔHOTA ДИ [-0.163; +0.141], ΔIDSw на ролик -1.89 ДИ [-3.00; -0.80]; val7 ΔHOTA +0.261 ДИ [+0.059; +0.494]. Буфер второй ассоциации 0,3 и 0,5: результаты в точности равны буферу 0,5.

Каскад сохраняет прирост одиночного буфера по HOTA/IDF1 к стенду и значимо снижает переключения ID сверх него (test: 23 ролика лучше, 7 хуже), на val7 даёт +0,40 HOTA. Буфер второй ассоциации ничего не меняет по устройству стенда: при fuse_score=True сходство второй ассоциации умножается на уверенность детекции 0,1–0,25, расстояние всегда больше порога 0,5 — вторая ассоциация стенда фактически не сопоставляет ничего (проверено: вызывается на каждом кадре с непустым набором детекций).

Каскад 0,3→0,6 — лучшая конфигурация ассоциации линии B на обучающих видео по совокупности (HOTA как у буфера, IDSw ниже, val7 выше). Отдельная открытая задача: вторая ассоциация стенда мертва при fuse_score — проверить её без умножения на уверенность (XYWHIoUSecondByteTrack) на обучающих видео.

Новизну: каскад — заимствованный метод C-BIoU.
