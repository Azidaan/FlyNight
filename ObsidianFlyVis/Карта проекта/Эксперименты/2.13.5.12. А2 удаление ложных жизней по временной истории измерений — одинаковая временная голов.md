Эта реализация А2 остановилась на выборе рабочего порога: в проверенной сетке (допустимы 0,70–0,90) не найдена точка, одновременно соблюдающая ограничения потерь и подтверждающая улучшение HOTA по принятому критерию (например, 0,70: +0,0109 [−0,0145; +0,0349] на train вне обучения), поэтому по правилу выбрано «ничего не удалять». Равенство HOTA с мухой и без фильтра на dev (61,766 = 61,766) — следствие отключения фильтра по построению, а не отдельное измерение бесполезности мухи: активно удаляющая голова с мухой на dev не проверялась. Различение ложных жизней у головы с мухой есть (AP на dev 0,554 против 0,542 без мухи), но устойчивая дополнительная польза мухи не подтверждена: разность на dev +0,012 с ДИ через 0, на train вне обучения знак другой (в целевой группе > 5 измерений −0,009, ДИ ниже 0). Та же временная голова без мухи прошла отбор на train (0,70: +0,029, ДИ > 0), но на dev не дала подтверждённого прироста (+0,004, ДИ через 0). Причину (сжатие истории, устройство головы, цель обучения или недостаток дополнительного сигнала FlyVis) этот разбор не различает; вывод относится к данной процедуре удаления жизней.

По протоколу (решение автора 11.10): принять отрицательный результат, голову и пороги не менять, новых видео для А2 не готовить; GPU на дополнительные ночные train для этой реализации не тратить. 75 пригодных отложенных val подготовлены (загружены, выровнены), но не использованы для оценки и выбора модели. Сохранённая история (runs/fly_signatures_hist) — ресурс: при обоснованной замене сначала проверить, достаточно ли собранных данных, до нового прохода FlyVis. Замены («польза удаления» вместо «ложности», иные признаки порядка — catch22 / MultiRocket) — гипотезы, не следствия результата; только по решению автора. Итог разбора решений (правило автора: направленной пользы мухи в спорных решениях не видно — новую голову удаления не делать): в спорных удалениях голова с мухой выбирает столько же ложных жизней, сколько голова без мухи (341 против 337), но больше настоящих / смешанных (261 против 210); обмен хуже: 402 ложных на 316 верных рамок против 419 на 238, в целевой группе > 5 измерений — 155 на 139 против 192 на 68; при 0,7 с мухой − без мухи HOTA −0,018 (ДИ ниже 0) за счёт удаления верных рамок (CLR_TP −78). Это не только ошибка цены удаления — муха выбирает худшие жизни; основания для замены цели обучения (учёт цены ошибок) нет. Ветка удаления жизней отложена; новая голова, цель и видео не готовятся.

Нельзя заявлять, что в мухе нет полезной информации о ложных жизнях: отсутствие выбранного действия этого не доказывает; проверена одна сводка шести статистик (история ≤ 32 шагов), одна голова и одна цель. «Вреда нет» — только для выбранного режима без удаления, не для любого применения обученной головы. Установленной причины провала нет. dev использован многократно; независимая проверка не проводилась.
