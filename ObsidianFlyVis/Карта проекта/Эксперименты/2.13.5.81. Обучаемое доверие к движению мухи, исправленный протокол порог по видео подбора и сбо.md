# 2.13.5.81. Обучаемое доверие к движению мухи, исправленный протокол: порог по видео подбора и сбор данных в условиях применения

Состояние: завершён с отрицательным результатом. Код: `fly_motion_trust_learned_v2`.

Реализует ли исправленный протокол запас доверия к мухе, и обязана ли польза признакам мухи?

runs/motion_scheme_search/trust_learned_v2.json, trust_learned_v2_log.txt. Примеров: круг 0 — 26 233, с кругом 1 — 52153 (с мухой). Подбор порога (HOTA − без движения, 18 видео): с признаками мухи — 0.5: −1,203, 0.6: −1,065, 0.7: −0,756, 0.8: −0,808 → 0.7; без признаков — 0.5: −1,246, 0.6: −0,404, 0.7: 0,006, 0.8: 0,006 → 0.8. 24 отложенных: с признаками мухи − без движения −0,651 [−1,757; 0,097], лучше 12/24 (dev 17 −0,051, val7 −2,109); без признаков − без движения 0,002 [−0,002; 0,010], лучше 2/24; с признаками − без признаков −0,653 [−1,754; 0,093], лучше 12/24. Проверка поля мухи на val7 (08.10, scripts/fly_trust_diagnostic.py --set val7 → runs/fly_motion_trust/val7/summary.json): медиана ошибки мухи / постоянной скорости / DIS 6,01 / 4,14 / 2,42 px (dev 35: 7,15 / 5,02 / 3,19); муха лучше постоянной скорости в 30% (dev 34%); число кадров поля совпадает с видео и выравниванием. Технического сбоя поля на val7 нет: отношение «муха / постоянная скорость» то же (≈ 1,45); больший вред на val7 — свойство видео (у самого DIS на val7 выигрыш меньше, +0,96).

Исправленный протокол не помог: модуль без признаков мухи при подобранном пороге перестаёт принимать поправки (≈ 0), модуль с признаками мухи принимает самые «уверенные» — и они всё равно вредят, сильно на val7 (−2,1) и около нуля на dev 17. Узел провала сместился: метка обучения «центр поправки ближе к эталону, чем центр Калмана» не совпадает с пользой для трекера — даже поправки, правильные по этой метке, ухудшают HOTA (вероятно, через сопоставление и жизнь треков). Различие val7 и dev 17 устойчиво во всех вариантах — поле мухи на val7 может отличаться (отдельная проверка).

Критерии не выполнены → completed_negative для этой реализации. По правилу 6.15 линия открыта; узлы-кандидаты: (1) метка обучения — заменить на пользу для трекера (изменение HOTA/сопоставления при принятии поправки) вместо близости центра; (2) различие val7 / dev — проверить поле мухи на val7; (3) источник сведений — внутренние ответы T4/T5 до декодера или разногласие ансамбля (GPU). Обоснованность дальнейших дешёвых вариантов в этой схеме низкая: даже идеальный выбор давал лишь +0,99 при DIS +3,28.

Что доверие к мухе невозможно; что признаки мухи вредны (ДИ разности содержит 0).
