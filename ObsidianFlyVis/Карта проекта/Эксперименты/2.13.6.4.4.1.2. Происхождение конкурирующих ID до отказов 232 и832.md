# 2.13.6.4.4.1.2. Происхождение конкурирующих ID до отказов 232 и832

Состояние: неопределённый результат. Код: `id_birth_audit_20261112`.

When did the competing IDs first appear and first overlap the same annotated object, and which association stages are evidenced?

Прослежены 392 назначения четырёх выбранных ID; независимый пересчёт совпадения с разметкой дал нулевое расхождение, полные назначения пяти сохранённых матриц воспроизведены. 232 создан на кадре214,474 на519; на размеченных кадрах520 и532 оба публичных номера единственным образом совпадают с GT00130234 при IoU≥0,5. 773 создан на479 и совпадает с GT00118997 на481;832 создан на518 и совпадает с этой машиной на534. На536 стандартное назначение возвращает773:0,749979 против0,809152 для832. На540 выбирается773 со стоимостью0,702474;832 имеет0,867315 и отрицательную оценку головы. На539 ID232 теряет назначение: минимум первой матрицы0,941220; максимальный IoU со всеми сохранёнными детекциями0,207022, с низкоуверенными0,188133. Вторая ассоциация не может принять ни одну из них даже при чистом IoU с неизменным допуском0,5. Источники research_id_birth_audit_20261112/trace.json, audit.json, drop232.json.

Подтверждены два различных механизма. Для232 поздний отказ восстановления следует за существованием параллельного номера474 и потерей геометрически подходящей детекции на539. Для832 критерий «вернуть номер последнего опорного наблюдения» не определяет устойчивую личность: он потребовал бы возврата более позднего832 после восстановления прежнего773. Это не отменяет метку собственной пары832, но запрещает называть её отклонение доказанным ухудшением всей истории ID. На534 и536 выбор происходил до визуального решения и не зависел от его оценки при зафиксированном состоянии этих кадров. Матрицы рождения выбранных четырёх ID не сохранены: прежний журнал записывает полные матрицы только при непустом списке предложений. Операция создания новой ветви и её время подтверждены журналом и совпавшим исходником; точная причина того, почему конкретная детекция осталась свободной на каждом кадре рождения, пока не восстановлена.

Сохранить различие между собственной парой, канонической историей объекта и фактическим действием трекера. Не менять пороги и не продвигать улучшение головы по требованию вернуть832 без проверки всей истории. Следующая проверка: восстановить только состояние отдельных ветвей и необходимые этапы назначения на кадрах рождения474/801/832 по сохранённым детекциям и назначениям, с обязательным совпадением со всеми доступными сохранёнными состояниями. Это должно закрыть пробел архивного журнала без полного запуска трекера. Если точное состояние восстановить нельзя, явно сохранить границу доказанности. Физическую причину расхождения рамки232 на539 проверять по исходным кадрам, не интерполируя разметку.

Причина всех неудач проекта ещё не установлена. Двойное совпадение с рамкой GT не является сегментацией объекта и не заменяет взаимно-однозначное назначение TrackEval. Нельзя назначить единственный правильный ID только по его номеру или возрасту. Начальные наблюдения232 до269 не получили однозначного совпадения с разметкой; на522 у773 и832 совпадения также нет. Полная чистота истории не доказана. На кадрах рождения нет сохранённых полных матриц; восстановление будет отдельным вычислением и не должно выдаваться за старый журнал. Нового трекера, ядра, обучения, карт и изменения порогов нет; HOTA и процент улучшения качества не измерялись.
