# 2.13.7.8. Сжатая муха в голове удаления цепочки: три парных варианта (V0 / V1 без мухи / V2 с мухой), сначала dev

Состояние: закрыт. Код: `chain_filter_compact_fly_v1`.

Даёт ли сжатый выход головы с мухой лучшее ранжирование цепочек, чем тот же выход головы без мухи?

runs/chain_filter_compact/report_dev.json. Пересборка цепочек dev совпала с runs/chain_filter_rank/chains.pkl (метки и признаки). AP на dev вне обучения: V0 0.5340, V1 0.5332, V2 0.5339; V2 − V1 +0.0007 [-0.0008; +0.0022]; V1 − V0 -0.0008 [-0.0026; +0.0007]; V2 − V0 -0.0001 [-0.0019; +0.0014]. Бюджет потерь 1 % на dev: V0 (порог 0.85): ложных рамок убрано 434, верных 215, потеряно 22/2447, точность удаления 0.652; V1 (порог 0.85): ложных рамок убрано 420, верных 213, потеряно 22/2447, точность удаления 0.649; V2 (порог 0.85): ложных рамок убрано 423, верных 211, потеряно 23/2447, точность удаления 0.654. test и val7 не открывались (критерий перехода не выполнен).

Проверенная схема переноса не дала измеримого улучшения: AP V2 − V1 на dev +0,0007 (ДИ содержит 0), V1 и V2 не лучше V0; при бюджете 1 % все три варианта удаляют почти одно и то же. Закрыт этот способ переноса сигнала (вероятности совпадения крайней рамки жизни → 8 сводных чисел → линейная голова цепочки). Не установлено, что у FlyVis нет информации: могли не подойти цель прежней головы, способ объединения оценок или действие над целой цепочкой (поправка 09.10).

Закрыта по заранее записанному критерию перехода (dev): test/val7 и HOTA не считались. Закрыта гипотеза «сжатый выход головы совпадения рамки с мухой улучшает ранжирование цепочек», не направление. Возможные узлы (разбор автора 09.10): действие над целой цепочкой слишком грубое; при объединении жизней теряется связь признаков; сигнал перенесён с неподходящей метки; нужна история внутри жизни. Следующее — оракул удаления отдельных жизней внутри готовых цепочек.

Нельзя заявлять вклад FlyVis в ранжирование цепочек для удаления. test и val7 не использовались — выводы только по dev вне обучения. Ошибка 09.10: в признаках цепочки (chain_task) строки трекера собирались по номеру для каждой жизни цепочки — у цепочек с повторно вернувшимся номером строки этого номера учтены дважды (счётные признаки завышены; средние и квантили почти не меняются); в compact-варианте life_features смешивали жизни одного номера. Влияние на выводы не измерено.
