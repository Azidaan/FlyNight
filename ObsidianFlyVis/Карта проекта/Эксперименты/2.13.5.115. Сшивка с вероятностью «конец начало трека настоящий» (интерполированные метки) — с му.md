# 2.13.5.115. Сшивка с вероятностью «конец/начало трека настоящий» (интерполированные метки) — с мухой и без

Состояние: завершён с отрицательным результатом. Код: `stitch_realness_fly_v1`.

Повышает ли вес «трек настоящий» HOTA сшивки, и даёт ли муха вклад в эту голову?

runs/stitch_realness/summary.json. Метки (интерполированный эталон): с меткой 99,1–99,8 % концов и начал (прежние — 14,2–17,5 %), настоящих 44–50 % (лог runs/stitch_realness_log.txt, [LABEL]). AP «настоящий» (realness_AP), test: конец без мухи 0.6411, с мухой 0.6702, разность +0,0291 [+0.0162; +0.0411]; начало 0.6824 → 0.7115, +0,0291 [+0.0169; +0.0404]; val7 конец 0.7144 → 0.7367, начало 0.7371 → 0.7661. Сшивка, общий HOTA test (без сшивки 58.469): base plain 59.134, ×nofly 58.822, ×fly 58.715; base_masa plain 58.983, ×nofly 58.894, ×fly 58.737. По видео (diff): base_masa ×nofly − plain test -0.208 [-0.433; +0.038], 10/35; ×fly − ×nofly test -0.217 [-0.715; +0.175], 16/35, val7 +0.103 [-0.503; +0.799], 3/7; ×fly − plain test -0.425 [-0.957; -0.085], 12/35; base ×fly − ×nofly val7 -0.253 [-0.475; -0.068], 0/7.

Муха улучшает распознавание «трек настоящий» (+0,029 AP на конце и начале, ДИ выше 0, val7 тот же знак) — устойчивый сигнал мухи на уровне трека. Но как множитель веса пары он вредит сшивке (×fly − plain −0,43, ДИ ниже 0): при AP ~0,67 голова гасит и связи настоящих обрывков, а связь ложного обрывка с настоящим треком стоит HOTA мало (ложная рамка штрафуется детекцией независимо от номера) — то же, что показала stitch_unlabeled_diag_v1. Чем сильнее голова (муха), тем сильнее она меняет ранжировку и тем больше теряет полезных связей. Цель «настоящий» — не та цель для сшивки.

Вес «настоящий» в сшивке не использовать. Сигнал мухи «трек настоящий» перенести туда, где он бьёт в HOTA напрямую: удаление ложных треков (рамки жизней с низкой вероятностью «настоящий» не выводятся — растёт точность детекции DetA). Это следующая проверка (карточка ставится отдельно, с контролем без мухи). Для сшивки — замена узла «метки пары»: обучать голову пары на интерполированных метках (обрывки получают метки).

Нельзя заявлять прирост HOTA от мухи в сшивке. Нельзя называть голову «распознаванием ложных треков»: метка — совпадение рамки в последнем/первом кадре жизни с интерполированным эталоном (IoU ≥ 0,5), без проверки всей жизни, класса и взаимно однозначного сопоставления; заявимо только «FlyVis улучшает распознавание совпадения рамки начала/конца жизни с разметкой» (+0,029 AP, ДИ по видео > 0, test и val7). Интерполяция берёт только объекты, видимые в обоих соседних опорных кадрах: 14 % интерполированных отрицательных меток test (6 536 из 47 180) лежат рядом (IoU ≥ 0,3) с объектом, видимым лишь в одном из них — сомнительные отрицательные (замер 08.10, журнал). Фраза «связь ложного обрывка с настоящим треком HOTA почти не стоит» ограничена этим опытом: по определению HOTA такие рамки могут ухудшать и ассоциацию. Признаки головы начала включают статистику всей жизни — это обработка завершённых траекторий, не потоковая.
