# 🟢 З13: признаки мухи против входа глаза той же размерности (онлайн-модель цели)

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** положительный · `z13_target_model_r1_v1`

## Вопрос
Сохраняется ли преимущество признаков FlyVis над входом глаза в онлайн-модели цели, если вход глаза представлен тем же числом временных каналов?

## Гипотеза
Разрыв D / C против R0 (+8,31 / +5,95 п.п.) не объясняется только числом признаков (8 против 68).

## Ожидалось (до прогона)
Повтор вывода [z13_target_model_probe_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fz13_target_model_probe_v1) «признаки мухи сильнее входа глаза» на контроле входа той же размерности (решение автора 17.10 «давай»). R1 — вход глаза (изображение после сетчатки на 721 колонке), по всей истории эпизода 17 скользящих средних EMA_τ (τ = 1,5…32 кадра, геометрически) и 17 переходных составляющих h − EMA_τ: 34 канала, как 34 выходных типа мухи; то же правило (колонка + среднее по 6 соседям = 68 чисел), та же стандартизация, та же сетка λ и выбор λ на тех же 20 видео train104, та же онлайн-модель цели и те же 8326 строк train26. Строки C0 / C / D — из runs/z13_target_model_20261017 (не пересчитываются). Только процессор. Чтение (порог +2 п.п., как в [z13_target_model_probe_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fz13_target_model_probe_v1)): D_new − R1_new по видео — ДИ > 0 и средняя ≥ +2 п.п. — преимущество мухи сохраняется при равной размерности; верхняя граница < +2 п.п. — не сохраняется; иначе неубедительно. То же для C_new − R1_new. Ограничение заранее: R1 — один выбранный набор временных фильтров без пространственной обработки шире соседей; другой контроль мог бы дать иной итог.

## Интерпретация
Преимущество признаков FlyVis над входом глаза в онлайн-модели цели сохраняется при равной размерности: D +8,83 п.п., C +6,47 п.п., C0 +7,06 п.п. против R1, ДИ > 0; R1 не лучше R0 (−0,52 п.п.) — число временных каналов разрыв не объясняет. Разрыв больше на ранних кадрах поиска; на поздних у C интервал включает ноль. Остаётся необъяснённым, что именно даёт муха: R1 не имеет пространственной обработки шире 6 соседей, а муха объединяет сигнал многих колонок; более строгий контроль — пространственно-временной банк фильтров входа без коннектома.

## Решение
Вывод «в признаках FlyVis есть сведения для узнавания цели сверх входа глаза» подтверждён на двух контролях входа (в рамках онлайн-модели цели, train26, поиск). Следующий содержательный контроль — пространственно-временной банк фильтров той же размерности (процессор, минуты); решение — за автором. Узел онлайн-модели по-прежнему не лучше прежнего считывателя (z13_target_model_probe_v1).

## Нельзя заявлять
Нельзя заявлять роль коннектома или анатомии: C0 на том же графе не хуже C, контроля с перемешанным графом нет. Нельзя заявлять пользу для трекера или HOTA. train26 многократно использован; один набор настроек узла.
