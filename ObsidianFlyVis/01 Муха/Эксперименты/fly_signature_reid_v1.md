# 🟡 Н11: сигнатура состояния фовеального глаза FlyVis (с сетчаткой-ламиной) для повторного опознания объекта после потери трека

↑ [[01 Муха/Темы/Отпечаток мухи и опознание|Отпечаток мухи и опознание]] · **Исход:** неопределённый · `fly_signature_reid_v1`

Функция, у которой нет аналога в DIS: память об объекте. Для каждой «жизни» глаза (EyeBank, сетчатка-ламина, трекер стенда) — средние за первые и последние 5 шагов: муха (34 выходных типа × 19 макроколонок), вход глаза (721 фасетка), серая картинка рамки 16×16 и HSV-гистограмма (scripts/build_fly_signatures.py). Пары «жизнь A закончилась → жизнь B другого трека началась в пределах 2 с и 3 размеров рамки»; метка — один и тот же GT-объект (по IoU ≥ 0,5 на ближайших опорных кадрах). Лестница логистических голов: геометрия (разрыв, расстояние, отношение размеров, класс) → + внешность (картинка, гистограмма) → + вход глаза → + муха; контроль — перемешанная сигнатура мухи. Голова учится на train (70 роликов), выбор порога — dev (35), отчёт — test (35) и val7. Если голова с мухой лучше головы с внешностью и входом глаза — сквозная проверка: офлайн-сшивка треков по вероятности (заимствовано по идее: AFLink, StrongSORT, Du et al. 2023) по HOTA/IDF1/IDSw.

## Вопрос
Несёт ли состояние глаза мухи информацию об идентичности объекта сверх геометрии, внешности и собственного входа глаза?

## Гипотеза
Рекуррентное состояние центрированного и нормированного по масштабу глаза кодирует форму и контраст объекта устойчивее к освещению, чем сырые пиксели.

## Ожидалось (до прогона)
AP головы «геометрия + внешность + вход глаза + муха» на test выше головы без мухи и выше перемешанного контроля; знак тот же на val7. Затем сшивка по голове с мухой: IDF1 test выше, чем сшивка по голове без мухи.

## Что сделано
Карточка записана до расчёта (30.09.2026, 14:4x MSK). scripts/build_fly_signatures.py (проверен на b1c81faa: 317 жизней, 75 мс/кадр), запуск через scripts/run_fovea_jobs.py (универсальный сборщик и маркер готовности): val7 + test 35 + dev 35 + первые 70 train. Сборка 14:22–18:09: первые попытки тормозили/зависали из-за видеопамяти (7 процессов по 1,5–2,7 ГБ заполняли 12 ГБ) — исправлено потолком 1,5 ГБ на процесс; оценка scripts/eval_fly_reid.py 18:10–18:39 (первая сшивка упала: два трека с одним ID в кадре после сшивки — исправлено запретом связи цепочек с общими кадрами; сетка порогов расширена до 0,2–0,7).

## Получено
Пары: train 78 385 (положительных 10 845), dev 31 390, test 32 178, val7 10 443. AP dev / test / val7: геометрия 0.4385 / 0.4380 / 0.3928; геометрия + муха 0.5688 / 0.5820 / 0.5445; + внешность 0.6965 / 0.6569 / 0.6287; + вход глаза 0.7092 / 0.6859 / 0.6235; + муха 0.7114 / 0.6910 / 0.6285; + перемешанная муха 0.7107 / 0.6877 / 0.6257. Бутстреп по видео (муха − без мухи): dev +0.0039 [+0.0012; +0.0068]; test +0.0033 [-0.0013; +0.0080]; val7 +0.0022 [-0.0021; +0.0060]; против перемешанной: test +0.0017 [-0.0037; +0.0070]. Обучаемая метрика по полным векторам (|a − b|) хуже косинусной (test L_app_hexin_fly 0.6632). Сшивка (порог по dev 0,2): test HOTA без сшивки 58.469 → без мухи 59.301 → с мухой 59.302; IDF1 66.965 → 68.741 → 68.727; с мухой − без мухи: ΔHOTA test +0.000 [-0.022; +0.022], val7 +0.014 [-0.015; +0.061].

## Интерпретация
Сигнатура состояния глаза мухи несёт собственную информацию об идентичности объекта: одна она поднимает AP повторного опознания над геометрией на +0,14 (test) — это функция, которой у DIS нет. Но уменьшенная картинка, цвет и сам вход глаза несут почти то же: поверх них муха добавляет +0,003–0,005 AP (значимо только на dev), и в сшивке треков разницы нет. Вывод по Н11: у мухи есть память об объекте, но при дневном и ночном входе с ламиной она почти полностью избыточна относительно простой внешности того же фрагмента.

## Решение
Критерии 1 и 2 выполнены по агрегату (AP test с мухой выше без мухи и выше перемешанной; знак на val7 тот же), но ДИ на test и val7 задевает ноль; критерий 3 (IDF1 сшивки с мухой выше) не выполнен → inconclusive. Побочный результат — сшивка треков по внешности (карточка [[01 Муха/Эксперименты/stitch_appearance_v1|stitch_appearance_v1]]) — сильный положительный результат линии B.

## Ограничения
Сигнатура снимается только с подтверждённых треков, у которых был глаз; разметка идентичности — на опорных кадрах 5 Гц.

## Нельзя заявлять
Сравнение с обученной ReID-сетью (цель 7) — в этой карточке не проводится. Новизна идеи «замороженная FlyVis как дескриптор для сопоставления» ограничена: Kuklev, arXiv 2609.24565 (сентябрь 2026) применил её к чертежам и тоже нашёл, что дескриптор фоторецепторов (0,894) лучше полной схемы (0,835). Поправка 03.10 (F13): результат получен на одной модели ансамбля FlyVis (flow/0000/000); интервалы учитывают разброс видео, но не моделей ансамбля.
