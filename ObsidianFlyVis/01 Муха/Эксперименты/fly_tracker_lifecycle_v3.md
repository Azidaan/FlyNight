# 🟢 Трекер на мухе, этап 1, v3: удалять «ушедший» трек сразу по голове мухи вместо таймера 30 кадров

↑ [[01 Муха/Темы/Трекер на мухе|Трекер на мухе]] · **Исход:** отрицательный · `fly_tracker_lifecycle_v3`

Итерация v2: голова мухи лучше всех различает «жив / ушёл» (v1), но в продолжении это не используется. Здесь при потере трека, если голова уверена, что объект ушёл (p ниже порога, выбранного на dev так, чтобы точность «ушёл» была ≥ 0,8), трек удаляется сразу, а не висит 30 кадров — его номер не подхватит соседний объект. Поверх v2 (продолжение слабой детекцией по той же голове). Сравнение голов: геометрия / + муха / + вход / + вход + муха.

## Вопрос
Снижает ли раннее удаление «ушедших» по мухе переключения ID и даёт ли HOTA больше, чем по геометрии?

## Гипотеза
Удаление ложных «живых» треков убирает часть ошибочных повторных захватов; голова мухи точнее определяет «ушёл», поэтому выигрыш с мухой больше.

## Ожидалось (до прогона)
test: голова с мухой − голова геометрии > 0 по HOTA (ДИ по видео > 0) и IDSw меньше; итог ≥ +0,3 HOTA к стенду.

## Что сделано
scripts/fly_lifecycle_alive.py --heads (новый порог удаления: точность «ушёл» ≥ 0,8 на dev) и --track --coast 3 --mode lowscore_del; модель 000.

## Получено
Пороги удаления (dev): геометрия 0.599, муха 0.613, вход + муха 0.543. ΔHOTA к стенду, test: геометрия -0,020 [-0,103; +0,052] (20/14); муха -0,015 [-0,073; +0,034] (21/12); вход + муха -0,016 [-0,089; +0,053] (15/19); IDSw 2221 → 2237 (муха). val7: геометрия -0,113 [-0,600; +0,172] (6/1); муха +0,063 [-0,040; +0,164] (5/2); вход + муха +0,259 [-0,023; +0,679] (5/2). Для сравнения v2 (без удаления): +0,08 на test.

## Интерпретация
Раннее удаление «ушедших» треков снимает выигрыш v2 (test +0,08 → ≈ 0) и не снижает переключения ID: ошибочные повторные захваты у ByteTrack редки, а каждый пятый «ушедший» по голове объект возвращается и получает новый номер. Муха и здесь не отличается от геометрии.

## Решение
Оба критерия не выполнены → completed_negative. Удаление по голове — не рычаг; ветка «решения о жизни трека» на одной модели исчерпана: полезное действие (продолжение слабой детекцией) не требует мухи. Мухе нужны действия со спорными случаями (сшивка после долгого заслонения, ночное рождение) или дообучение (К1).

## Нельзя заявлять
Что удаление по мухе бесполезно при другом пороге: проверен один порог (точность «ушёл» ≥ 0,8).

## Условия
- **baseline:** стенд; v2 с головой геометрии
- **variant:** v2 + удаление по головам
- **dataset:** как у [fly_tracker_lifecycle_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_tracker_lifecycle_v1)
- **split:** test 35, val7

## Критерии приёмки (записаны до прогона)

  *runs/fly_lifecycle/m000/track_c3_lowscore_del.json → geometry_fly_c3_lowscore_del|test dHOTA -0.015 против geometry -0.020*
