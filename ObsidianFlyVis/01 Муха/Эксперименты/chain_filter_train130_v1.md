# 🟢 Голова удаления цепочки на цепочках train 130 (перекрёстная сшивка) — без мухи и с мухой

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** закрыт · `chain_filter_train130_v1`

Замена (б), выбор автора 09.10: больше данных для головы цепочки. Голова пары (база + MASA) обучена на train 130, поэтому train сшивается перекрёстно: две половины по видео (seed 11), каждая — головой пары, обученной на другой половине (жадно, порог 0,6, окно 150; 5). Признаки цепочки (748 без мухи / 2 040 с мухой), метки (правило output_filter_oracle), голова (логистическая регрессия C = 0,1) — как в [chain_filter_rank_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fchain_filter_rank_v1); dev/test/val7 — те же цепочки (runs/chain_filter_rank/chains.pkl). dev — чистая проверка: AP и порог при бюджете потерь 1 %; test/val7 и HOTA — только при выполнении критерия перехода. Оговорка: голова пары для train-цепочек обучена на 65 видео (для dev/test — на 130), качество сшивки немного различается. scripts/chain_filter_train130.py.

## Вопрос
Становится ли сырая сигнатура мухи полезной для головы цепочки, если обучать голову на вчетверо большем числе цепочек?

## Гипотеза
Ухудшение от мухи в [chain_filter_rank_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fchain_filter_rank_v1) — переобучение на малой выборке; на train 130 муха улучшает ранжирование на dev.

## Ожидалось (до прогона)
Критерий перехода (dev): AP с мухой − без мухи > 0, ДИ по видео > 0. При выполнении — test/val7: AP с мухой − без мухи > 0 с ДИ > 0 и HOTA при бюджете 1 % с мухой − без мухи > 0 с ДИ > 0 (val7 — знак). Справочно — AP без мухи на train 130 против 0,534 (dev вне обучения).

## Получено
runs/chain_filter_train130/report_dev.json. Цепочки train 130 (перекрёстная сшивка, runs/chain_filter_train130/train_chains.pkl, halves.json): 57839 — ложных 3321, оставить 13048 (с меткой 16369; в dev было 4 526). AP на dev: без мухи 0.5934, с мухой 0.5731, разность -0.0203 [-0.0392; -0.0006]. Справочно — прежняя голова на dev 35 (вне обучения): без мухи 0.5340, с мухой 0.5337. Бюджет потерь 1 % на dev: без мухи (порог 0.7): ложных рамок убрано 468, верных 211, потеряно 22/2447, точность удаления 0.670; с мухой (порог 0.85): ложных рамок убрано 294, верных 147, потеряно 18/2447, точность удаления 0.664. test/val7 не открывались.

## Интерпретация
Больше данных помогает голове без мухи: AP на dev 0,534 → 0,593 (+0,059); при бюджете 1 % она удаляет больше ложных рамок (468 против 434 у прежней) при тех же потерях. Сырая сигнатура мухи по-прежнему ухудшает ранжирование: −0,020 AP, ДИ ниже 0 (на dev теперь как на чистой проверке). Версия «муха вредит только из-за малой выборки» не подтвердилась: при вчетверо большем числе цепочек ухудшение осталось. Это относится к способу подачи — среднее и σ сигнатуры по концам жизней, целиком для цепочки, линейная голова; другие версии (действие над целой цепочкой слишком грубое, сигнал нужен по истории) этим опытом не проверены.

## Решение
Закрыта по заранее записанному критерию перехода (dev); test/val7 и HOTA не считались. Голова цепочки без мухи на train 130 — лучший фильтр носителя на dev (кандидат для проверки на test/val7 отдельно от вопроса о мухе). Следующее по плану — оракул удаления отдельных жизней внутри готовых цепочек.

## Нельзя заявлять
Нельзя заявлять вклад FlyVis в голову цепочки; нельзя заявлять, что муха бесполезна для удаления — проверен один способ подачи. Только dev. Ошибка 09.10: в признаках цепочки (chain_task) строки трекера собирались по номеру для каждой жизни цепочки — у цепочек с повторно вернувшимся номером строки этого номера учтены дважды (счётные признаки завышены; средние и квантили почти не меняются); в compact-варианте life_features смешивали жизни одного номера. Влияние на выводы не измерено.
