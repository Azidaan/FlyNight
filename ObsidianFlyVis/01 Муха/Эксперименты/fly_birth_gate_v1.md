# 🟢 Т2 трекера на мухе, гейт: отличает ли отпечаток мухи на начале жизни трека настоящее рождение от ложного

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** отрицательный · `fly_birth_gate_v1`

Решение автора 08.10 — начать Т2 (рождение трека, план 7.8). Мишень до стройки (6.1): потолок «идеальное рождение молодых объектов» +0,21 HOTA (detection_oracle_ladder_v1), отложенное рождение без мухи уже взяло часть; муха в q_birth по тайловому считыванию не добавляла (flyvis_event_features_v1). Гейт по фовеальному отпечатку начала жизни (first_fly, first_hexin, внешность) — scripts/fly_birth_gate.py, как для «объект ещё здесь?».

## Вопрос
Добавляет ли отпечаток мухи на начале жизни трека различение настоящих и ложных рождений сверх геометрии и сверх своего входа?

## Гипотеза
Муха различает «живой объект или ложное срабатывание» на рождении так же, как различает «объект ещё здесь?».

## Ожидалось (до прогона)
test 35: geometry_fly − geometry > 0, ДИ > 0, и geometry_hexin_fly − geometry_hexin > 0, ДИ > 0 (вклад мухи сверх входа); val7 — тот же знак. Если гейт пройден — встраивание в отложенное рождение; если нет — Т2 не строится (потолок < 1 HOTA).

## Что сделано
scripts/fly_birth_gate.py на имеющихся сигнатурах (train 130 / test 35 / val7); процессор, минуты.

## Получено
runs/fly_birth_gate/summary.json. Рождений в train 38756 (настоящих 67%). AP на test 35: геометрия 0,8375, + муха 0,8353, + вход 0,8266, + вход + муха 0,8248, + внешность 0,8356. Разности test: муха − геометрия −0,0021 [−0,0103; 0,0054]; (вход + муха) − вход −0,0019 [−0,0087; 0,0048]; внешность − геометрия −0,0019 [−0,0069; 0,0021]. val7: муха − геометрия 0,0001 [−0,0078; 0,0054].

## Интерпретация
На начале жизни трека отпечаток мухи не различает настоящее и ложное рождение (≈ 0 и на test, и на val7); внешность тоже ничего не добавляет — решает геометрия с уверенностью детектора. Вероятный узел: глаз мухи на рождении только что «включился» — отпечаток начала жизни усреднён по 1–5 первым кадрам, своей истории у глаза ещё нет, тогда как «объект ещё здесь?» работает на длинной истории жизни. Потолок рождения мал (+0,21 HOTA, [detection_oracle_ladder_v1↗](obsidian://open?vault=ObsidianFlyVis&file=02%20%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fdetection_oracle_ladder_v1)).

## Решение
Оба критерия не выполнены → completed_negative для этой реализации; Т2 в виде «голова мухи на рождении» не строится. По правилу 6.15 узел — момент считывания (нет истории у глаза); замена — решение о подтверждении рождения по отпечатку мухи через N кадров предварительной жизни (в схеме отложенного рождения N = 2–3), что требует снимка сигнатуры в середине жизни (пересборка сигнатур ≈ 3 ч GPU). Учитывая потолок +0,21 HOTA, приоритет низкий — сначала Т3 (сопоставление по отпечатку).

## Нельзя заявлять
Что муха бесполезна для рождения вообще (проверено только начало жизни, 1–5 кадров); одна модель (000).

## Условия
- **baseline:** голова геометрии; голова геометрии + вход мухи
- **variant:** + отпечаток мухи
- **dataset:** BDD100K MOT train_cache (train 130 / test 35) + val7
