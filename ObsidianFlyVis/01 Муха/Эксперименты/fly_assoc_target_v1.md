# 🟢 Т3 трекера на мухе, мишень: потолок сопоставления при рамках стенда и узел «нет истории у глаза» в узнавании

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** положительный · `fly_assoc_target_v1`

Решение автора 08.10 — Т3 (сопоставление по отпечатку мухи, план 7.8). Измерено ранее: сшивка по геометрии +0,84 HOTA (stitch_appearance_v1); в узнавании после потери муха поверх геометрии + внешности + входа +0,003, ДИ задевает 0 (fly_signature_reid_v1). Гипотеза узла (как в [fly_birth_gate_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_birth_gate_v1)): отпечаток начала нового трека — 1–5 кадров, истории у глаза нет. scripts/fly_assoc_target.py: (1) потолок сопоставления — номера треков стенда переназначены по эталону при тех же рамках; (2) прибавка мухи в узнавании по длине истории нового трека.

## Вопрос
Сколько HOTA остаётся у сопоставления при рамках стенда, и ограничена ли польза мухи в узнавании короткой историей глаза на начале трека?

## Гипотеза
Запас сопоставления ≥ 1 HOTA; прибавка мухи в узнавании растёт с длиной истории нового трека.

## Ожидалось (до прогона)
(1) Потолок: номера по эталону − как есть ≥ 1 HOTA на test (иначе Т3 не строится); сверка — «как есть» совпадает со стендом (58,469). (2) Прибавка мухи при n_first 4–5 больше, чем при 1–2 (ДИ по парам не перекрываются) — тогда замена узла: снимок отпечатка через N кадров жизни.

## Что сделано
scripts/fly_assoc_target.py на имеющихся сигнатурах; процессор.

## Получено
runs/fly_assoc_target/summary.json. (1) Потолок сопоставления при рамках стенда: test — как есть HOTA 58,469 / AssA 59,682 / IDSw 2221 (сверка со стендом 58,469 — совпадает), номера по эталону 66,383 / 76,302 / 106, Δ по видео 6,665 [5,458; 7,930]; val7 — 54,573 → 63,671, Δ 6,992. (2) Прибавка мухи в узнавании (поверх геометрии + внешности + входа) по длине истории нового трека: n_first 1-2: 0,0024 [−0,0026; 0,0071], пар 2909; n_first 3: 0,0038 [−0,0019; 0,0097], пар 1723; n_first 4-5: 0,0030 [0,0014; 0,0045], пар 27546; n_first all: 0,0031 [0,0018; 0,0045], пар 32178 (бутстрэп по парам). Разложение потолка (runs/fly_assoc_target/decompose.json, scripts/fly_assoc_decompose.py; склейка — каждому треку номер основного эталонного объекта, разрезание — трек делится при смене объекта под ним), HOTA: test: как есть 58,469 (IDSw 2221), склейка 64,606 (839), разрезание 58,859 (2410), полный оракул 66,383 (106); val7: как есть 54,573 (IDSw 526), склейка 61,502 (194), разрезание 55,154 (566), полный оракул 63,671 (27). Почти весь запас — разрывы треков (склейка +6,14 из +7,91 на test), обмены номерами — +0,39. Нынешняя сшивка по геометрии (+0,84, [stitch_appearance_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fstitch_appearance_v1)) берёт ≈ 14 % запаса склейки.

## Интерпретация
У сопоставления большой запас: при тех же рамках идеальные номера дают +6,7 HOTA на test и +7,0 на val7 (переключений личности 2 221 → 106) — это крупнейший рычаг после точности рамок (+5,7, Д1). Узел «нет истории у глаза» не подтвердился: прибавка мухи в узнавании ≈ +0,003 при любой длине истории 1–5 кадров — малая польза мухи в узнавании не от короткой истории.

## Решение
Критерий 1 выполнен (потолок ≥ 1 HOTA), критерий 2 — нет → completed_positive по мишени. Т3 строится. Следующий шаг: разложить потолок на «разрыв трека» (лечит сшивка) и «обмен номерами» (лечит онлайн-сопоставление) и бить в большую часть; признак мухи — как добавка к узнаванию (её вклад мал, +0,003 AP).

## Условия
- **baseline:** стенд XYWHByteTrack как есть
- **variant:** номера по эталону; голова узнавания с мухой
- **dataset:** BDD100K MOT train_cache (train 130 / test 35) + val7

- ❌ прибавка мухи в узнавании при n_first 4–5 больше, чем при 1–2
