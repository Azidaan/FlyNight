## Вопрос
Даёт ли фильтр жизней с мухой больше HOTA, чем тот же фильтр без мухи, при одинаковом бюджете потерь?

## Гипотеза
Лучшее ранжирование с мухой (+0,0148 AP) переходит в прирост HOTA на test.

## Ожидалось (до прогона)
Критерий: test — HOTA «с мухой − без мухи» по видео > 0, ДИ > 0; val7 — тот же знак; потери с мухой на test ≤ 1 % объектов с попаданиями. Справочно — каждый фильтр против без фильтра, доля потолка того же действия, ночь.

## Интерпретация
Результат смешанный. На test фильтр жизней с мухой лучше того же фильтра без мухи: +0,066 HOTA по видео, ДИ [+0,003; +0,134] — выше 0 впритык, 22/35 видео; на dev (порог выбран на нём) +0,149. На val7 знак обратный: −0,150 [−0,426; +0,074], лучше в 1 из 7 видео, ночью (2 видео) −0,55. Потери на test в норме (19 объектов из 2 366 с мухой). Сами фильтры берут малую долю потолка того же действия: test — 6 % без мухи, 9 % с мухой; val7 — 3 % и −2 %. Добавка мухи в HOTA на test мала (+0,08 общей) и не воспроизводится на val7 (7 видео, другой набор BDD100K — val, которого детектор не видел).

## Решение
Критерий выполнен частично (test — да, val7 — нет, потери — да): вклад FlyVis в HOTA не подтверждён. Решение о следующем шаге — за автором. Варианты: проверка на большем наборе видео val, которых детектор не видел (нужны сигнатуры мухи — GPU); история мухи внутри жизни (22 % ложных жизней и 36 % их ложных рамок — вне окна сигнатуры); усиление различения (сейчас фильтры берут 6–9 % потолка).

## Нельзя заявлять
Нельзя заявлять вклад FlyVis в HOTA: на test ДИ выше 0 впритык, на val7 знак обратный. test — из обучающей части BDD100K и уже участвует в выборе направления; val7 — 7 видео.
