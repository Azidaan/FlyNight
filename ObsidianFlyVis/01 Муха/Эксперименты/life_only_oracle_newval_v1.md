Разбор автора 10.10 после [life_filter_newval_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Flife_filter_newval_v1): прежде чем решать про историю мухи на GPU, проверить запас самого действия на новых данных. Эти видео — для объяснения ошибки; подбирать по ним порог и объявлять улучшение нельзя. scripts/newval_oracle.py.

## Интерпретация
Запас у действия на новых видео заметный: идеальное удаление полностью ложных жизней даёт ночью +1,24 HOTA общей (по видео +1,22, ДИ выше 0, 68/69), днём +1,66 (28/28); прирост почти весь в DetA, найденные объекты не теряются. Значит, провал фильтра в [life_filter_newval_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Flife_filter_newval_v1) — не в самом действии, а в различении: головы ранжируют полностью ложные жизни выше случайного (ночь AP 0,425 / 0,430 против 0,236), но этого мало, чтобы удалять с пользой; добавка мухи к AP на новых видео не доказана (ночь +0,006, ДИ содержит 0). Запас на новых видео меньше, чем на dev (+2,26), — у новых видео меньше ложных рамок на выходе.

## Решение
Критерий «запас заметен» выполнен — по плану автора следующий дешёвый шаг на тех же сохранённых данных: разбор ошибочно удаляемых настоящих жизней (какие признаки их путают с ложными), чтобы решить — нужны новые признаки, другая цель обучения или иное правило применения. Эти 97 видео — только для объяснения ошибки, не для подбора порога.

## Нельзя заявлять
Оракул по разметке: запас действия, не достижимый результат. Нельзя заявлять вклад мухи в различение на новых видео (ДИ AP содержит 0).
