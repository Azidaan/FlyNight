# 🟢 Нулевая модель коннектома: муха с перемешанными связями (степени и знаки сохранены) против настоящей — в повторном опознании поверх входа глаза

↑ [[01 Муха/Темы/Отпечаток мухи и опознание|Отпечаток мухи и опознание]] · **Исход:** неопределённый · `fly_connectome_null_v1`

Контроль, без которого вклад мухи нельзя приписать топологии коннектома (Dhiman, arXiv 2604.04033, 2026). tracking/connectome_null.py, режим type_sign: получатели связей (network._target_indices) переставлены внутри групп «знак веса × тип нейрона-получателя» — сохранены число входов и выходов каждого нейрона, знак и обученная сила каждой связи, число входящих связей каждого знака у каждого типа; разрушены ретинотопия и схема «тип → тип» (проверка на b1c81faa: 99,9 % связей переставлено, входящие степени совпадают, активность конечна). Те же ролики, трекер, сетчатка и пары, что в [fly_matched_controls_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_matched_controls_v1); сигнатуры — runs/fly_signatures_null(_val).

## Вопрос
Держится ли дополнительный вклад мухи поверх входа глаза (+0,006 test, +0,010 ночью) на перемешанном коннектоме?

## Гипотеза
Если вклад создаётся топологией коннектома, настоящая муха лучше перемешанной; литература (Dhiman 2026, Kuklev 2026) допускает, что разницы нет.

## Ожидалось (до прогона)
Если топология важна: AP test головы «геометрия + вход + муха» у настоящей мухи выше, чем у перемешанной, с ДИ бутстрепа по видео > 0; ночью разница не меньше. Если разницы нет (ДИ через ноль) — вклад не приписывается коннектому (cannot_claim).

## Что сделано
Карточка записана до расчёта (30.09.2026, 23:2x MSK). Запуск 23:2x: 147 роликов, 7 процессов (сторожа run_fovea_jobs с extra_args --rewire type_sign --rewire-seed 0). Сборка 30.09 23:2x – 01.10 01:5x (7 перезапусков сторожем). Лестница: scripts/eval_fly_reid.py --ladder-only --sig-root runs/fly_signatures_null → runs/fly_reid_null/report.json; сравнение scripts/compare_connectome_null.py → runs/fly_reid_null/compare.json. Самопроверка: головы без мухи в обоих отчётах совпадают точно (test geometry_hexin 0.6248 = 0.6248).

## Получено
AP test / val7, настоящая / перемешанная муха: геометрия + муха 0.5820 / 0.5219 и 0.5445 / 0.5026; геометрия + вход + муха 0.6323 / 0.6279 и 0.5639 / 0.5541; геометрия + внешность + вход + муха 0.6910 / 0.6868. Настоящая − перемешанная (бутстреп по видео, лучше/хуже): геометрия + муха — test +0.0437 [+0.0273; +0.0595] (29/5), dev +0.0427 [+0.0256; +0.0603] (27/7), тёмные +0.0497 [+0.0264; +0.0744] (19/6), светлые +0.0391 [+0.0265; +0.0509] (37/6); геометрия + вход + муха — test +0.0032 [-0.0028; +0.0100] (15/20), dev +0.0060 [+0.0017; +0.0106] (24/10), тёмные +0.0063 [-0.0021; +0.0155] (16/10), светлые +0.0036 [+0.0005; +0.0068] (23/20).

## Интерпретация
Топология коннектома существенна для собственного представления мухи: сигнатура настоящей мухи различает «тот же объект / другой» значимо лучше, чем сигнатура той же сети с перемешанными проводами (+0,044 AP на test, лучше в 29 из 35 роликов; ночью +0,050). Но дополнительный вклад мухи поверх её входа держится на топологии лишь частично: перемешанная муха поверх входа тоже добавляет ~+0,003, настоящая — ещё +0,003 (ДИ на test задевает ноль; на dev значимо). Иначе говоря, коннектом делает представление мухи информативнее, но большую часть этой информации простой вход глаза уже содержит.

## Решение
Критерий 1 (настоящая > перемешанной в голове «геометрия + вход + муха», ДИ test > 0) не выполнен: +0,0032, ДИ [−0,0028; +0,0100]; критерий 2 (ночью разница не меньше) выполнен по средним (+0,0063 против +0,0036), но ночная разность незначима → inconclusive. Положительная побочная находка — значимый эффект топологии на собственное представление мухи — формулируется как свойство модели, а не как прирост трекинга.

## Ограничения
Один сид перестановки; параметры обученной мухи не переобучаются под перемешанный граф (контроль «та же сеть, другие провода»). Разрез по освещению — поисковый, без поправки на множественные сравнения.

## Нельзя заявлять
Что прирост трекера или дополнительный вклад мухи поверх входа обусловлен именно коннектомом (на test ДИ задевает ноль); один сид перестановки. Поправка 03.10 (research_fundamental_problems, F17): перемешивание сделано БЕЗ переобучения (tracking/connectome_null.py сохраняет обученные параметры) — это проверка расстройки обученной мухи, а не топологии; при переобучении перемешанной сети из общей начальной точки разница исчезает (Dhiman, arXiv 2604.04033). Нельзя заявлять «топология коннектома значима»; один сид перестановки, одна модель ансамбля (flow/0000/000).
