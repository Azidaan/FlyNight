# 🟢 Замена узла доверия: фотометрическая проверка поправки мухи по изображению (постоянство яркости, как в KLT)

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** отрицательный · `fly_motion_photometric_v1`

Правило 6.15: узел провала доверия к движению мухи — оценка надёжности поправки (уверенность поля AUC 0,51). Замена из работ по оптическому потоку и трекингу: проверка прогноза по изображению — шаблон объекта из прошлого размеченного кадра сравнивается нормированной корреляцией с текущим кадром в рамке, сдвинутой Калманом и поправкой мухи; поправка принимается, если совпадение лучше. Параметров нет — проверка сразу на 24 отложенных видео (17 dev + val7). Контроли: та же проверка с предложением «нулевое движение» (вклад проверки без мухи) и с DIS. Схема 5 Гц (motion_scheme_search_v1).

## Вопрос
Делает ли фотометрическая проверка поправку мухи полезной для трекера, и обязана ли польза предложениям мухи?

## Гипотеза
Изображение надёжно отличает верную поправку от неверной; с проверкой муха даёт прирост HOTA, и он больше, чем у проверки с «нулевым движением».

## Ожидалось (до прогона)
24 отложенных видео: муха + проверка − без движения > 0, ДИ > 0; муха + проверка − «нулевое движение» + проверка > 0, ДИ > 0 (вклад предложений мухи).

## Что сделано
scripts/motion_scheme_search.py (источники fly#photo, zero#photo, dis#photo), 17 dev + val7; процессор.

## Получено
runs/motion_scheme_search/photo_summary.json (dev_photo.json, val7_photo.json), 24 отложенных видео, схема 5 Гц, HOTA: муха + проверка − без движения −0,489 [−0,995; −0,052], лучше 9/24; нулевое движение + проверка − без движения −0,660 [−1,065; −0,331], лучше 5/24; муха + проверка − нулевое + проверка 0,171 [−0,301; 0,610], лучше 15/24; DIS + проверка − без движения 0,177 [−0,722; 0,915], лучше 16/24; муха без проверки − без движения −1,094 [−2,304; −0,104], лучше 10/24. Проверка принимает ≈ 6 % поправок мухи (средний вес в журнале расчёта).

## Интерпретация
Фотометрическая проверка вдвое уменьшает вред мухи (−1,09 → −0,49), но сама вредит трекеру: с нулевым движением −0,66, с DIS съедает почти весь его выигрыш (+0,18 против +2,40 без проверки на тех же видео). Узел провала — сама проверка: сравнение изображения целой рамки (нормированная корреляция, ½ разрешения) за 6 кадров на 5 Гц ненадёжно — меняются вид и размер объекта, частичные перекрытия; рамка Калмана часто совпадает «лучше», хотя хуже по положению. Вклад предложений мухи сверх контроля +0,17 — не значим.

## Решение
Критерии не выполнены → completed_negative для этой реализации (правило 6.15: узел — проверка изображения целой рамки). Замены узла проверки: проверка по точкам внутри рамки с ошибкой «вперёд-назад» (Kalal et al., 2010, «медианный поток»), проверка на полной частоте кадров (30 Гц, малые изменения вида), масштаб рамки в проверке.

## Нельзя заявлять
Что фотометрическая проверка вообще бесполезна (одна реализация); что муха хуже нулевого движения при проверке (+0,17, ДИ содержит 0).

## Условия
- **baseline:** без движения; проверка с нулевым движением; DIS + проверка
- **variant:** муха + lcn24 + фотометрическая проверка
- **dataset:** BDD100K MOT train_cache dev (17 проверочных) + val7

## Критерии приёмки (записаны до прогона)
- ❌ муха + проверка − без движения > 0, ДИ > 0 (24 отложенных)  
  *photo_summary.json → fly#photo−none -0.489, ci95 [-0.9951309164807497, -0.052321707818538246]*
- ❌ муха + проверка − нулевое движение + проверка > 0, ДИ > 0  
  *fly#photo−zero#photo 0.171, ci95 [-0.3006848397452011, 0.6099584802283862]*
