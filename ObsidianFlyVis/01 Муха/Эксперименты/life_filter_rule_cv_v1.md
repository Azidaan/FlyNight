# 🟢 Ограниченный выбор правила удаления жизней по 5 частям train+dev с ограничением потери верных рамок (вариант (б) перед проверкой на новых val)

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** положительный · `life_filter_rule_cv_v1`

Решение автора 09.10: (б) — одна ограниченная подготовка, затем (а) — однократная проверка на новых val-видео; (в) — запасной. 165 видео (train 130 + dev 35), 5 частей по видео; прогнозы обеих голов (бустинг, одна конфигурация) — вне обучения. Пороги 0,55–0,90 и «ничего не удалять»; ограничения в каждой части — потеря объектов ≤ 1 % и удалённых верных рамок ≤ 0,5 % верных рамок части (предел 0,5 % задан агентом: прежний порог 0,6 удалял ≈ 0,9 % на dev); полезность — средняя по видео разность HOTA с без фильтра по 165 видео с ДИ. Итоговые модели для (а) — на train+dev; порог — из этой процедуры. scripts/life_filter_rule_cv.py.

## Вопрос
Есть ли правило удаления, соблюдающее ограничения потери объектов и верных рамок в каждой части и дающее положительную разность HOTA вне обучения?

## Гипотеза
Осторожный порог при обоих ограничениях сохраняет положительный эффект удаления ложных рамок.

## Ожидалось (до прогона)
Переход к (а) — для головы выбран порог (не «ничего не удалять») с разностью HOTA − без фильтра > 0, ДИ > 0 (165 видео). Если безопасным оказывается только «ничего не удалять» — большой проход на новых val не оправдан. Справочно — «с мухой − без мухи» на выбранных порогах.

## Интерпретация
Формально критерий перехода выполнен для обеих голов, но эффект крошечный. Ограничение на верные рамки отсекает пороги ниже 0,7. Голова без мухи: ДИ выше 0 только у порога 0,85 — +0,0008 HOTA, меняется 7 видео из 165, практически «ничего не удалять»; при 0,7 — +0,016, ДИ содержит 0. Голова с мухой: при 0,7 — +0,021 HOTA (ДИ выше 0, лучше в 100/165), при 0,75 и 0,8 — тоже ДИ выше 0. При одинаковом пороге 0,7 голова с мухой удаляет больше ложных рамок (706 против 639) и даёт ДИ выше 0, без мухи — нет. Разность «с мухой − без мухи» на выбранных порогах (+0,020, ДИ выше 0) — по сути сравнение с почти пустым фильтром; она смешивает муху и выбор порога. Величина +0,02 HOTA — около 0,03 % исходного HOTA.

## Решение
Порог зафиксирован для (а): без мухи 0,85, с мухой 0,7 (по правилу); дополнительно — общий порог 0,7 для обеих голов (разводит муху и выбор порога). Запуск (а) — только с согласия автора (решение автора 09.10: «не запускать без меня»). Оговорка: при таком малом эффекте на 165 видео ожидаемая разница на новых видео мала; решение о затратах GPU — за автором.

## Нельзя заявлять
Нельзя заявлять заметный прирост HOTA от фильтра (≈ +0,02); нельзя заявлять вклад FlyVis — разность на выбранных порогах смешивает муху и порог; это данные разработки (train+dev).
