## Вопрос
Лучше ли муха выбирает отдельные ложные жизни для удаления, чем тот же фильтр без мухи, при правильной идентификации жизней?

## Гипотеза
На чистых данных «жизнь → признаки → метка» сигнатура мухи улучшает ранжирование ложных жизней.

## Ожидалось (до прогона)
Критерий перехода (dev): AP с мухой − без мухи > 0, ДИ по видео > 0. При выполнении — HOTA при бюджете 1 % (порог из dev) на dev, test и val7: с мухой − без мухи > 0 с ДИ > 0 на test, val7 — знак; потери ≤ 1 %. Справочно — без мухи − без фильтра.

## Решение
Закрыта по заранее записанному критерию перехода (dev). Следующее (выбор автора 09.10) — ограниченная парная проверка более сильной головы (градиентный бустинг) на сохранённых признаках, подбор настроек внутри train по видео. Поправка 09.10: оракул +0,956 получен после идеального удаления ложных цепочек; обученная голова применяется к исходному выходу и может удалять жизни в любых цепочках — долю потолка обученной головы считать только по оракулу того же действия на том же исходном выходе.
