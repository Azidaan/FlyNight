# ⚫ Сжатая муха в голове удаления цепочки: три парных варианта (V0 / V1 без мухи / V2 с мухой), сначала dev

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** закрыт · `chain_filter_compact_fly_v1`

Замена узла (а) после [chain_filter_rank_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fchain_filter_rank_v1), решение автора 08.10 — парная постановка. V0 — нынешний фильтр без мухи; V1 — V0 + сжатый выход головы «совпадение рамки начала/конца жизни» без мухи; V2 — V0 + тот же выход той же головы с мухой. Головы жизней обучаются одинаково на train 130 (scripts/stitch_realness, интерполированные метки); свод в цепочку одинаковый для V1 и V2 (среднее, минимум, максимум r_end и r_start по жизням, r_end последней и r_start первой жизни — 8 чисел). V2 − V1 — только муха; V1 − V0 — дополнительное обучение на train 130. Голова цепочки, части проверки dev, бюджет потерь — как в [chain_filter_rank_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fchain_filter_rank_v1). Прежняя голова предсказывает другую цель (совпадение рамки отдельной жизни), здесь она — только признак. Сначала только dev (вне обучения): AP и потери при бюджете 1 %; test/val7 и HOTA — только при выполнении критерия перехода. scripts/chain_filter_rescore.py.

## Вопрос
Даёт ли сжатый выход головы с мухой лучшее ранжирование цепочек, чем тот же выход головы без мухи?

## Гипотеза
Сжатое представление не переобучается; сигнал мухи (+0,029 AP на уровне жизней) переносится в ранжирование цепочек.

## Ожидалось (до прогона)
Критерий перехода (dev, вне обучения): AP V2 − AP V1 > 0, ДИ по видео > 0. Только при выполнении — test/val7 (AP V2 − V1 > 0 с ДИ > 0) и HOTA при бюджете 1 % (V2 − V1 > 0, ДИ > 0; val7 — знак).

## Интерпретация
Сжатый выход головы «совпадение рамки начала/конца жизни» ничего не добавляет к голове цепочки — ни без мухи (V1 − V0 −0,0008), ни с мухой (V2 − V1 +0,0007, ДИ содержит 0); при бюджете 1 % все три варианта удаляют почти одно и то же. Сигнал мухи на уровне отдельной жизни (+0,029 AP в [stitch_realness_fly_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fstitch_realness_fly_v1)) в оценку целой цепочки не переходит: признаки цепочки V0 (уверенность детектора, длительность, рамка, вход глаза) уже несут ту же информацию, что выход этих голов.

## Решение
Закрыта по заранее записанному критерию перехода (dev): test/val7 и HOTA не считались. Закрыта гипотеза «сжатый выход головы совпадения рамки с мухой улучшает ранжирование цепочек», не направление. Узел: у мухи в нынешнем виде (сигнатура на концах жизней) нет информации о ложности цепочки сверх признаков носителя. Варианты замены (правило 6.15) — признак мухи по всей жизни цепочки, а не по концам; больше данных для головы цепочки (train 130); другое действие для сигнала мухи. Выбор — за автором.

## Нельзя заявлять
Нельзя заявлять вклад FlyVis в ранжирование цепочек для удаления. test и val7 не использовались — выводы только по dev вне обучения.
