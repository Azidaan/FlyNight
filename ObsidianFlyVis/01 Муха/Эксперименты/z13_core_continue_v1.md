# 🟢 З13: продолжение обучения ядра D против продолжения только считывателя (ступень 1, 1000 шагов)

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** отрицательный · `z13_core_continue_v1`

## Вопрос
Улучшает ли дальнейшее обучение ядра D объектную локализацию по сравнению с продолжением обучения только пространственного считывателя при том же исходном состоянии?

## Гипотеза
Если ядро после 4000 шагов (≈ 1,53 условного прохода по 41 724 примерам train104, reports/z13_training_budget_20261017.json) не исчерпало полезное изменение, D-train даст больше полезных центров на train26, чем D-frozen при тех же пакетах.

## Ожидалось (до прогона)
Протокол runs/z13_continue_20261017/protocol.json (хеши кода и исходной контрольной точки). Исходное состояние — runs/z13_spatial_v2_20261013/D/full/checkpoint.pt, шаг 4000; аудит согласованности пройден (runs/z13_continue_20261017/audit.json). D-train: ядро (734 свободных параметра, lr 1e-4 / 5e-6 / 5e-6, притяжение λ = 1) + прежний пространственный считыватель (lr 3e-3), Adam восстановлен целиком. D-frozen: ядро той же D заморожено, Adam только группы считывателя с перенесёнными моментами. Пакеты, генераторы, данные (train104), функция потерь, нормировка, вырезки — общие; хеш пакета пишется на каждом шаге. Ступень 1 — по 1000 дополнительных шагов, порядок D-frozen → D-train; продолжение до 4000 — отдельное решение. Оценка: фиксированный набор train26 (эпизоды без возмущения, все помеченные кадры) до обучения (со сверкой с сохранёнными предсказаниями D: |Δp| < 1e-3, |Δцентр| < 0,5 px) и после каждого варианта. Главная мера — доля полезных центров среди положительных (scripts/z13_train.success), парный бутстрэп по видео (5000). Дополнительно: медиана ошибки в долях масштаба, NLL цели, вмешательства при доле отбора 1 / 2 / 5 % всех строк (известные / неизвестные / полезные / вредные), обучающая ошибка последних 100 шагов. Минимальный практически полезный сдвиг (предложение агента, до прогона; автор может изменить до запуска): +2 п.п. доли полезных центров по видео — разрешающая способность train26 (пилот распределённой цели, полуширина ДИ ≈ 2 п.п.). Чтение: ДИ D-train − D-frozen целиком > 0 и средняя ≥ +2 п.п. — дальнейшее обучение ядра улучшает локализацию (поиск, train26 многократно использован); верхняя граница ДИ < +2 п.п. — в этом режиме дальнейшее обучение ядра полезного сдвига не даёт; иначе — неубедительно. Причину провала эта пара не устанавливает; преимущество FlyVis над B и роль анатомии не проверяются. Бюджет (предварительный): D-train ≈ 20,5 мин по исторической скорости 1,23 с/шаг (runs/z13_spatial_v2_20261013/D/full/status.json), D-frozen не дольше, три оценки train26 по ≈ 2–3 мин, загрузка данных ≈ 2–4 мин; итого ≈ 45–55 мин; жёсткий срок остановки 1,5 ч; скорость нового запуска измеряется в первых шагах и пишется в консоль.

## Интерпретация
По заранее записанному правилу дальнейшее обучение ядра в этом режиме полезного сдвига не даёт: верхняя граница ДИ D-train − D-frozen (+0,83 п.п.) ниже минимального полезного сдвига +2 п.п.; средняя отрицательна (−1,67 п.п.). Обе продолжающие ветви не улучшили исходную D, а D-train её ухудшил (−2,94 п.п., ДИ ниже нуля); NLL цели на train26 растёт сильнее у D-train при почти равной обучающей ошибке — продолжение, вероятно, подгоняет train104, не обобщая (вывод из чисел, причина не установлена). В верхних 1–2 % отбора обе ветви хуже исходной D по числу полезных среди известных.

## Решение
Ступень 2 (до +4000 шагов) для ядра не запускается: по правилу протокола дальнейшее обучение ядра в этом режиме признано не полезным. Узел провала эта пара не устанавливает; недообученность ядра как причина прежнего провала З13 не подтверждена. Следующий шаг — по решению автора: проверка «муха против входа глаза» для узла DiMP (процессор), контроль B — при последующих заявках.

## Нельзя заявлять
Нельзя заявлять, что обучение ядра вредно вообще: один сид, один режим (продолжение с шага 4000, те же скорости), train26 многократно использован. Нельзя переносить на HOTA. Нельзя делать вывод о FlyVis против B или об анатомии.
