# 🟡 Трекер на мухе, этап 1: решение «трек жив / удалить» по отпечатку мухи вместо таймера ByteTrack

↑ [[01 Муха/Темы/Трекер на мухе|Трекер на мухе]] · **Исход:** неопределённый · `fly_tracker_lifecycle_v1`

Первый этап линии 7.8 (решения ByteTrack принимает муха). Событие — потеря трека стендом (XYWHByteTrack); у всех 283 потерь пробного видео есть сигнатура глаза мухи (ключ «номер трека + первый кадр потери» совпадает побайтно, выходы трекера при повторном прогоне совпали с сигнатурами). Метка по разметке: объект ещё присутствует на размеченных кадрах в пределах 30 кадров («жив») или нет. Головы «жив ли» (логистическая регрессия): геометрия; + муха (last_fly, 34 × 19); + вход глаза (721 фасетка); + вход + муха; + внешность. Трекер: потерянный трек выдаётся по предсказанию Калмана ≤ 3 кадров, только если голова говорит «жив» (порог — максимум F1 на dev); сравнение со стендом и со слепым продолжением (track_continuation_v1: −0,82 HOTA). Обучение голов — train 130, оценка — dev / test / val7; модель ансамбля 000, затем повтор на моделях Д5.

## Вопрос
Лучше ли муха таймера и контролей решает, что потерянный трек ещё жив?

## Гипотеза
Отпечаток мухи с сетчаткой отличает «объект ещё здесь» от «пропал» лучше таймера и не хуже обычной сети, особенно ночью.

## Ожидалось (до прогона)
Голова с мухой различает «жив / ушёл» лучше геометрии и лучше внешности; поверх входа глаза — не хуже. Продолжение по решению головы с мухой даёт ≥ +0,3 HOTA на test и лучше продолжения по голове на одной геометрии. Если муха не лучше входа — заявлять пользу схемы мухи для решения нельзя.

## Что сделано
scripts/fly_lifecycle_alive.py: события потерь по сигнатурам модели 000 (видео с сигнатурами: train 70, dev 35, test 35, val7 7; событий train 13072, доля «жив» 0.81); головы — логистическая регрессия; трекер — стенд с продолжением ≤ 3 кадров по решению головы (порог — максимум F1 на dev).

## Интерпретация
Впервые в проекте муха обходит собственный вход: для решения «объект ещё здесь?» вход глаза (721 фасетка) и внешность ничего не добавляют к геометрии, а состояние мухи на момент потери добавляет (+0,009–0,011 AP, ДИ > 0 на test; поверх входа и на dev). Вероятное объяснение — временная информация в динамике нейронов, которой нет в одном кадре. Но продолжение трека по предсказанию Калмана HOTA не даёт ни с одной головой: голова убирает вред слепого продолжения (−0,82 → ≈ 0), а неточная рамка-предсказание съедает выигрыш (точность рамок — крупнейший рычаг, [detection_oracle_ladder_v1↗](obsidian://open?vault=ObsidianFlyVis&file=02%20%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fdetection_oracle_ladder_v1)).

## Решение
Критерии 1 и 2 выполнены (на модели 000), критерий 3 — нет → inconclusive. Следующая итерация — [fly_tracker_lifecycle_v2↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_tracker_lifecycle_v2): при «жив» продолжать трек рамкой слабой детекции, а не предсказанием; повтор голов на моделях ансамбля после Д5.

## Нельзя заявлять
Что муха улучшает трекинг: на уровне HOTA эффекта нет; доля «жив» 80 % делает AP высоким у всех голов.
