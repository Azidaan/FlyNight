# 🔴 А2: удаление ложных жизней по временной истории измерений — одинаковая временная голова без FlyVis и с FlyVis (одна реализация)

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** отрицательный · `life_fly_history_v1`

Решение и границы автора 11.10. Мишень: оракул, удаляющий только полностью ложные жизни с > 5 измерениями глаза, — ночь 57,678 → 58,498 на 97 новых val (runs/newval_long_false_oracle/report.json; потолок при знании разметки). Нынешняя сигнатура — два средних первых и последних 5 измерений; у жизней длиннее пяти измерений середина и порядок теряются. Действие (одно): удалить рамки жизни из выхода после MASA, если временная голова считает её ложной (как в life_filter --v2). Пересчёт сигнатур train 130 + dev 35 тем же трекером (буфер 30) с сохранением по шагам: выход мухи (34 × 19), вход глаза (721), миниатюра 16 × 16, гистограмма (40); история не длиннее 32 шагов (равномерное прореживание). Временная голова (одна, задана до прогона): по каждому признаку — среднее, ст. отклонение, минимум, максимум, наклон по времени, средний модуль приращения + длина жизни и прежние признаки без мухи (751); HistGradientBoosting конфиг 0 (lr 0,1, 15 листьев, 200 итераций, l2 1,0, random_state 0). Без мухи — эти статистики по входу глаза, миниатюре и гистограмме; с мухой — то же плюс статистики выхода мухи; больше отличий нет. Сверка: жизни (track_id, start, end) и выход трекера совпадают с runs/fly_signatures; средние первых / последних 5 шагов из истории совпадают с сохранёнными в пределах fp16. Пробный прогон (019efe88-bbc2a4ac, dev, флаг --history scripts/build_fly_signatures.py → runs/fly_signatures_hist): track_id, start, end, n_first, n_last, cls и выход трекера совпадают с runs/fly_signatures; признаки без мухи — точно, средние мухи — до 0,002 (fp16 GPU); число шагов истории = end − start; среднее первых 5 шагов истории = first_fly у 2 112 из 2 112 жизней ≤ 32 шагов; ≈ 5 мин GPU и 25 МБ на видео. Признаки голов: без мухи — прежние 751 + длина жизни + статистики по времени входа глаза, миниатюры, гистограммы; с мухой — то же + прежние средние мухи (первые / последние 5) + статистики по времени выхода мухи.

## Вопрос
Различает ли временная история измерений мухи ложные жизни лучше такой же истории без мухи, с выигрышем HOTA?

## Гипотеза
Порядок и изменение ответов мухи внутри жизни несут сведения о ложности, которых нет в двух средних и в такой же истории обычных признаков.

## Ожидалось (до прогона)
Стоимость: ≈ 6 ч GPU (165 видео × ≈ 2,2 мин при трёх процессах), диск ≈ 4 ГБ; головы — процессор. Разрешение автора 11.10 — один прогон train 130 + dev 35. Порог (решение автора 11.10): подбор на train 130 по 5 частям по видео с прогнозами вне обучения, по правилу life_filter_rule_cv (сетка 0,55–0,90 и «ничего не удалять»; допустим, если в каждой части потеря объектов ≤ 1 % и удалённых верных рамок ≤ 0,5 %; выбирается допустимый с наибольшей средней по видео разностью HOTA с без фильтра при ДИ > 0, иначе «ничего не удалять»), для каждой головы одинаково. Итоговые головы — на всём train 130. dev 35 — одна проверка зафиксированных голов и порогов, три выхода: без фильтра, временная голова без мухи, та же голова с мухой. Критерий: (1) с мухой − без мухи по видео > 0, ДИ > 0; (2) с мухой − без фильтра по видео > 0, ДИ > 0; (3) на dev потеря объектов ≤ 1 % и верных рамок ≤ 0,5 %. Не выполнен — остановиться без переделки головы и без новых видео. Граница формулировки (дописано до результата, 11.10, расчёт идёт; опыт не меняется): вариант «с мухой» содержит и прежние два средних мухи, и временную историю, поэтому разность «с мухой − без мухи» оценивает вклад всего набора сигнала мухи, а не пользу именно середины жизни или порядка измерений. Поправка 11.10 (до расчётов на списке): 7 дневных видео списка уже скачаны, но без выравнивания кадров с разметкой — исключаются правилом alignment_ok; пригодных не более 89 (все — других условий, ещё не скачаны). Конвейер подготовлен: scripts/heldout_pipeline.py (cache / jobs / stitch / check); шаг stitch на готовых кэшах 2 новых val воспроизводит сшивку, метки и признаки жизней точно.

## Интерпретация
Эта реализация А2 не сработала: голова с мухой (прежние два средних + шесть статистик временной истории) на train не нашла порога с приростом HOTA при ДИ > 0 и по протоколу ничего не удаляет; на dev она совпадает с выходом без фильтра, все критерии не выполнены. Различения тоже нет: на train вне обучения добавка мухи немного ухудшает AP в целевой группе (жизни > 5 измерений: −0,009, ДИ ниже 0), на dev — +0,009 с ДИ через 0; знак не устойчив. Та же временная голова без мухи прошла отбор на train (0,70: +0,029, ДИ > 0), но на dev не дала прироста (+0,004, ДИ через 0) — временная сводка обычных признаков тоже не переносится. Вывод относится к данной сводке временных сигналов (среднее, разброс, экстремумы, наклон, приращения) и ко всему набору сигнала мухи, а не к любой модели, использующей порядок измерений.

## Решение
По протоколу (решение автора 11.10): остановиться без переделки головы и без новых видео; 75 пригодных отложенных val не расходуются. Оракульная мишень (+0,820 ночью на 97 новых val) остаётся, но этой реализацией не взята. Узел провала по разбору: сигнал мухи в данной сводке не добавляет различения ложных жизней сверх обычных признаков (AP). Замены — только по решению автора ([раздел 5↗](obsidian://open?vault=ObsidianFlyVis&file=05%20%D0%9F%D0%BB%D0%B0%D0%BD%2F5.%20%D0%A7%D1%82%D0%BE%20%D0%B6%D0%B8%D0%B2%D0%BE) разбора research_flyvis_a2_error_analysis_2026-10-11: цель «польза удаления» вместо вероятности ложности, иные признаки порядка — catch22 / MultiRocket на сохранённых рядах).

## Нельзя заявлять
Нельзя заявлять, что временная история мухи бесполезна вообще: проверена одна сводка шести статистик (история ≤ 32 шагов) и одна голова. Нельзя заявлять вред мухи для трекера: голова с мухой ничего не удаляет. dev использован многократно; независимая проверка не проводилась.
