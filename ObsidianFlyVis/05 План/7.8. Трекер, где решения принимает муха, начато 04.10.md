# 7.8. Трекер, где решения принимает муха, начато 04.10

↑ [[05 План/7. Действующий план|7. Действующий план]]

**Решение автора 04.10.** После Д5 — сделать мухе ведение учёта треков с целью полной замены ByteTrack мухой. Под «полной заменой» понимается: все решения трекера (где будет объект, какая рамка чья, родить, держать, удалить трек) принимает муха; счётчик номеров и список треков остаются кодом. Итог сравнивается с ByteTrack (стенд и итоговый трекер линии B) на тех же детекциях — без этого заявка недоказуема.

**Устройство.** Уже сейчас «один глаз — один трек» (EyeBank): трек жив, пока его глаз «видит объект»; умирает, когда отклик гаснет; рождается, когда новый глаз подтверждает объект. Решения читают обученные головы поверх отпечатка мухи (сетчатка-ламина обязательна).

**Этапы (каждый — со своим гейтом и критерием заранее).**
1. *Жизнь трека* (держать / удалить) — мишень Д2: у ~1/3 реальных потерь на пороге объект уверенно виден в прошлых 5 кадрах ([past_view_oracle_v1↗](obsidian://open?vault=ObsidianFlyVis&file=02%20%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fpast_view_oracle_v1)), а простое продолжение по Калману вредит ([track_continuation_v1↗](obsidian://open?vault=ObsidianFlyVis&file=02%20%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ftrack_continuation_v1)). Сравнение: таймер ByteTrack (30 кадров) / голова по отпечатку мухи / та же голова на входе мухи без мухи / обычная маленькая сеть того же размера на той же картинке. Прежняя проверка [flyvis_event_features_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fflyvis_event_features_v1) (без сетчатки, без мишени) — отрицательная; повтор оправдан новыми условиями.
2. *Рождение трека* — голова мухи против отложенного рождения без мухи ([birth_deferred_train_v1↗](obsidian://open?vault=ObsidianFlyVis&file=02%20%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fbirth_deferred_train_v1)).
3. *Сопоставление* — стоимость по отпечатку мухи (+ геометрия) вместо одного перекрытия рамок; основание — отпечаток мухи к геометрии +0,14 AP ([fly_signature_reid_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_signature_reid_v1)).
4. *Движение* — предсказание положения мухой вместо фильтра Калмана; только после дообучения мухи на видео BDD (К1, рецепт F18), так как сейчас ошибка мухи 8,0 px против 2,6 у DIS ([fly_decoder_refit_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_decoder_refit_v1)).
5. *Сборка* — все четыре решения от мухи; HOTA / IDF1 / IDSw на test 35 и val7 против ByteTrack; ≥ 3 модели ансамбля (по итогам Д5), двухуровневый бутстреп.

**Что должно выполняться для заявки.** На каждом этапе муха не хуже контроля «тот же вход без мухи» и обычной сети того же размера; итоговый трекер не хуже ByteTrack по HOTA на test (ДИ по видео) и лучше хотя бы ночью или на объектах, пропавших на несколько кадров. Честный ожидаемый исход по прежним данным — этапы 1–3 возможны, этап 4 — главный риск.
