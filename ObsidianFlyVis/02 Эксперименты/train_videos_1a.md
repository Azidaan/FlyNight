# 🔧 Цель 1а: исходные обучающие видео BDD100K MOT — загрузка, манифест, выравнивание с разметкой, разбиение

**Направление:** [[03 Направления/Инфраструктура и данные|Инфраструктура и данные]] · **Исход:** инфраструктура · `train_videos_1a`

1 400 MOT-train роликов выкачиваются по диапазонам байт из официального bdd100k_videos.zip (1,97 ТБ; Zip64-каталог читается с конца; CRC32/sha256); для каждого — частота и кадры по контейнеру, сопоставление размеченных кадров с исходными по содержимому (tracking.video_alignment, радиус 24, как у семи val-видео), аудит (max MAE ≤ 2,5, шаги 1–12, монотонность); разбиение train/dev/test 70/15/15 по sha1(ID), фиксируется до обучения. Семь val-видео остаются отдельным отложенным набором.

## Вопрос
Инфраструктурный: пригодны ли обучающие видео для обучения голов FlyVis и линии B (частота ~30 Гц, читаемость, соответствие разметке)?

## Ожидалось (до прогона)
Манифест с числом пригодных роликов, диапазоном частот, числом отказов выравнивания и составом разбиения; без научных выводов.

## Что сделано
scripts/zip_range_fetch.py (4 теста), scripts/fetch_bdd100k_videos.py (12 потоков, докачка), scripts/build_train_video_manifest.py (дымовой прогон 3 видео: все выровнены, 30,04–30,15 fps). Загрузка (PID 17380) и выравнивание (PID 24056, ~18 с/видео) идут 17.09 с 01:1x MSK. Загрузка завершена 17.09 02:1x MSK (25,8 ГБ за 62 мин, 6,9 МБ/с). Выравнивание: 3 шарда с повтором радиуса 24→48→96 и допуском шага 36, завершено 03:57; манифесты слиты.

## Получено
1 400/1 400 роликов, CRC32 из каталога архива совпал у всех, sha256 записаны; читаются 1400/1400; частота по контейнеру 29.267–30.424 кадр/с; кадров 591–1 567. Выравнивание по содержимому пригодно у 1281 роликов (91.5 %): max MAE медиана 1,26, максимум 1,60; шаг между опорными кадрами в основном 6–11, до 13. Отказов 119: 111 — сопоставление не монотонно даже при радиусе 96, 8 — прочее; список в manifest.summary.failed. Размеченных кадров у пригодных — 254 498. Разбиение по sha1(ID) среди пригодных: train 914, dev 193, test 174; семь val-видео — отдельный отложенный набор.

## Решение
Обучающие видео приняты: 1 281 пригодный ролик с фиксированным разбиением. Отказавшие 119 исключаются из обучения и оценки (не заменяются другими); повторное выравнивание с бо́льшим радиусом — отдельная инфраструктурная задача при необходимости. Открываются: кэши детекций YOLO26 и полей FlyVis/DIS на train-видео; головы FlyVis (Н2, Н7, Н1-декодер, цель 3) и обучение голов линии B на train с проверкой на dev/test и на val-семёрке.

## Ограничения
Разбиение по хэшу ID — без стратификации по условиям съёмки; при необходимости стратификация оформляется отдельной версией разбиения.

## Критерии приёмки (записаны до прогона)
- ✅ все 1 400 роликов скачаны и проходят CRC32 из каталога архива  
  *data/bdd100k/videos/train_manifest.json: 1400 записей с crc32 (проверка при загрузке) и sha256*
- ✅ частота по контейнеру 29–31 кадр/с, ролик читается, число размеченных кадров = число опорных изображений  
  *runs/train_videos/manifest.json → summary.fps_range = [29.26707661625395, 30.42365182921794]; opened у всех; labelled_frames = reference_images у пригодных*
- ✅ выравнивание по содержимому: max MAE ≤ 2,5, шаги монотонны и ≤ 12 — доля пригодных роликов и список отказов записаны  
  *runs/train_videos/manifest.json → summary.alignment_ok = 1281, summary.failed (119)*
- ✅ разбиение train/dev/test зафиксировано в манифесте до любого обучения; val-семёрка вне обучения  
  *runs/train_videos/manifest.json → split_rule, videos.*.split; split_counts*
