# 🔴 Г2 (проба): дообучение YOLO26 с целью уверенности без умножения на IoU — возвращает ли это ночные и новорождённые объекты

**Направление:** [[03 Направления/Уверенность детектора|Уверенность детектора]] · **Исход:** отрицательный · `conf_target_probe_v1`

Следствие Г0а ([[threshold_mechanism_iou_v1]]): при равном IoU ночной разрыв потерь на пороге сокращается на ~40 %. Проверка вмешательством: training/conf_target.py убирает множитель IoU из цели уверенности TaskAlignedAssigner (пик цели = 1). Два плеча, меняется одно условие: ctl (штатная цель) и iou_free; оба — дообучение от weights/baseline_seed42/best.pt на full_step5, 2 эпохи при 640, SGD lr0 0,002 без разогрева, мозаика включена в обоих плечах (при 2 эпохах close_mosaic=10 не срабатывает); сиды 42/123/2024. Оценка — кэш val при 960, conf 0,01, полнота при равном общем FP (бюджет — FP исходного YOLO26 на пороге 0,25 на тех же 107 видео). Побочный эффект патча: веса потерь рамки в v8DetectionLoss тоже идут от target_scores.

## Вопрос
Поднимает ли цель без IoU полноту ночью и при первом появлении объекта при том же числе ложных срабатываний, и какой ценой для mAP?

## Гипотеза
Объекты с неточной рамкой перестают учиться на низкий балл: ночная полнота и полнота на возрасте 0 при равном FP растут больше, чем дневная; mAP почти не падает.

## Ожидалось (до прогона)
iou_free − ctl (среднее по 3 сидам): ночная полнота при равном FP +0,5…+1,5 пп; возраст 0 больше; mAP50 (Ultralytics, val step5, 640) от −0,005 до 0. Если ночная разность < разброса сидов ctl — направление закрывается.

## Что сделано
scripts/conf_target_probe.py: 6 дообучений (2 плеча × сиды 42/123/2024), по 2 эпохи (~40 мин) + кэш val 960 (200 видео); патч сработал (14 596 вызовов назначателя за прогон iou_free). Оценка scripts/eval_conf_probe.py → runs/conf_probe/eval.json: бюджет FP 30945 (исходный YOLO26 на пороге 0,25, 107 видео). Обнаружено: сид в Ultralytics 8.4.84 при старте от одних весов ничего не меняет — порядок данных и аугментации задаются константой (ultralytics/data/build.py:350, generator.manual_seed(6148914691236517205 + RANK)); три сида каждого плеча совпали по всем метрикам, то есть получено одно эффективное повторение на плечо.

## Получено
Полнота при равном FP, ctl / iou_free: ночь 0.6541 / 0.6526 (-0,15 пп [-0,32; +0,03]); ночь, возраст 0 0.3892 / 0.3841 (-0,51 пп [-1,06; +0,06]); день 0.7129 / 0.7125 (-0,04 пп [-0,23; +0,14]); все, возраст 0 -0,48 пп [-0,91; -0,05]. mAP50 (val step5, 640) 0.42859 / 0.42802 (-0.0006). Порог при равном FP: ctl 0.2518, iou_free 0.3345. Исходный YOLO26 для справки: ночь 0.6500, день 0.7117, возраст 0 ночью 0.3884.

## Интерпретация
Цель без IoU поднимает баллы в целом (тот же бюджет FP достигается на пороге 0,33 вместо 0,25), но не улучшает порядок «настоящий объект / ложный кандидат»: ночная полнота и полнота на первом появлении при равном FP не растут, а скорее падают (возраст 0 по всем видео −0,48 пп, ДИ < 0). Значит, связь «неточная рамка ↔ низкий балл», найденная в Г0а, — в основном общая причина (трудный объект), а не след умножения цели на IoU. mAP почти не изменилась.

## Решение
Критерии 1 и 2 не выполнены (знак отрицательный), 3 и 4 выполнены → completed_negative: направление «правка цели уверенности» закрыто, полное обучение не нужно.

## Нельзя заявлять
Разброс между сидами не измерен (сид Ultralytics при старте от одних весов ничего не меняет); вывод держится на одном повторении на плечо и ДИ по видео. Проверено только снятие IoU целиком, не мягкие варианты (пол, степень) и только 2 эпохи дообучения.

## Условия
- **baseline:** ctl — то же дообучение со штатной целью (парный контроль)
- **variant:** iou_free — цель уверенности без умножения на IoU
- **dataset:** train full_step5 (56 349 кадров); оценка — runs/conf_probe_cache/<плечо_сид>/val (200 видео val, 960), разметка box_track_20/val
- **split:** val: 107 видео с атрибутом день/ночь (ночь 71, день 36)

## Критерии приёмки (записаны до прогона)
- ❌ ночь: полнота при равном общем FP, iou_free − ctl (среднее по сидам) ≥ +1,0 пп, ДИ по видео > 0 и разность больше размаха ctl между сидами  
  *runs/conf_probe/eval.json → diff.night = -0.0015, ci95.night = [-0.003193890492482937, 0.00030235873139404783]; размах ctl между сидами = 0 — артефакт одинаковых прогонов, сравнение с ним невозможно*
- ❌ возраст 0: полнота при равном FP, iou_free − ctl ≥ +1,5 пп, ДИ > 0  
  *runs/conf_probe/eval.json → diff.night_age0 = -0.0051, ci95.night_age0 = [-0.010588780648907404, 0.000624205917514896]*
- ✅ день: полнота при равном FP не хуже ctl более чем на 0,5 пп  
  *runs/conf_probe/eval.json → diff.day = -0.0004, ci95.day = [-0.002291833272512267, 0.0013810705005165287]*
- ✅ mAP50 (Ultralytics, val step5): iou_free не ниже ctl более чем на 0,005  
  *runs/conf_probe/eval.json → diff.map50 = -0.0006*

## Доказательства
- основание: ~40 % ночного разрыва при выравнивании по IoU: `runs/gate_g0a/summary.json` · point.iou_bin.night_vs_day.reduction
- полнота при равном FP и mAP50 по плечам: `runs/conf_probe/eval.json` · recall, diff, ci95, map50
