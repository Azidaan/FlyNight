# 🟢 Д1: лестница оракулов детекции — потолок HOTA для каждой стороны обнаружения (порог, ложные, рамки, невидимые, рождение)

**Направление:** [[03 Направления/Уверенность детектора|Уверенность детектора]] · **Исход:** положительный · `detection_oracle_ladder_v1`

Из research_fundamental_problems (F9): до постройки модуля измерить его потолок. Оракулы по эталону правят детекции только на размеченных кадрах (5 Гц): thr — поднять лучшего кандидата объекта ступени ПОРОГ до 0,9; thr_ctl — столько же случайных несопоставленных слабых кандидатов (контроль); thr_young — thr только для возраста 0–1; fp — удалить несопоставленные ≥ 0,1; box — эталонные рамки сопоставленным; miss — добавить эталон для объектов без кандидата; all — всё. Трекер — стенд ([[bench_freeze_v1]]) на 30 Гц; HOTA TrackEval; test 35 и val7; ночь/день.

## Вопрос
Сколько HOTA максимум даёт исправление каждой стороны обнаружения — какая из них стоит модуля?

## Гипотеза
Наибольший потолок — у возврата потерь на пороге и у ложных срабатываний; рождение (thr_young) — малая доля; случайный контроль не даёт прироста.

## Ожидалось (до прогона)
Правило: строить модуль под сторону, только если её потолок ≥ 1 HOTA на test (ДИ > 0) и он больше контроля thr_ctl.

## Что сделано
scripts/oracle_detection_ladder.py: 8 вариантов × 42 видео (test 35 + val7), 10 процессов, ~15 мин; стенд без каскада и сшивки; TrackEval по наборам и по видео; бутстреп по видео 5000.

## Получено
test HOTA (по набору), базa 58.469 (DetA 58.214, AssA 59.682); box 63.89 (Δ по видео +5.68 [+5.16; +6.25]); fp 61.30 (Δ по видео +2.61 [+1.95; +3.42]); thr 60.42 (Δ по видео +2.02 [+1.62; +2.40]); miss 59.01 (Δ по видео +0.56 [+0.35; +0.78]); thr_young 58.63 (Δ по видео +0.21 [+0.14; +0.29]); thr_ctl 57.25 (Δ по видео -1.17 [-1.44; -0.89]); all 72.21 (Δ по видео +13.95 [+12.71; +15.18]). Ночь test: box +6.12, thr +2.23, fp +2.85. val7: база 54.57, box 59.41, fp 55.92, thr 56.79, miss 55.32, thr_young 54.56.

## Интерпретация
Крупнейший рычаг — точность рамок (+5,4 HOTA на test, больше возврата потерь на пороге и снятия FP вместе): HOTA усредняется по порогам IoU 0,05–0,95, неточная рамка теряет и в DetA, и в AssA (AssA 59,68 → 62,71 при одних только рамках). Ложные срабатывания (+2,8) весят больше потерь на пороге (+2,0); объекты, которых детектор не видел, — +0,5; рождение (возраст 0–1) — лишь +0,17, хотя на него был построен рельс В. Случайный подъём слабых кандидатов вредит (−1,2) — контроль работает.

## Решение
Оба критерия выполнены (база = стенд 58,469; контроль < 0). По правилу «строить, только если потолок ≥ 1 HOTA»: проходят точность рамок, ложные срабатывания, потери на пороге; не проходят невидимые объекты и рождение. Следующий шаг — дешёвые проверки рычага «рамки» (сглаживание выхода трекера, уточнение рамки по нескольким кадрам) до любых модулей.

## Нельзя заявлять
Оракулы правят только размеченные кадры (5 Гц) и пользуются эталоном — это потолки, а не достижимые приросты; оракул рамок ставит эталон, реальное уточнение даст долю этого.
