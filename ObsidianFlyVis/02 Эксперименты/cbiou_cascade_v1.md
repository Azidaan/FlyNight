# 🟢 Каскад буферов IoU (C-BIoU) и буфер второй ассоциации на стенде XYWHByteTrack — HOTA на обучающих видео

↑ [[02 Эксперименты/Направления/Собственная архитектура трекера|Собственная архитектура трекера]] · **Исход:** положительный · `cbiou_cascade_v1`

Заимствовано: C-BIoU (Yang et al., WACV 2023) — после первой ассоциации с малым буфером оставшиеся треки и детекции сопоставляются ещё раз с большим буфером; дополнительно — буфер во второй ассоциации (детекции низкой уверенности). tracking/motion_source_bytetrack.py (cascade_buffer, second_buffer; при нулях байт-в-байт равен стенду — тест). Конфигурации заданы заранее файлом runs/e2e_motion_source/configs_cascade.json; выбор — на dev (35), отчёт — test (35) и val7.

## Вопрос
Добавляет ли каскад буферов что-то сверх одиночного буфера 0,5?

## Гипотеза
Малый буфер сначала сохраняет точные пары, большой затем подбирает быстрые объекты — меньше переключений ID.

## Что сделано
Прогон 30.09.2026 09:0x упал на имени конфигурации с символом «>» (недопустим в путях Windows); переименовано, перезапуск 14:00–14:15. Карточка до прогона не записывалась — поле «ожидалось» пустое; выбор варианта по dev задан протоколом скрипта заранее.

## Получено
dev / test / val7 HOTA: стенд 61.336 / 58.469 / 54.573; буфер 0,5 61.766 / 59.121 / 54.680; каскад 0,3→0,6 61.810 / 59.106 / 55.076 (IDF1 test 68.350 против 66.965 у стенда; IDSw test 2221 / 2034 / 1968). Бутстреп по видео: каскад − стенд на test ΔHOTA +0.745 ДИ [+0.220; +1.487], ΔIDF1 ДИ [+0.699; +2.918]; каскад − буфер 0,5: test ΔHOTA ДИ [-0.163; +0.141], ΔIDSw на ролик -1.89 ДИ [-3.00; -0.80]; val7 ΔHOTA +0.261 ДИ [+0.059; +0.494]. Буфер второй ассоциации 0,3 и 0,5: результаты в точности равны буферу 0,5.

## Интерпретация
Каскад сохраняет прирост одиночного буфера по HOTA/IDF1 к стенду и значимо снижает переключения ID сверх него (test: 23 ролика лучше, 7 хуже), на val7 даёт +0,40 HOTA. Буфер второй ассоциации ничего не меняет по устройству стенда: при fuse_score=True сходство второй ассоциации умножается на уверенность детекции 0,1–0,25, расстояние всегда больше порога 0,5 — вторая ассоциация стенда фактически не сопоставляет ничего (проверено: вызывается на каждом кадре с непустым набором детекций).

## Решение
Каскад 0,3→0,6 — лучшая конфигурация ассоциации линии B на обучающих видео по совокупности (HOTA как у буфера, IDSw ниже, val7 выше). Отдельная открытая задача: вторая ассоциация стенда мертва при fuse_score — проверить её без умножения на уверенность (XYWHIoUSecondByteTrack) на обучающих видео.

## Ограничения
Критерии до прогона не записаны; один сид; буфер второй ассоциации проверить нельзя, пока в стенде fuse_score=True (см. интерпретацию).

## Нельзя заявлять
Новизну: каскад — заимствованный метод C-BIoU.

## Условия
- **baseline:** стенд XYWHByteTrack; буфер 0,5
- **variant:** каскад 0,3 → 0,6 (лучший на dev: HOTA 61,810)
- **dataset:** runs/train_cache (dev 35, test 35) + runs/video_rate (val7)
- **split:** выбор на dev, отчёт test и val7
