# 🔴 Г3: глаз мухи перед детектором — замороженный YOLO26 на кадрах после фоторецептора и накопления (без обучения)

**Направление:** [[03 Направления/FlyVis|FlyVis]] · **Исход:** отрицательный · `fly_eye_frontend_v1`

Правило 6.14: новый сигнал должен входить до детектора. Варианты входа замороженного YOLO26 (960, conf 0,01): raw; tavg3/tavg5 — среднее 3/5 прошлых кадров, совмещённых гомографией фона по DIS (небиологический контроль накопления); pr — фоторецептор tracking/retina.py (закон Вебера, локальная адаптация τ 0,3 с) по яркости с сохранением цвета; pr_int — то же с временной интеграцией фоторецептора τ 0,1 с; pr_tavg3 — фоторецептор поверх совмещённого среднего 3 кадров. Наборы: val7 и dev+test 70 видео (только размеченные кадры вне full_step5_train). Полнота при равном FP (бюджет — raw на пороге 0,25 внутри набора), слепота, возраст 0; ночь/день по атрибутам. Сверка: raw воспроизводит кэш raw_video.npz (медиана |Δconf| 0,0008 на пробном видео).

## Вопрос
Даёт ли накопление света и адаптация фоторецептора мухи детектору свидетельство, которого нет в одном кадре, — прежде всего ночью?

## Гипотеза
Ночью накопление снижает шум и поднимает уверенность недооценённых объектов; вариант мухи не хуже небиологического накопления.

## Ожидалось (до прогона)
Ночью (dev+test) хотя бы один вариант даёт полноту при равном FP ≥ +1,0 пп к raw, ДИ > 0; для вклада мухи — вариант pr* лучше лучшего tavg, ДИ > 0. Днём ожидается вред (размытие, сдвиг входа). Если ноль/вред из-за чужого для детектора входа — следующий шаг дообучение 2 эпохи на лучшем варианте (это не успех гейта).

## Что сделано
scripts/gate_fly_eye_frontend.py: 77 видео (val7 + dev+test 70), 6 процессов, ~2,5 ч; один процесс завис на CUDA при параллельной работе (видео b1cac6a7, кадр 100/106) — снят, видео пересчитано одним процессом за 290 с. Оценка — runs/gate_g3/summary.json; бюджет FP dev+test 22235, val7 2364; ночных видео dev+test 29, val7 2.

## Получено
Полнота при равном FP, вариант − raw. dev+test ночь (raw 0.7552): tavg3 -1,97 пп [-2,79; -1,22], tavg5 -5,69 пп [-7,06; -4,44], pr -9,45 пп [-11,54; -7,68], pr_int -15,13 пп [-17,20; -13,15], pr_tavg3 -8,31 пп [-10,32; -6,64]. dev+test день: tavg3 -2,06 пп [-3,64; -1,07], pr -2,88 пп [-3,49; -2,30]. val7 все: tavg3 -1,54 пп [-2,38; -0,79], pr -3,21 пп [-5,44; -2,21]. Слепота ночью dev+test: raw 0.1047, tavg3 0.1222, pr 0.1585, pr_int 0.2167.

## Интерпретация
Замороженному YOLO26 любой обработанный вход вреден, и вред растёт со степенью изменения кадра; растёт и слепота (объект не находится даже при conf 0,01) — признак сдвига распределения входа, а не только шума. Накопление по гомографии фона размывает именно движущиеся объекты (они движутся не как фон) — чем больше кадров, тем хуже (tavg5 хуже tavg3); интеграция фоторецептора без компенсации (pr_int) — хуже всех. Ночью у BDD100K нет фотонного голода в смысле, который лечит накопление: H.264 уже сглаживает шум во времени.

## Решение
Критерии 1–3 не выполнены (лучший вариант ночью tavg3 −1,97 пп; варианты мухи хуже лучшего tavg) → completed_negative для замороженного детектора. Заранее записанный следующий шаг — дообучение на лучшем варианте — не даёт мухе преимущества: лучший вариант небиологический (tavg3), а мушиные хуже его; решение о дообучении на pr (адаптация без временного размытия) — за автором.

## Нельзя заявлять
Что вход мухи бесполезен для детектора вообще: детектор не дообучался на обработанных кадрах (сдвиг распределения), накопление компенсировалось только по фону, а не по объекту.

## Условия
- **baseline:** raw — сырой кадр, тот же детектор
- **variant:** tavg3, tavg5, pr, pr_int, pr_tavg3
- **dataset:** исходные видео 30 Гц: data/bdd100k/videos/{val,train}; DIS runs/video_rate, runs/train_cache; разметка box_track_20
- **split:** val7; dev+test 70 (кадры вне full_step5_train)
