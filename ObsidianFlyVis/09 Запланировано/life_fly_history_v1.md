# ⚪ А2: удаление ложных жизней по временной истории измерений — одинаковая временная голова без FlyVis и с FlyVis (одна реализация)

↑ [[09 Запланировано/FlyVis — планы|FlyVis]] · **Исход:** запланирован · `life_fly_history_v1`

Решение и границы автора 11.10. Мишень: оракул, удаляющий только полностью ложные жизни с > 5 измерениями глаза, — ночь 57,678 → 58,498 на 97 новых val (runs/newval_long_false_oracle/report.json; потолок при знании разметки). Нынешняя сигнатура — два средних первых и последних 5 измерений; у жизней длиннее пяти измерений середина и порядок теряются. Действие (одно): удалить рамки жизни из выхода после MASA, если временная голова считает её ложной (как в life_filter --v2). Пересчёт сигнатур train 130 + dev 35 тем же трекером (буфер 30) с сохранением по шагам: выход мухи (34 × 19), вход глаза (721), миниатюра 16 × 16, гистограмма (40); история не длиннее 32 шагов (равномерное прореживание). Временная голова (одна, задана до прогона): по каждому признаку — среднее, ст. отклонение, минимум, максимум, наклон по времени, средний модуль приращения + длина жизни и прежние признаки без мухи (751); HistGradientBoosting конфиг 0 (lr 0,1, 15 листьев, 200 итераций, l2 1,0, random_state 0). Без мухи — эти статистики по входу глаза, миниатюре и гистограмме; с мухой — то же плюс статистики выхода мухи; больше отличий нет. Сверка: жизни (track_id, start, end) и выход трекера совпадают с runs/fly_signatures; средние первых / последних 5 шагов из истории совпадают с сохранёнными в пределах fp16.

## Вопрос
Различает ли временная история измерений мухи ложные жизни лучше такой же истории без мухи, с выигрышем HOTA?

## Гипотеза
Порядок и изменение ответов мухи внутри жизни несут сведения о ложности, которых нет в двух средних и в такой же истории обычных признаков.

## Ожидалось (до прогона)
Стоимость: ≈ 6 ч GPU (165 видео × ≈ 2,2 мин при трёх процессах, по [buffer_extend_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fbuffer_extend_v1)), диск ≈ 10 ГБ; головы — процессор. Разрешение автора на GPU — отдельно, до запуска. Обучение на train 130; порог — по правилу life_filter_rule_cv (допустим, если потеря объектов ≤ 1 % и верных рамок ≤ 0,5 %; максимум средней разности HOTA) — выбор на dev 35 по решению автора (оговорка: выбор порога и критерий на одном dev завышают оценку; альтернатива — пороги по 5 частям train вне обучения, решение за автором до запуска). Критерий (dev 35): HOTA с мухой − без мухи по видео > 0, ДИ > 0, при соблюдении пределов потерь. Не выполнен — остановиться без переделки головы и без новых видео. Выполнен — проверить неизменённый вариант на новых, ещё не использованных размеченных видео val (97 новых val не считаются независимыми); доступность: из 96 неиспользованных размеченных val локально 7, остальные — загрузка (≈ 2 ГБ) и подготовка (детекции, сигнатуры, эмбеддинги — часы GPU) по отдельному разрешению.

## Условия
- **baseline:** та же временная голова без мухи
- **variant:** временная голова с мухой
- **dataset:** BDD100K MOT train_cache: train 130 (обучение), dev 35 (порог, критерий); новые неиспользованные val — подтверждение

## Критерии приёмки (записаны до прогона)
- ⏳ Сверка: жизни и выход трекера совпадают с runs/fly_signatures; средние 5 шагов из истории = сохранённые (fp16)
- ⏳ dev 35: HOTA с мухой − без мухи по видео > 0, ДИ > 0, пределы потерь соблюдены
- ⏳ Новые неиспользованные val: неизменённый вариант, тот же критерий (только при выполнении критерия dev)

## Доказательства
- мишень: оракул ложных жизней > 5 измерений: `runs/newval_long_false_oracle/report.json` · oracle.night
- совпадение средних — только при ≤ 5 измерениях: `runs/signature_overlap_reconcile/count_check.json` · *.same_gt5
