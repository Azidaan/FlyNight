# 🔵 Запас идеального удаления полностью ложных жизней на 97 новых val-видео (диагностика на сохранённых выходах)

↑ [[09 Запланировано/FlyVis — планы|FlyVis]] · **Исход:** идёт · `life_only_oracle_newval_v1`

Разбор автора 10.10 после [life_filter_newval_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Flife_filter_newval_v1): прежде чем решать про историю мухи на GPU, проверить запас самого действия на новых данных. Из сохранённого выхода после MASA (runs/newval_eval/stitched) удаляются все полностью ложные жизни по меткам (runs/newval_eval/lives.pkl; правило оракула — IoU 0,5, венгерское по классу, crowd — игнор); номера и связи не меняются; HOTA по группам ночь / день / все. Дополнительно (без порога) — AP ранжирования полностью ложных жизней сохранёнными прогнозами голов с мухой и без (runs/newval_eval/probs.npz). Без GPU. Эти видео — для объяснения ошибки; подбирать по ним порог и объявлять улучшение нельзя. scripts/newval_oracle.py.

## Вопрос
Есть ли на новых видео запас у действия «удалить полностью ложные жизни», и различают ли ложные жизни головы с мухой и без?

## Гипотеза
Запас действия на новых видео сопоставим с dev (+2,26 HOTA), а провал фильтра — в различении.

## Ожидалось (до прогона)
Запас «заметен» (записано до расчёта), если ночью оракул − без фильтра по видео > 0 с ДИ > 0 и общий прирост ≥ +0,3 HOTA (как в life_filter_oracle). Если запас мал — новый проход мухи не оправдан. AP голов — описательно.

## Условия
- **baseline:** выход после MASA без фильтра
- **variant:** оракул удаления полностью ложных жизней
- **dataset:** BDD100K MOT val: 69 ночных + 28 дневных новых видео (runs/newval_eval)

## Критерии приёмки (записаны до прогона)
- ⏳ ночь: оракул − без фильтра по видео > 0, ДИ > 0, и общий прирост ≥ +0,3 HOTA
