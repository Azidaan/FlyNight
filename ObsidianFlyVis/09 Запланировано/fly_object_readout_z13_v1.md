# ⚪ З13: объектное считывание FlyVis — поправка центра потерянного трека по образцу цели

↑ [[09 Запланировано/FlyVis — планы|FlyVis]] · **Исход:** запланирован · `fly_object_readout_z13_v1`

## Вопрос
Улучшает ли стенд (выход после MASA) муха, обученная находить заданный объект по образцу в области глаза потерянного трека или отказываться, — и даёт ли это больше, чем та же схема без FlyVis и с замороженной мухой?

## Гипотеза
Обучение ядра FlyVis и считывателя на объектную задачу (найти образец или отказаться) даёт поправку центра потерянного трека, возвращающую его к своему объекту в пределах буфера; ориентир этого действия — оракул только для потерянных треков.

## Ожидалось (до прогона)
ДЕЙСТВИЕ (одно, не подменяется по ходу опыта): перед первым сопоставлением каждого кадра у каждого потерянного трека в пределах штатного буфера (30 кадров; ведомые треки не трогаются) считыватель выдаёт распределение по 721 колонке области глаза и вариант «отказ». Если вероятность «найден» ≥ τ — центр прогноза Калмана (mean[0:2]) заменяется оценкой центра: колонка-максимум и её 6 соседей (взвешенное среднее только по этим 7 колонкам, не по всей карте — два максимума не усредняются), перевод в пиксели кадра; скорость, ширина и высота не меняются (как у оракула). При отказе — штатный прогноз. Выбор готовой детекции вместо поправки центра — другое действие, в этом опыте не применяется. УСТРОЙСТВО. Образец цели — последний надёжный: при потере трека глаз рождается fade-in (1 с) на вырезке crop_box вокруг рамки трека за 4 кадра до потери и проходит 4 последних ведомых кадра (вырезки вокруг рамок трека); активность 34 выходных типов по колонкам на последнем ведомом кадре — образец; во время потери образец не обновляется. Область поиска — тот же глаз продолжает работать на каждом кадре потери на вырезке crop_box вокруг прогноза Калмана (состояние переносится; эфферентная поправка не применяется — считыватель учится в этих же условиях). Считыватель (одинаковый во всех вариантах, обучается во всех): стандартизация признаков по train, линейное вложение признаков колонки в 16 чисел; вектор образца — среднее вложений колонок внутри рамки трека в вырезке образца; балл колонки = κ·cos(образец, вложение колонки) + β, «отказ» — обучаемый балл; softmax по 722 вариантам. ≈ 34·16 + 16 + 3 = 563 параметра. Модель мухи — flow/0000/000 (глаз стенда). ВАРИАНТЫ: (A) стенд без действия — dev после MASA 61,655 (runs/o2_masa_residual/report.json, pooled.stand_masa|all); (B) без FlyVis — то же действие, тот же считыватель, вместо мухи малая временная сеть на том же входе глаза (изображение после сетчатки на шестиугольной решётке, те же вырезки и кадры): по колонке и 6 соседям — яркость текущего кадра, разность с прошлым кадром, разность прошлого с позапрошлым, среднее за 4 кадра (28 чисел) → 24 признака (tanh), ≈ 696 параметров против 734 свободных параметров мухи; (C) замороженная муха (штатные параметры) + обучаемый считыватель; (D) обучаемая муха: 734 свободных параметра (nodes_bias, nodes_time_const, edges_syn_strength; знаки и коннектом закреплены) + считыватель, шаги и притяжение к штатному решению — как в К1 v2 (scripts/fly_k1_v2.py: λ = 1, lr 1e-4 / 5e-6 / 5e-6). ДАННЫЕ И НАСТРОЙКИ (выбор только на train). Примеры — эпизоды потери трекера стенда на train 130 (без вмешательства), метки — только на размеченных кадрах (5 к/с, не интерполированных): положительный — центр своего объекта разметки внутри области глаза (цель — ближайшая колонка); отрицательный («отказ») — свой объект вне области, отсутствует в разметке кадра или объект трека неизвестен (трек не сопоставлен с разметкой). Объём (runs/z13_prep/stats.json, counts.train): пар «потерянный трек × размеченный кадр» 136513, объект известен 32563, положительных 17537, отрицательных при известном объекте 15026, объект неизвестен 103950 (в обучение — случайные 15 000, сид 0). Обучение — на 104 видео train, τ — на остальных 26 видео train (деление по видео, сид 0), модель после выбора τ не переобучается. Правило τ (одинаковое для всех вариантов): наименьший порог, при котором среди вмешательств доля попаданий оценки центра внутрь рамки своего объекта ≥ 0,9 (вмешательство на отрицательном примере — ошибка). Оптимизация: Adam, 4000 итераций, пакет 16 эпизодов, потеря — перекрёстная энтропия по 722 вариантам, считыватель lr 3e-3, один сид (0) на вариант; без подбора по dev. Dev 35 — только проверка зафиксированного решения; отложенные 75 видео — однократное подтверждение, без настройки, отдельным разрешением. ТЕХНИЧЕСКИЕ ПРОВЕРКИ (работоспособность, не качество; ≤ 1 ч GPU): Т1 — данные и координаты: перевод центра разметки в колонку и обратно, ошибка < шага колонки; 20 примеров глазами. Т2 — обучение доходит до ядра и использует образец: 300 итераций на 500 эпизодах train — потеря падает, свободные параметры мухи сдвигаются (медиана |Δp|/|p| > 0); при перемешивании образцов между эпизодами точность на тех же эпизодах падает. Т3 — последовательная работа без разметки: трекер с считывателем на 2 видео dev — без сбоев, счёт вмешательств и отказов, время на кадр → уточнение бюджета. После Т1–Т3 — основное обучение и измерение; четвёртой диагностики нет (правило 6.16), кроме ошибки в данных или измерении. БЮДЖЕТ (до прогона; один процесс GPU): извлечение примеров ≈ 1–2 ч процессора; Т1–Т3 ≤ 1 ч GPU; обучение B, C, D ≤ 3 ч GPU (ориентир — К1 v2: 2000 итераций по 6 глазов × 32 кадра за 10,5 мин); проверка на dev — по варианту трекер со считывателем + сигнатуры + DINO + MASA + сшивка ≈ 3–4 ч, три варианта ≤ 12 ч GPU (уточняется по Т3; при превышении более чем в 1,5 раза — остановка и вопрос автору). Итого предел ≈ 16 ч GPU. Отложенные 75 видео — отдельное разрешение. ОРИЕНТИР (не прогноз): оракул только для потерянных треков (runs/z13_prep/stats.json, Olost-stand) — без сшивки общий +0,560, по видео +0,650 [+0,418; +0,904], лучше 30/35; после MASA для этого правила не измерялся (O2 — +0,333). ТРИ ВЫВОДА НЕ ЗАМЕНЯЮТ ДРУГ ДРУГА: D − A — польза всей реализации; D − B — добавочная польза мухи в этой схеме; D − C — польза обучения ядра.

## Условия
- **baseline:** стенд + MASA, dev 35: 61,655
- **variant:** B без FlyVis, C замороженная муха, D обучаемая муха — одно действие и один считыватель
- **dataset:** BDD100K MOT: train 130 (обучение 104 / выбор τ 26), dev 35 (проверка), отложенные 75 val (подтверждение, отдельно)

## Критерии приёмки (записаны до прогона)
- ⏳ Т1–Т3 пройдены (условие основного обучения)
- ⏳ Польза реализации: dev 35, HOTA после MASA, D − A: общий прирост ≥ +0,10 (практический минимум) и ДИ средней разности по видео > 0 (бутстрэп 5000)
- ⏳ Добавочная польза мухи: dev 35, HOTA после MASA, D − B: средняя разность по видео > 0 и ДИ > 0
- ⏳ Польза обучения ядра: dev 35, HOTA после MASA, D − C: средняя разность по видео > 0 и ДИ > 0
