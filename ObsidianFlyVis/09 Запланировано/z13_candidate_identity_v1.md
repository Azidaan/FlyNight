# ⚪ З13: покадровое сопоставление кандидатов без будущих данных

↑ [[09 Запланировано/FlyVis — планы|FlyVis]] · **Исход:** запланирован · `z13_candidate_identity_v1`

Зафиксирована одна версия сопоставления кандидатов, исход не получен.

## Вопрос
Does causal propagation of candidate identities improve the centered FlyVis readout, beyond geometric matching and the same node on R1?

## Гипотеза
Сохранение идентичности отдельных пиков может использовать часть измеренного запаса; перенос принципа KeepTrack требует проверки.

## Ожидалось (до прогона)
Одна фиксированная версия по текущим и прошлым кадрам, C/D/R1 и геометрические контроли; параметры только по fit20, проверка на всех train26, CPU до1800с.

## Нельзя заявлять
Нет HOTA и безопасного причинного правила вмешательства; верхняя доля по всей выборке — диагностика. Это не полная реализация KeepTrack и не доказательство анатомии FlyVis.

## Критерии приёмки (записаны до прогона)
- ⏳ Воспроизведение прежнего top1, хеши и одинаковые строки всех вариантов подтверждены.
- ⏳ C сопоставление−C top1: прирост>=2п.п. и нижняя95%повидеоДИ>0.
- ⏳ C сопоставление лучше C геометрии и R1 сопоставления: обе нижние95%повидеоДИ>0.
