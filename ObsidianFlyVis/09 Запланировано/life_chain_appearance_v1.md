# ⚪ Последняя дешёвая проверка ветки удаления жизней: связь с цепочкой и внешность MASA поверх соседства — H1 / B1 / B2 (+ муха), данные разработки

↑ [[09 Запланировано/FlyVis — планы|FlyVis]] · **Исход:** запланирован · `life_chain_appearance_v1`

Решение автора 10.10: вариант (б) — одна дешёвая, заранее ограниченная проверка поверх нынешнего лучшего контроля, не как подтверждение FlyVis и не ради улучшения носителя. Варианты (одинаковый бустинг, конфигурация 0): H1 — нынешние признаки + соседство (life_context_neighbors_v1), без мухи; B1 — H1 + связь с цепочкой и внешность MASA; B2 — B1 + муха (сигнатуры начала и конца). Признаки цепочки (из выхода сшивки «база + MASA», порог 0,6; для train — выход перекрёстной сшивки, голова пары с другой половины; цепочка жизни — номер её рамок в выходе): число жизней в цепочке, число рамок цепочки (log), длительность цепочки, доля рамок жизни в цепочке, признак одиночной цепочки, положение жизни (первая/внутренняя/последняя), средняя уверенность цепочки. Признаки внешности (MASA-R50, runs/masa_embeddings — эмбеддинги начала и конца каждой записи): косинус начала жизни с концом предыдущей жизни цепочки и конца жизни с началом следующей (+ признаки наличия); косинус с предшественником и преемником из соседства (а). Всё наблюдаемо, без разметки. Порог — то же правило, что в (а): 5 частей train 130 вне обучения, допустимость при потере объектов ≤ 1 % и верных рамок ≤ 0,5 % в каждой части, наибольшая средняя разность HOTA с ДИ > 0, иначе «ничего не удалять»; порог каждого варианта выбирается до просмотра dev. dev 35 — проверка; новые 97 видео не используются. scripts/life_chain_appearance.py.

## Вопрос
Добавляет ли муха информацию для удаления ложных жизней сверх соседства, связи с цепочкой и внешности MASA?

## Гипотеза
Сигнатура мухи несёт сведения о ложности короткой жизни, которых нет в соседстве, цепочке и внешности.

## Ожидалось (до прогона)
Основной критерий (вклад мухи, dev 35): AP B2 − B1 > 0, ДИ по видео > 0, И HOTA B2 − B1 > 0, ДИ > 0. Описательно: B1 − H1 (AP, HOTA), ночь отдельно. Остановка: если B2 не улучшает B1 по обоим — опыты по удалению жизней с нынешней сигнатурой мухи прекращаются; меняется представление сигнала или действие. Если улучшает — повод планировать проверку на ещё не просмотренных видео с отдельным согласованием затрат.

## Условия
- **baseline:** B1 (соседство + цепочка + внешность, без мухи)
- **variant:** B2 (B1 + муха)
- **dataset:** BDD100K MOT train_cache: train 130 (обучение, порог по 5 частям) / dev 35 (проверка)

## Критерии приёмки (записаны до прогона)
- ⏳ dev: AP B2 − B1 > 0, ДИ по видео > 0
- ⏳ dev: HOTA B2 − B1 > 0, ДИ по видео > 0
