# ⚪ Авторская версия FlyVis: фовеальный глаз с учётом собственного перемещения (эфферентная копия) и откалиброванным считыванием движения объекта

↑ [[09 Запланировано/FlyVis — планы|FlyVis]] · **Исход:** запланирован · `fly_efference_eye_v1`

Решение автора 12.10 — следующий большой этап: одна версия FlyVis, надёжнее оценивающая движение объекта при перемещении самого глаза. Основание: Синтетическая проверка (runs/fly_eye_coord_check/report.json, scripts/fly_eye_coord_check.py; кадр BDD, рамка 120 px, 2 px/кадр, 8 направлений): (а) объект движется, вырезка неподвижна — средний косинус сигнала с истиной +0.92, |сигнал| / сдвиг 0.18; (б) вырезка движется, сцена неподвижна — косинус -0.92, |сигнал| / сдвиг 0.18. Вертикальная составляющая сигнала ≈ втрое сильнее горизонтальной (0,45–0,53 против 0,15–0,18 на 2 px). Изменение затрагивает путь мухи — вход, состояние, считывание. Биологическая опора: у дрозофилы сигналы двигательной системы подавляют ожидаемый зрительный отклик на собственный поворот (эфферентная копия; Kim, Fitzgerald, Maimon, 2015); перенос на программный глаз — инженерная гипотеза. Архитектура (одна реализация): 1) вход — стабилизация по известной геометрии вырезки: на каждом шаге стимул строится из прошлого и текущего кадра, отрисованных в одной (текущей) вырезке, поэтому перемещение и изменение размера вырезки не создают видимого движения; 2) состояние — глаз сохраняется при потере трека (как в [fly_persistent_eye_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_persistent_eye_v1)), само сохранение преимуществом не объявляется; 3) считывание — остаточный декодированный поток внутри рамки с калибровкой 2 × 2 (масштаб по осям и перекрёстные члены) по синтетическим известным сдвигам на кадрах train, без разметки и dev; выход — смещение объекта за кадр в px кадра. Отличие от проверенного: [fly_persistent_eye_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_persistent_eye_v1) — без стабилизации и с одним общим g; К1 (fly_finetune_k1_core_v1) — обучение ядра на поле DIS по колонкам; обучение 734 параметров сейчас не ставится. Сильнейшее возражение: корректная геометрия может убрать ошибку применения, но сигнал мухи может остаться слишком слабым (|сигнал| / сдвиг ≈ 0,18); одна геометрия — не научный результат.

## Вопрос
Оценивает ли версия FlyVis со стабилизацией вырезки и откалиброванным считыванием движение объекта лучше действующей, и даёт ли тот же модуль пользу стенду?

## Гипотеза
Учёт собственного перемещения глаза и калибровка по осям уменьшают накопленную ошибку положения объекта при потере трека и делают поправку полезной трекеру.

## Ожидалось (до прогона)
Две ступени, бюджет до запуска: реализация ≤ 1 дня, ступень 1 ≤ 3 ч GPU, ступень 2 ≤ 6 ч GPU; одна реализация; после результата — подтверждение на независимых данных или остановка именно этой реализации. Ступень 1 (функция): накопленная ошибка положения центра рамки при последовательном прогнозе от последнего наблюдения через периоды потери, только на реально размеченных кадрах (интерполированное положение — не разметка); видео dev 35. Сравнение: действующий глаз (без стабилизации, один g), новая версия, контроль «та же геометрия и сопоставимое считывание без FlyVis» (классический поток на тех же стабилизированных парах вырезок, та же калибровка), нулевая поправка (только фильтр). Критерий 1: новая версия лучше действующей и лучше контроля без FlyVis по видео, ДИ ниже 0 (ошибка). Ступень 2 (только при критерии 1): тот же зафиксированный модуль на 30 Гц, одинаковые детекции и способ применения поправки (потерянные треки), dev 35, HOTA по видео: новая версия − стенд > 0, ДИ > 0; затем со сшивкой MASA. 5 Гц не используется. Если весь выигрыш даёт контроль без FlyVis — улучшение мухи не доказано. Отрицательный итог — остановка этой реализации без «ещё одной небольшой поправки».

## Условия
- **baseline:** действующий фовеальный глаз (fly_persistent_eye_v1); стенд без сшивки
- **variant:** глаз со стабилизацией вырезки и калибровкой 2 × 2
- **dataset:** BDD100K MOT train_cache: кадры train (калибровка), dev 35 (ступени 1–2)

## Критерии приёмки (записаны до прогона)
- ⏳ Ступень 1: накопленная ошибка положения — новая версия меньше действующей и меньше контроля без FlyVis по видео, ДИ ниже 0
- ⏳ Ступень 2 (при ступени 1): HOTA dev 35 новая версия − стенд по видео > 0, ДИ > 0
