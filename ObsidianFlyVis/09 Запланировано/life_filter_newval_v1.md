# ⚪ Проверка фильтра жизней на новых val-видео (вариант (а)): без фильтра / фильтр без мухи / фильтр с мухой — ночь основная

Видео: runs/newval_protocol/videos.json — 69 ночных (основная проверка) и 35 дневных (дополнительная) из размеченных val BDD100K, кроме val7; детектор их не видел; для подбора не используются. Оценка затрат: ≈ 4 мин GPU на видео (104 видео ≈ 7 ч), загрузка ≈ 1,8 ГБ (scripts/fetch_bdd100k_videos.py).

## Вопрос
Воспроизводится ли на новых ночных видео, незнакомых детектору, польза фильтра жизней и добавка мухи?

## Гипотеза
Фильтр с мухой даёт больше HOTA, чем фильтр без мухи, на новых ночных видео, при ограниченных потерях.

## Ожидалось (до прогона)
Основное (ночь, 69 видео): HOTA «фильтр с мухой − фильтр без мухи» по видео > 0, ДИ > 0 (бутстрэп 5000); при общем пороге 0,7 — тот же знак. Также фильтр с мухой − без фильтра > 0. Потери: объекты ≤ 1 %, верные рамки ≤ 0,5 %. Дополнительно — дневные и все видео. Если на ночных добавка мухи не воспроизведётся или потери выше пределов — эту реализацию удаления жизней остановить и искать другое действие для сигнала мухи (вариант (в)).

## Условия
- **baseline:** фильтр без мухи (порог 0,85; дополнительно 0,7)
- **variant:** фильтр с мухой (порог 0,7)
- **dataset:** BDD100K MOT val: 69 ночных + 35 дневных новых видео (runs/newval_protocol/videos.json)

## Критерии приёмки (записаны до прогона)
- ⏳ ночь: HOTA фильтр с мухой − без мухи по видео > 0, ДИ > 0
- ⏳ ночь: фильтр с мухой − без фильтра > 0; потери объектов ≤ 1 %, верных рамок ≤ 0,5 %
