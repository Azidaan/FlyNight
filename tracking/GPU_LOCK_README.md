# Блокировка GPU

`GpuLock` координирует отмеченные участки работы с единственным GPU проекта в одной сессии Windows. Это соответствует правилу исполнения из раздела 9.2 `AGENTS.md`: один GPU-процесс либо общая блокировка. Блокировка не резервирует память видеокарты и не защищает код, который её не использует.

Имена `flyvis_fovea_gpu`, `FlyVis_z13_observed_memory_single_gpu` и `Local\DissertationSingleGpu` теперь разрешаются в один объект Windows `Local\DissertationSingleGpu`. Создаётся и захватывается ровно один мьютекс; последовательного захвата прежних имён нет. Поле `name` сохраняет запрошенное имя, `effective_name` показывает имя объекта Windows. Другие имена остаются независимыми, регистр учитывается. `None`, пустая строка и отсутствие `FOVEA_GPU_LOCK` по-прежнему отключают блокировку. На других платформах прежний режим без блокировки сохранён.

Для применения общего имени уже запущенные процессы со старым кодом должны штатно завершиться либо быть перезапущены владельцем запуска. Простое обновление файла не меняет их импортированный модуль и уже открытые мьютексы. Смешанная работа старых и новых процессов не обеспечивает взаимного исключения между прежними разными именами. Обновление кода само не останавливает и не перезапускает процессы. Пространство `Local` ограничено текущей сессией Windows; глобальная координация разных сессий не заявляется.

Один поток может повторно входить в блокировку, в том числе через разные экземпляры и разные известные имена. Каждый успешный вход требует одного выхода. Это сохраняет схему внешней блокировки задания и внутренней повторно используемой блокировки EyeBank. Выход из `with` освобождает владение, но оставляет дескриптор для следующего кадра. После окончания использования свободный экземпляр можно закрыть через `close`; свободные удалённые объекты закрываются автоматически. Закрытие занятого экземпляра либо экземпляра с ожидающими потоками запрещено. Освобождать блокировку должен тот же поток, который её получил.

Не следует держать GPU-блокировку в родителе во время ожидания дочернего задания, которому она тоже нужна: родитель и ребёнок будут ждать друг друга. Проверенные имеющиеся диспетчеры запускают детей вне защищённых участков. Эта проверка не является доказательством для будущих динамических вызовов. Разные пользовательские имена сохраняются для явно отдельных задач; они не дают общей защиты единственного GPU.

Отказ создания, захвата, освобождения или закрытия объекта Windows сообщает исключение. Защищённый участок не выполняется после отказа создания или захвата. Код `WAIT_ABANDONED` означает получение владения после завершения прежнего владельца и сохраняет прежнее поведение.

Проверки `tests/test_gpu_lock_lifecycle.py` и `tests/test_gpu_lock_aliases.py` используют подменённый интерфейс Windows либо уникальные случайные имена, включая отдельные дочерние процессы. Рабочие имена в этих проверках не захватываются, Torch не импортируется и обращения к GPU нет.
