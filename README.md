# FlyNight

Исследовательский проект многообъектного трекинга на BDD100K MOT.
Авторская система включает детектор YOLO26, трекеры, модуль FlyVis,
память объектов и экспериментальные способы сопоставления обнаружений.

## 1. Основная рабочая ветка

Продолжать работу в `codex/system-integrity-20261106-e8f674ce`.
В ней объединены исправления системы, исследовательские изменения обоих чатов
и актуальные рабочие исходники. Прежняя `main` сохраняется как история.
Целевой репозиторий публикации: https://github.com/Azidaan/FlyNight.
GitLab временно заморожен по решению автора; отправлять туда изменения нельзя.

Перед работой прочитать [AGENTS.md](AGENTS.md), проверить текущую ветку,
связь с удалённым репозиторием и незакоммиченные изменения.
Не применять принудительную отправку и не переключать ветки поверх чужих правок.

## 2. Исходники и результаты

`tracking/` содержит компоненты трекеров и FlyVis; `scripts/` — запуски,
проверки и генераторы; `tests/` — проверки реализации.
`experiments/project_history.json` хранит каталог опытов,
`dissertation/ЕДИНЫЙ_ПЛАН.md` — хронологию и действующие правила.
`ObsidianFlyVis/` — производное представление записей, обновляемое генератором.

Окружение, набор данных, веса и крупные массивы опытов хранятся локально
в рабочей папке проекта. Клонирование репозитория само по себе не восстанавливает
все эти зависимости. Состав окружения описан в `requirements.txt` и `notes/environment.md`.
Научные результаты читать вместе с исходным протоколом и ограничениями карточки.

## 3. Локальные проверки

Проверки запускать последовательно с контролем свободной памяти всей системы.
Не ограничивать каждый процесс произвольными 2–4 ГиБ.
Служебный запуск текущего аудита, рассчитанный на существующее Windows-окружение:

```powershell
.venv/Scripts/python.exe runs/flyvis_repairs_20261106/unification_20261107/per_file.py tests/test_project_history_cache_transient.py unused
```

Последний аргумент оставлен для совместимости служебного запуска;
отдельная временная папка создаётся контроллером автоматически.
Полный отчёт о локальном объединении и проверках находится в
`runs/flyvis_repairs_20261106/unification_20261107/`.

Штатная команда обработки видео проверена на полном ролике BDD100K
`b1c66a42-6f7d68ca` с пустыми кэшами и оценкой семи трекеров.
Код запуска — `4c3545b96ef5ddbbdbb52d72ffb0a51bcfe52565`.
Для повторной проверки сохранённых файлов из корня проекта выполнить

```powershell
.venv/Scripts/python.exe runs/flyvis_repairs_20261106/unification_20261107/verify_run_fingerprint.py 9f322655eab14129a260aeb69166448d --expected-sha256 cdca519cf13f3262eace922ee751cb8095f0e41b447aeed774e4d8e95f2d5768
```

Веса, датасет, архив исходников запуска и большие кэши хранятся локально.
Паспорт, контрольные суммы и отчёт независимой проверки опубликованы в подкаталоге
`uncapped_checks/9f322655eab14129a260aeb69166448d` отчёта об объединении.
На семи полных видео отдельно воспроизведена работа трекеров по сохранённым
кэшам. Результаты локальных тестов, расхождения при новом вычислении полей
FlyVis и ограничения описаны в журнале Единого плана. Для облачного запуска
GitHub Actions потребуется отдельная настройка.
