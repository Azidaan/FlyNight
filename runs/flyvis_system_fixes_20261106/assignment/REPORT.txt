1. Назначение треков

В WeightedGeometryAssignment ограничение max_assignment_cost применялось после решения задачи Hungarian. Это позволяло недопустимым по цене парам вытеснить допустимую пару. Контрпример с реальными рамками сохранён в before_report.json: матрица стоимости [[0,1; 0,2], [0,2; 0,5]], порог 0,15. До исправления второй кадр получал ID 3 и 4 вместо сохранения допустимого ID 1. После исправления выдаются ID 1 и 3: допустимое сопоставление сохранено, второй объект получает новый идентификатор.

Порог теперь входит в ограничения задачи до оптимизации. Сохраняется цель прежнего алгоритма: сначала максимальное число допустимых пар, затем минимальная сумма стоимости. Цена недопустимой пары ограничена снизу величиной, превышающей возможное изменение суммы допустимых стоимостей. На обычном диапазоне сохраняется прежнее значение 1000000; при больших и отрицательных стоимостях граница увеличивается, а при переполнении промежуточной границы выполняется положительное масштабирование допустимых стоимостей в [-1, 1]. Нечисловая стоимость, помеченная допустимой, отклоняется до оптимизации.

Полный перебор 32125 малых матриц размеров 1x3, 3x1, 2x2, 2x3, 3x2 сравнивает результат с независимым перечислением всех частичных назначений. Проверены полностью запрещённые матрицы, отрицательные стоимости, ограничения цены и несколько возможных решений. Отдельно проверены четыре крайних численных случая через Decimal и 300 обычных случаев с одинаковыми стоимостями: без ограничения цены выбор пар совпадает с прежним solver. Это техническая проверка назначения, не измерение HOTA.

2. Состояние входного фильтра Retina

Воспроизведено нарушение формы: после кадра 16x32 вход 1x32 возвращал массив 16x32 из-за неявного расширения размерности NumPy при смешивании с прежним состоянием адаптации. Воспроизведено загрязнение памяти: один NaN во входе приводил к NaN в ответе следующего чистого кадра. Исходное доказательство — retina_audit_before.json.

Теперь process требует непустой полутоновый кадр HxW и конечные значения. В режимах photoreceptor и lamina изменение размера отклоняется до изменения _adapt и _filtered с указанием вызвать reset() перед новым видео. Режимы none и norm не содержат пространственной памяти и продолжают принимать кадры разных размеров. После отказа следующий чистый кадр побайтно совпадает с отдельным контрольным фильтром, не получавшим повреждённый вход. После reset() новый размер обрабатывается как новый видеопоток. Формулы обработки и значения коэффициентов не изменены.

3. Проверки и сохранность

tests_original_v2.log: исходный модуль назначения проверен теми же регрессионными тестами через неизменный снимок, 10 failed / 8 passed. tests_before.log сохранён отдельно: его дополнительное падение относилось к первоначальному тестовому двойнику, который оставлял конечную стоимость у геометрически запрещённых пар; в уточнённой проверке воспроизведён реальный договор cost(), то есть inf для запрещённых пар. Эти ранние журналы не перезаписаны.

retina_tests_before.log: до исправления 28 failed / 2 passed. tests_final.log: после исправления назначения и Retina, вместе с прежними тестами трекера и геометрии движения, 136 passed. Команда сохранена в manifest.json.

probe_v2_report.json: на 48 конфигурациях Retina, 192 корректных кадрах, типах uint8/float32/float64, двух настройках временного фильтра и двух масштабах пространственного размытия результаты побайтно совпали с исходным модулем. Сброс состояния также совпал. Исходный probe.log сохранил неудачную проверку требования float32: она выявила уже существовавший переход ответа photoreceptor/lamina к float64 со второго кадра. probe_v2 проверяет совпадение типа с исходной реализацией; этот прежний переход типа не исправлялся, чтобы не менять точность последующего resize без отдельной проверки. Описание возвращаемого типа в docstring уточнено: нормализация входа float32, временная адаптация может повысить тип до float64; EyeBank._render приводит его обратно к float32 после resize. Это уточнение описания, а не численного алгоритма.

Исходники до исправлений сохранены как original_flyvis_tracker.py и original_retina.py. manifest.json содержит их контрольные суммы, актуальные суммы четырёх изменённых файлов и суммы доказательств. Проверки выполнены на CPU, без обучения, изменения весов и пересчёта научных результатов. Коммитов агент не создавал.

4. Повторный независимый разбор детекторного кэша

В отдельном motion/cache_review_v2_report.json подтверждены исправления root: путь со скобками читается построителем, изменившийся список исходных кадров отклоняется, прежний кэш сохраняется побайтно, Q-кэш без stride отклоняется. Реальные прежние кэши детектора и Q читаются валидатором. Первая версия проверки сохранена отдельно; исходники root этот агент не редактировал.
