1. Наблюдение и ответственность

После сообщения автора об исчерпании оперативной памяти обнаружена перезагрузка Windows в 00:42:07 MSK 07.11.2026. Четыре проверки журнала и каталога, запущенные агентом одновременно около 00:37 MSK, прерваны. Их прежние пустые журналы и журнал с 27 точками не являются успешными проверками. Параллельный запуск был неудачным решением агента. Записей Resource-Exhaustion с виновным PID не найдено; сохранённого измерения пика перед перезагрузкой нет. Причина именно этого инцидента не доказана.

2. Проверенные ограничения и измерения

Добавлен отдельный запуск через Windows Job Object с ограничением суммарной выделенной памяти и ограничением каждого процесса; дочерние процессы наследуют группу, запуск разрешается только после успешного назначения ограничений. Вывод пишется в файл, а не накапливается вызывающим процессом. Одновременно выполняется только одна проверка. Проба запроса 256 МиБ при лимите 96 МиБ завершилась MemoryError, данные находятся в limit_probe/.

Полный git status при запросе лимита 384 МиБ завершился успешно: измеренный пик группы 208359424 байта; выход 30307383 байта (git_status_probe/result.json). Валидатор рабочего каталога завершился успешно с пиком группы 327790592 байта (validator_bounded/result.json, output.log). Эти результаты не подтверждают гипотезу, что один такой запрос сам исчерпывает всю память компьютера.

Проверка опубликованного представления каталога при лимите 384 МиБ дала 56 успешных тестов и две ошибки MemoryError в сериализации/повторной сборке; измеренный PeakJobMemoryUsed составил 436207616 байт (overlay_tests_bounded/result.json, output.log). Запрошенный предел Job и измеренный пик приводятся раздельно: измеренный пик оказался выше заданных 402653184 байт. Это не полностью успешный прогон. Последующий повтор с лимитом 512 МиБ имеет отдельный каталог overlay_tests_512/ и оценивается только по его фактическому result.json.

3. Подтверждённый риск в коде и граница вывода

GitReader._run использует capture_output=True и обрезает max_bytes после полного захвата вывода; такой срез не ограничивает пиковый расход памяти чтения. build_index также запрашивает статистику всей истории Git. Новый ограниченный запуск защищает проверку средствами Windows, но не объявляется исправлением реализации GitReader. Служебная проверка не загружает нейронную модель. Приписать ей прежнее исчерпание памяти без измерения до перезагрузки нельзя.

Позднейшие прерванные проверки документации этим результатом не подменяются. Штатные обученные веса, конфигурации и ранее сохранённые научные результаты при диагностике памяти не изменялись.
