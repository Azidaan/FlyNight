1. Подтверждённый дефект и исправление

Прежняя Windows-обёртка datamate открывала существующий HDF5-файл в режиме w до проверки возможности сохранить значение. Неподдерживаемый object dtype оставлял прежний файл обрезанным, а новый путь — частично созданным. Две исходные проверки владельца аудита завершились отказом; первичный журнал runs/flyvis_repairs_20261106/hdf5_before.log. Непосредственные снимки перед исправлением и SHA256 находятся в original_flyvis_adapter.py, original_test_flyvis_hdf5_transaction.py и baseline.json.

Теперь массив записывается в отдельный временный файл рядом с целевым. Создание data, flush, включение SWMR и закрытие HDF5 завершаются до os.replace. Ошибка значения, flush, SWMR или публикации сохраняет прежние байты; при новом пути неполный целевой файл не появляется. Временный файл удаляется. Формат единственного массива data, тип и значения сохраняются. Внешние vendor-файлы не изменялись; обёртка по-прежнему обновляет оба импортированных имени _write_h5.

Пустой каталог с именем HDF5 удаляется только после полной успешной подготовки временного файла; при отказе публикации пустой каталог восстанавливается. Непустой каталог не удаляется и не переименовывается. Файловая символическая ссылка разрешается в её целевой файл, чтобы публикация не подменяла саму ссылку. Ссылка на каталог отвергается заранее. Для нескольких жёстких ссылок атомарная подмена одного имени разорвала бы их общую идентичность; это воспроизведено на NTFS в hardlink_before_guard.log. Такой целевой файл теперь явно отвергается до изменения данных.

2. Совместимость с фактическими данными

Directory.__setitem__ вызывает _write_h5 для массивов; H5Reader открывает и закрывает файл на каждом чтении. После исправления проверен реальный Directory: запись, чтение и отказ неподдерживаемого значения с сохранением прежнего файла. В исходниках datamate не найдено создания символических или жёстких ссылок; этого наблюдения недостаточно для вывода о состоянии файлов на диске, поэтому выполнена отдельная проверка.

actual_hdf5_links.json перечисляет 992 фактических HDF5-файла общим размером 2164046975 байтов: 990 в runs/flyvis, по одному в tools/flyvis-runtime/data и tools/flyvis-runtime/flyvis/data. Файлов с st_nlink > 1 и файловых символических ссылок не обнаружено. Для каждого файла дважды рассчитан SHA256 и сопоставлены размер, inode, mtime и число ссылок. Все исходные байты и идентификаторы остались неизменными. Выполнено только чтение, без запуска FlyVis, HDF5 writer или GPU. Проверка относится к этим фактическим корням, а не произвольным будущим путям.

3. Проверки

final_tests.log: 53 passed, 2 skipped in 5.65s. Команда охватывала test_flyvis_hdf5_transaction.py, test_flyvis_adapter.py, test_flyvis_device_contract.py, test_flyvis_checkpoint_strict.py и test_flyvis_connectome_transfer.py. Проверены float32/float64/int64/bool/complex64/byte-string, скаляр и пустой массив; повторная запись и чтение SWMR; отказ записи и публикации при существующем/новом файле; ошибка flush/SWMR; пустой и непустой каталоги; реальный открытый читатель Windows; реальные жёсткие ссылки и оба имени обёртки datamate.

Две нативные проверки создания символической ссылки пропущены из-за WinError 1314: в данном процессе отсутствует привилегия создания таких ссылок. Это ограничение не скрыто. Отдельная проверка с подменой разрешения Path проверила публикацию именно целевого файла с сохранением запрошенного объекта. Полная работа символической ссылки Windows не объявляется проверенной.

Первый расширенный тестовый fixture ошибочно предполагал, что h5py установлен в основной .venv; after.log содержит 16 ошибок импорта и две успешные реальные проверки. Исправлен только fixture: он подключает существующий tools/flyvis-runtime, где расположен h5py. Пакеты и окружение не устанавливались и не изменялись. after_v2.log отражает промежуточное состояние, затем добавлен проверенный отказ для жёстких ссылок. После окончательного набора тестов изменены только две описательные строки документации адаптера; тело writer не менялось.

4. Ограничения

Гарантия относится к отказам записи и публикации обычного целевого файла в одном пишущем процессе. Не заявлены устойчивость к отключению питания, поддержка нескольких конкурирующих писателей или атомарное изменение всех имён жёсткой ссылки. Пустой каталог при отказе публикации восстанавливается как пустой каталог; сохранение его inode и времён не заявляется. Ранее открытый читатель Windows не теряет прежние данные, если замена запрещена операционной системой. Новая атомарная запись не исправляет и не перезаписывает исторические файлы автоматически.
