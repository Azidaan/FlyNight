1. Подтверждённая проблема и граница проверки

Изменение Fly.points_scale с одного множителя на плитку (n,) на отдельные оси (n,2) не вызвало обнаруженной ошибки формы во вторичных потребителях: все они передают scale в общий K.to_px, включая одно деление на scalar gain в fly_axes_probe. Настоящий chunked run_frames с отдельными осями проверен тестом. Это исключение конкретного подозрения, а не доказательство исправности всех вычислений этих опытов.

Подтверждён другой новый риск: после изменения default Fly на resize_v2 старые entrypoints не передавали версию. В частности, fly_k1_v2.py --eval-only читал реально существующий runs/fly_k1_v2/arms.pt без geometry marker, после чего создавал Fly с новой геометрией. Веса и новые преобразования незаметно смешивались. Пробы и кэши также могли дописать результаты нового преобразования в прежние JSON/npz без версии. Исправлены 11 потребителей: восемь первоначально перечисленных и ещё build_fly_lcn_motion, fly_noise_probe, fly_speed_response, которые используют общий make_fly.

2. Что изменено

Новый tracking/flyvis_geometry_protocol.py задаёт общий проверяемый договор. --geometry-version по умолчанию resize_v2; --out выбирает отдельный файл/каталог внутри проекта. Непомеченный существующий результат считается legacy_v1. Несовместимая версия отклоняется до записи и создания модели. Совпадающий протокол может продолжить прежний каталог. Новые каталоги получают geometry_protocol.json, отдельные файлы — <имяфайла>.geometry.json; старые чужие файлы не переписываются при отказе.

Все 11 entrypoints явно передают выбранную версию в Fly либо make_fly. У make_fly она передаётся дальше в Fly. К1 v2 сохраняет geometry_version в каждой обученной ветви и в summary.meta, проверяет весь набор arms до модели при --eval-only, требует явный legacy_v1 для старых весов. Отсутствие весов больше не запускает обучение; частичный набор новых ветвей тоже отвергается заранее. Начало нового обучения поверх arms.pt запрещено; нужен новый --out.

fly_wide_field проверяет версию собственного npz-кэша и численного reference результата. Для нового v2 нужен --reference-results из соответствующего нового fly_scale_probe; старые цифры не подставляются как сопоставимый контроль. Новые wide-field и lcn кэши содержат geometry_version. build_fly_lcn_motion проверяет существующий файл до прежнего пропуска already exists; --out здесь означает другой корень кэшей. В новой записи также помечены обычные JSON-метаданные источника.

Status/log вторичных опытов с новым --out направляются в новый результат, а не в старый каталог К1. В синтетическом К1 перенос status/log не меняет источник списка train/dev: путь к прежнему summary сохраняется до смены K.OUT. Геометрия обучения и проверки synthetic state сравнивается явно.

Shared tracking/flyvis_motion.py и scripts/fly_finetune_k1.py этой правкой не изменялись.

4. Ограничения

Общий helper защищает договор геометрии, а не все возможные параметры научного протокола, выборки и веса. Совпадение geometry_version само по себе не доказывает равенство исходников, seed, данных или качества. Абсолютное усиление движения и HOTA не оценивались. Legacy остаётся явным способом воспроизведения прежних результатов; он не объявляется новым исправленным преобразованием. Метрика качества относительно исходного решения и доля измеренного предела отсутствуют, поэтому проценты улучшения не рассчитываются.
