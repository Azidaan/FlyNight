3. Передача в индекс без включения чужих изменений.

manifest.json закрепляет исходный commit, контрольные суммы, точные пути prepared candidates и исключённые чужие карточки. Эти копии предназначены для отдельной, проверяемой записи только в индекс. Обычный git add для рабочих двух путей включил бы все пользовательские изменения и здесь не применяется.

До записи владелец операции должен сверить HEAD, manifest SHA256 и candidate SHA256 и убедиться, что индекс целиком совпадает с HEAD. Отдельный stage_audit_ledger_index.py предусматривает read-only проверку по умолчанию и явный режим записи --apply, проверяет raw Git blob без фильтров, сохраняет частные резервные копии и подтверждает неизменность рабочего дерева. Требуется отсутствие других процессов, записывающих Git. Две операции cacheinfo не являются одной транзакцией: при отказе после первой нужен разбор receipt и текущего индекса, а не автоматический reset. Эта ветвь работы режим --apply не запускала и Git не изменяла.
