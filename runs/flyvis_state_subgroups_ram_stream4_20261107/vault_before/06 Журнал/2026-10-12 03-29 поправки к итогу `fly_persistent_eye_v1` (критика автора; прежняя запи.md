# 2026-10-12 03:29 — поправки к итогу `fly_persistent_eye_v1` (критика автора; прежняя запись не правится)

↑ [[06 Журнал/Дни/2026-10-12|2026-10-12]]

*Ошибка в эксперименте.* Подбор g объединял строки 20 видео до поиска соседних кадров: пары соединяли треки с одинаковым номером из разных видео (18 ложных пар, 15 пропущенных настоящих в каждом варианте). Исправлено в fit_gain (пары внутри видео); пересчёт без GPU: g = 1,6841 / 1,7386 / 0,5971 против 1,6474 / 1,6969 / 0,5823 (runs/fly_persistent_eye/fit_corrected.json). Ночные HOTA — результаты фактически запущенных вариантов, не версии с корректным подбором.

*Ошибки в выводе.* «На оба вопроса ответ “нет”» → оба преимущества не подтверждены (интервалы допускают пользу и вред). «Ограничение — в самом действии», «поправки уводят к чужой детекции», «сдвигом прогноза запас не взять» — сильнее данных: разбора назначений не было, оракул сдвигал прогноз успешно; −18 / −35 % — на обучающих примерах подбора. Верно: испытанная схема покадровых поправок не улучшила HOTA ни с FlyVis, ни с DIS; причина не локализована.

*Проверка применения поправки.* Из кода: сдвиг прогноза перемещает следующую вырезку глаза, и этот сдвиг входит в следующее измерение потока; по сохранённой статистике разгона нет (ограничитель — 35 из 161 278 у P-carry, средний |δ| 0,9 px); величину влияния без записи покадровых поправок не оценить.

*Решение автора.* В стенд не включать, MASA не ставить, автоматически не повторять; новая реализация — только при конкретной найденной ошибке применения; «выбор своей детекции» не ставить (внешняя голова, не узел FlyVis).
