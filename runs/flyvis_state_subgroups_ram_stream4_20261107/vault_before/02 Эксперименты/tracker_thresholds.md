# ⚫ Пороги трекера: сетка вниз, порог по яркости, разрешение 960

↑ [[02 Эксперименты/Направления/Пороги трекера|Пороги трекера]] · **Исход:** закрыт · `tracker_thresholds`

Три попытки монетизировать занижение уверенности ночью через пороги — все неудачные; разрешение 960 дало в одиннадцать раз больше.

## Вопрос
Можно ли вернуть ночные объекты снижением порога трекера, в том числе адаптивно по яркости?

## Ожидалось (до прогона)
Оптимум порога ночью ниже дневного и устойчив при разбиении по видео; регрессия «яркость → порог» окупается на отложенных видео.

## Что сделано
Сетка порогов вниз от 0.25 на кэше; проверка разбиением по видео (4 из 4); настройка порога по яркости на обучающей половине и замер на отложенной; расцепление проходов трекера; 960 в трекере.

## Получено
Оптимум ночью 0.15 против 0.25, но +169 перебросов личности. Порог по яркости: +0.096 IDF1 при разбросе плеч 0.095; R² регрессии 0.043. Расцепление проходов — выход совпал побайтово. 960 в трекере: MOTA ночью 41.72 → 44.81 (+3.1), днём +4.1; ночной оптимум порога при 960 исчез.

## Интерпретация
Выигрыш от снижения порога приходит от обнаружения, а связывание за него платит. Гипотеза «ночной дефект — артефакт разрешения» опровергнута прямо (+0.0911 на 960).

## Решение
Адаптация порога по яркости закрыта; 960 принято как база, а не прирост метода.

## Условия
- **baseline:** порог 0.25
- **variant:** 0.15; регрессия по яркости; две ступени по яркости
- **dataset:** BDD100K
- **split:** val, 25 видео на условие
- **detector:** YOLO26s seed42
- **tracker:** ByteTrack

## Критерии приёмки (записаны до прогона)
- ❌ прирост порога по яркости больше разброса между плечами  
  *0.096 при разбросе 0.095*
- ❌ снижение порога ночью не увеличивает перебросы личности  
  *+169 IDSw*
