# ⚪ З13: чтение отдельных моделей памяти по текущему запросу

↑ [[09 Запланировано/FlyVis — планы|FlyVis]] · **Исход:** запланирован · `z13_query_memory_v1`

Зафиксирована одна версия чтения раздельных моделей памяти; исход не получен.

## Вопрос
Помогает ли зависимый от текущего запроса выбор между отдельными моделями прошлых наблюдений сверх последнего образца и равномерного смешивания тех же моделей?

## Гипотеза
Раздельное сохранение моделей и выбор по текущему отклику может использовать прошлые наблюдения иначе, чем испытанное совместное обучение одной модели.

## Ожидалось (до прогона)
Те же C/D/R1 и fit20/train26. Отдельные модели1–3, фиксированное и зависимое от запроса смешивание; допуски прежние, ядро не обучается. GPU до2400с, по одному процессу.

## Нельзя заявлять
Не полная STMTrack, не HOTA и не безопасное вмешательство. Параметры выбираются только по fit20. Оракул трёх прежних пиков не задаёт потолок новых карт отклика.

## Критерии приёмки (записаны до прогона)
- ⏳ Контроль last всех3 вариантов воспроизведён на8326 строках: центр<0,5px,балл<0,001; исходники/наблюдаемые маски неизменны.
- ⏳ C query−C last: средний сдвиг>=2п.п. и нижняя95%повидеоДИ>0.
- ⏳ C query лучше C fixed и такого же R1 query: обе нижние95%повидеоДИ>0.
