# 🟢 Голова «удалить отдельную жизнь» в готовом выходе после MASA — без мухи и с мухой

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** закрыт · `life_filter_head_v1`

Решение автора 09.10 после [life_filter_oracle_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Flife_filter_oracle_v1) (оракул +0,33 HOTA сверх удаления цепочек на dev). Действие — удалить рамки жизни (фрагмент трекера до сшивки) из готового выхода после MASA; номера и связи не меняются. Метка жизни — правило оракула: 1 — все учитываемые рамки ложные, 0 — есть верная, −1 — нет учитываемых (не обучается, не удаляется). Метки train 130 — с выхода перекрёстной сшивки (метка зависит только от рамок кадра). Признаки: без мухи — длина, уверенность детектора, рамки начала и конца, класс, вход глаза (751); с мухой — плюс сигнатуры мухи начала и конца (2 043). Логистическая регрессия C = 0,1 на жизнях train 130; dev — проверка, порог при бюджете потерь 1 %. Проверка сборки на 019efe88-bbc2a4ac: полностью ложных жизней 52 — как у оракула. scripts/life_filter_head.py.

## Вопрос
Лучше ли муха выбирает отдельные ложные жизни для удаления, чем тот же фильтр без мухи?

## Гипотеза
На уровне жизни (без сведения в цепочку) сигнал мухи о совпадении крайних рамок (+0,029 AP в [stitch_realness_fly_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fstitch_realness_fly_v1)) переносится в выбор ложных жизней.

## Ожидалось (до прогона)
Критерий перехода (dev): AP с мухой − без мухи > 0, ДИ по видео > 0. При выполнении — HOTA при бюджете 1 % (порог из dev) на dev, test и val7: с мухой − без мухи > 0 с ДИ > 0 на test, val7 — знак; потери ≤ 1 %. Справочно — без мухи − без фильтра.

## Интерпретация
На уровне отдельной жизни муха не улучшает ранжирование ложных жизней: AP одинаков (−0,0001, ДИ содержит 0) — в отличие от цепочек, она и не ухудшает его. Наблюдение, не входившее в критерий: при бюджете 1 % на dev голова с мухой на том же пороге 0,7 удаляет больше ложных рамок (560 против 419) при немного больших потерях (21 против 17 объектов) — порог и бюджет выбраны на тех же данных, вывода из этого не делаю. Закрыт способ «сырые сигнатуры мухи в начале и конце жизни → линейная голова жизни»; версия «нужна история внутри жизни» не проверена. Найдена ошибка 09.10 (разбор автора): в signatures.npz один номер трекера встречается в нескольких записях жизней (трек потерян и вернулся с прежним номером; dev — 49 652 записи при 41 304 уникальных номерах, train — 196 216 при 159 592). Рамки выхода относились к жизни по номеру, а не по записи и интервалу кадров: метки и потери считались для объединения всех жизней номера (pos = {tid: i} оставлял последнюю запись), признаки life_features (уверенность, число строк) смешивали жизни номера, удаление шло по номеру. Пример: 019efe88-bbc2a4ac, номер 8 — жизни 0–129 (3 верных, 5 ложных) и 141–221 (0 верных, 8 ложных) получили общую метку 0. Ограничение вывода: опыт не является чистой проверкой способности мухи различать отдельные жизни (метки и признаки смешивали жизни одного номера); повтор — [life_filter_head_v2↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Flife_filter_head_v2).

## Решение
Закрыта по заранее записанному критерию перехода (dev); test/val7 и HOTA не считались. Направление «удаление с мухой» по уровням цепочка → жизнь проверено при нынешних сигнатурах (только концы жизней) — сигнала нет. Оставшиеся версии из разбора 09.10: история мухи внутри жизни (новый проход FlyVis на GPU, контроль с той же историей без мухи) и обучаемое объединение — каждое по отдельному согласованию затрат.

## Нельзя заявлять
Нельзя заявлять вклад FlyVis в выбор ложных жизней; наблюдение по бюджету (больше удалённых ложных рамок) не заявляется — порог выбран на тех же данных и не входил в критерий. Только dev. Числа получены с ошибкой идентификации жизней (см. interpretation) — как вердикт для отдельных жизней не использовать.
