# 🟢 К16, ступень 1: важна ли тонкая схема связей — профили FlyWire против перемешанных при той же «дозе», на «объект ещё здесь?» и узнавании

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** отрицательный · `fly_flywire_swap_v1`

Решение автора 08.10 (после проверки поля val7): К16-1. tracking/flyvis_connectome_swap.py строит варианты связей FlyVis (data/flywire/flyvis_variants/, имена с хэшем содержимого — FlyVis кэширует сборку по пути): flywire — для 424 из 604 рёбер (оба типа найдены в FlyWire, ≥ 0,5 синапса на клетку, типы есть в каждой колонке) профиль по смещениям колонок из FlyWire при сохранении общего числа синапсов ребра («та же доза»); flywire_shuf — те же профили, перемешанные между заменёнными рёбрами одного знака (своя доза). Обученные свободные параметры — модели 000 без переобучения. Проверки пути: штатная копия даёт ту же активность (макс |Δ| 2·10⁻⁶); полные числа FlyWire без сохранения дозы взрывают динамику (до 10¹⁵ / NaN) — поэтому «та же доза»; при той же дозе средн. |Δ активности| к штатной: FlyWire 0,12, перемешанные 0,18 (средн. |акт.| 0,71). Сигнатуры мухи (build_fly_signatures.py --connectome-json) для двух вариантов на 70 видео dev + test; штатные — runs/fly_signatures. Головы «объект ещё здесь?» и узнавания: обучение на dev 35, проверка на test 35, одинаково для трёх вариантов. Поправка 08.10 до получения результатов: первый запуск сигнатур (6 процессов) упал — вариант FlyWire со всеми смещениями ≥ 0,05 синапса давал 7 408 чисел синапсов против 2 355 у штатной (сеть втрое тяжелее), процессы не помещались в 12 ГБ GPU. Варианты пересобраны с той же разреженностью: у ребра — k самых сильных смещений FlyWire, k = числу смещений в FlyVis; заменено 398 рёбер; чисел синапсов 2 153; средн. |Δ активности| к штатной: FlyWire 0,089, перемешанные 0,172. Новые каталоги сигнатур — runs/fly_signatures_k16b_flywire, _k16b_shuf (прерванные k16_* не используются); 3 процесса, потолок памяти 0,3.

## Вопрос
Зависит ли полезность признаков мухи («объект ещё здесь?», узнавание) от конкретного пространственного профиля связей?

## Гипотеза
Профили FlyWire (настоящая анатомия) дают признаки не хуже штатных и лучше перемешанных профилей той же дозы.

## Ожидалось (до прогона)
На test 35 (головы с dev 35), бутстрэп по видео: (1) FlyWire − перемешанные > 0 с ДИ > 0 по AP «объект ещё здесь?» (голова геометрия + муха) — тонкая схема важна; (2) FlyWire − штатные: нижняя граница ДИ > −0,01 (не хуже); то же для узнавания — дополнительно. Если (1) ≈ 0 — тонкий профиль связей при той же дозе не важен для этих признаков (ответ P6 для профиля, не для топологии типов).

## Что сделано
Варианты связей (той же дозы и разреженности), сигнатуры двух вариантов на 70 видео dev + test (3 процесса, ≈ 2,7 ч GPU после перезапуска), головы dev → test (scripts/k16_compare_heads.py).

## Получено
runs/fly_flywire_swap/heads_compare.json (сигнатуры — runs/fly_signatures, runs/fly_signatures_k16b_flywire, runs/fly_signatures_k16b_shuf; 140 видео без ошибок). Головы обучены на dev 35, проверка на test 35; события трёх вариантов совпадают: True. AP «объект ещё здесь?» (геометрия + муха): штатная 0,9594, FlyWire 0,9532, перемешанные 0,9540; только геометрия 0,9419. FlyWire − перемешанные −0,0008 [−0,0045; 0,0029]; FlyWire − штатная −0,0062 [−0,0099; −0,0028]; штатная − перемешанные 0,0054 [0,0018; 0,0098]. Прибавка мухи к геометрии: штатная 0,0175 [0,0091; 0,0276], FlyWire 0,0113 [0,0033; 0,0204], перемешанные 0,0121 [0,0038; 0,0227]. С входом (hexin): FlyWire − перемешанные −0,0016 [−0,0045; 0,0013], FlyWire − штатная −0,0039 [−0,0071; −0,0009].

## Интерпретация
Профили связей FlyWire при обученных параметрах штатной мухи не лучше перемешанных профилей той же дозы (разница ≈ 0), а оба варианта чуть хуже штатного (≈ −0,006 AP). Штатный профиль лучше перемешанного (+0,005) — но FlyWire-профиль, анатомически более полный, ведёт себя как случайная перестановка: без переобучения опыт меряет расстройку сети, обученной на своей схеме, а не значимость анатомии (то же ограничение, что у нулевой модели в [fly_connectome_null_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_connectome_null_v1), F17). Важное попутное: прибавка мухи к геометрии сохраняется при любом профиле (+0,011…+0,018, ДИ > 0) — польза признака «объект ещё здесь?» держится на типах клеток и входе, а не на тонкой пространственной структуре связей.

## Решение
Критерий 1 не выполнен (FlyWire − перемешанные ≈ 0, ДИ содержит 0); критерий 2 формально выполнен на границе (нижняя граница −0,0099 > −0,01), хотя разность значимо отрицательна → completed_negative для этой реализации. По правилу 6.15 узел провала — постановка без переобучения (расстройка смешивается с анатомией). Замена: одинаковое дообучение каждого варианта (штатный, FlyWire, перемешанный) перед сравнением — протокол К1 v2 на нормализованном входе (≈ 0,5 ч GPU на вариант) и затем сигнатуры (≈ 3 ч на 2 варианта) — по согласованию; либо исходное обучение на Sintel (сутки GPU на вариант).

## Нельзя заявлять
Что анатомия FlyWire не важна (не было переобучения); что FlyWire «хуже» штатной схемы как анатомия (параметры обучены под штатную); выводы — для одной модели (000), одной задачи («ещё здесь?»), профилей при той же дозе.
