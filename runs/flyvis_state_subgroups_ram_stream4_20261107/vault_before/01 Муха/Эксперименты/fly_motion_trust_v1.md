# 🟢 Когда движению мухи можно доверять: уверенность поля против фактической ошибки и потолок избирательного применения

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** положительный · `fly_motion_trust_v1`

Предложение 07.10 (принято автором как следующий этап, без обучения): в [motion_scheme_search_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fmotion_scheme_search_v1) муха вредит в схеме 5 Гц. Уверенность поля (tracking/flyvis_tracker.py:147–150) = покрытие / (1 + разброс векторов в рамке) — согласованность, а не правильность; при < 3 колонок в рамке добираются колонки снаружи; вес мухи в схеме ≈ DIS (0,67 против 0,71). Шаг 1 (scripts/fly_trust_diagnostic.py): по переходам между размеченными кадрами dev 35 — ошибка мухи, DIS, постоянной скорости (заменитель Калмана) и нуля против уверенности, размера, числа колонок, расхождения с постоянной скоростью; ошибка за один сырой кадр. Шаг 2: в трекере схемы 5 Гц — идеальный выбор «муха / Калман» по разметке (потолок идеи доверия).

## Вопрос
Различает ли нынешняя уверенность поля полезные и вредные поправки мухи, и есть ли запас у избирательного применения мухи в трекере?

## Гипотеза
Уверенность мухи не отражает её ошибку; при идеальном выборе мухи против Калмана трекер выигрывает — значит, мишень — модуль доверия.

## Ожидалось (до прогона)
Шаг 1: AUC уверенности для «муха лучше постоянной скорости» ≤ 0,6 — уверенность не различает (мишень для замены). Шаг 2: идеальный выбор по разметке в схеме 5 Гц даёт HOTA выше без движения с ДИ > 0 — запас есть, обучаемый модуль доверия обоснован (с контролем без мухи); иначе — модуль доверия в этой схеме не нужен.

## Что сделано
Шаг 1 — scripts/fly_trust_diagnostic.py (63 554 перехода, dev 35); шаг 2 — scripts/motion_scheme_search.py с источниками fly_oracle / dis_oracle (dev 35, val7). Только процессор.

## Получено
Шаг 1 (runs/fly_motion_trust/summary.json, rows.npy): 63554 переходов «объект × пара размеченных кадров», dev 35. Медиана / среднее ошибки центра, px: муха + lcn24 7,15 / 14,77, DIS 3,19 / 7,49, постоянная скорость 5,02 / 9,42, ноль 8,31; идеальный выбор «муха / постоянная скорость» 3,96 / 7,52. Муха лучше постоянной скорости в 34% случаев (DIS — в 60%). Уверенность поля мухи: Спирмен с ошибкой −0,474, AUC «муха лучше постоянной скорости» 0,556; расхождение с постоянной скоростью — AUC 0,570. По размеру объекта: 0-32 px: n 17015, муха 5,51, DIS 2,35, пост. скорость 4,07, муха лучше 36%, AUC уверенности 0,508, средняя уверенность 0,79; 32-64 px: n 20531, муха 6,35, DIS 2,72, пост. скорость 4,70, муха лучше 36%, AUC уверенности 0,521, средняя уверенность 0,73; 64-128 px: n 14658, муха 9,42, DIS 3,98, пост. скорость 5,56, муха лучше 30%, AUC уверенности 0,573, средняя уверенность 0,62; 128-∞ px: n 11350, муха 14,78, DIS 8,27, пост. скорость 7,45, муха лучше 30%, AUC уверенности 0,614, средняя уверенность 0,53. Шаг 2 (runs/motion_scheme_search/dev.json, val7.json; источник *_oracle — поправка берётся только там, где по разметке она ближе к правде, чем Калман), схема 5 Гц, HOTA. dev 35: none: 52,53; fly: 51,54 (−0,995 [−1,740; −0,279], лучше 15/35); fly_oracle: 53,52 (0,990 [0,412; 1,574], лучше 26/35); dis: 55,81 (3,277 [1,694; 4,927], лучше 29/35); dis_oracle: 58,74 (6,214 [4,703; 7,873], лучше 33/35). val7: none: 46,26; fly: 43,54 (−2,723 [−5,495; −0,574], лучше 1/7); fly_oracle: 46,86 (0,596 [−0,095; 1,273], лучше 4/7); dis_oracle: 50,84 (4,578 [1,816; 7,603], лучше 7/7).

## Интерпретация
Вред мухи в схеме 5 Гц — от доверия: её поправка в среднем хуже продолжения скорости, а вес поправки (уверенность поля) почти не связан с тем, права ли муха, и наибольший на мелких рамках. При идеальном выборе «поправка / Калман» муха даёт +0,99 HOTA вместо −1,00 — запас у модуля доверия есть, но потолок мухи ниже обычного DIS (+3,28). Модуль доверия ещё сильнее помогает DIS (+6,21 при идеальном выборе) — улучшение доверия прежде всего улучшает схему трекера; вклад мухи нужно отделять контролем «тот же модуль без признаков мухи».

## Решение
Оба критерия выполнены → completed_positive. Следующее (решение автора 07.10): дешёвый вариант без обучения — пониженный вес мухи и запрет поправки при недостатке колонок в рамке, подбор и проверка на разных видео (fly_motion_trust_cheap_v1); если мало — обучаемое доверие с обязательным сравнением того же модуля без признаков мухи. Критерий перехода — положительная парная разность HOTA на видео, не участвовавших в настройке.

## Нельзя заявлять
Что идеальный выбор достижим (использует разметку); что муха лучше DIS как источник движения (потолок мухи ниже обычного DIS).
