# 🟢 Трекер на мухе, этап 1, v2: при «жив» по мухе продолжать трек рамкой слабой детекции, а не предсказанием

↑ [[01 Муха/Темы/Трекер на мухе|Трекер на мухе]] · **Исход:** отрицательный · `fly_tracker_lifecycle_v2`

Итерация [fly_tracker_lifecycle_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_tracker_lifecycle_v1): голова мухи хорошо отличает «жив / ушёл», но продолжение рамкой-предсказанием Калмана неточно. Здесь при «жив» (порог — максимум F1 на dev) потерянный трек ≤ 3 кадров выдаётся рамкой слабого кандидата детектора (conf 0,01–0,25, тот же класс, IoU ≥ 0,3 к предсказанию, не занятого выходами трекера). Контроль — то же без головы (все потерянные треки), т. е. вторая волна без слияния баллов. Головы — те же (модель 000).

## Вопрос
Даёт ли продолжение рамкой слабой детекции по решению мухи прирост HOTA, которого не даёт слепое продолжение?

## Гипотеза
Рамка детекции точнее предсказания; голова мухи отсекает исчезнувшие объекты, поэтому продолжение по ней не плодит ложных выходов.

## Ожидалось (до прогона)
test: голова с мухой ≥ +0,3 HOTA к стенду, ДИ > 0; больше, чем без головы и чем по голове на геометрии; val7 — тот же знак.

## Что сделано
scripts/fly_lifecycle_alive.py --track --coast 3 --mode lowscore; головы — из [fly_tracker_lifecycle_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_tracker_lifecycle_v1) (модель 000).

## Получено
ΔHOTA к стенду, test: без головы -0,142 [-0,290; +0,009] (14/21) (IDSw 2221 → 2460); голова геометрии +0,080 [+0,049; +0,115] (27/7); с мухой +0,082 [+0,047; +0,121] (28/6); вход +0,083 [+0,047; +0,122] (29/5); вход + муха +0,082 [+0,047; +0,122] (29/5). val7: без головы +0,481 [-0,046; +1,166] (5/2); геометрия +0,173 [+0,100; +0,238] (7/0); с мухой +0,166 [+0,080; +0,240] (6/1).

## Интерпретация
Продолжение потерянного трека рамкой слабой детекции, отфильтрованное головой «жив ли», даёт устойчивый небольшой плюс (test +0,08, val7 +0,17, ДИ > 0; без головы — больше переключений ID). Но все головы равны: когда рядом с предсказанием есть слабый кандидат, объект почти всегда «жив», и это видно по геометрии — преимущество мухи в различении «жив / ушёл» здесь не используется.

## Решение
Критерии 1 и 2 не выполнены (+0,08 < +0,3; муха = геометрия), 3 — выполнен по знаку → completed_negative для мухи. Приём «продолжать слабой детекцией по голове на геометрии» — практическое улучшение линии B (+0,08…+0,17 HOTA). Следующая итерация мухи — удаление «ушедших» треков по её голове (fly_tracker_lifecycle_v3).

## Нельзя заявлять
Что муха нужна для продолжения треков: голова на геометрии даёт то же.

## Условия
- **baseline:** стенд; продолжение без головы
- **variant:** продолжение рамкой слабой детекции по головам
- **dataset:** как у [fly_tracker_lifecycle_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Ffly_tracker_lifecycle_v1)
