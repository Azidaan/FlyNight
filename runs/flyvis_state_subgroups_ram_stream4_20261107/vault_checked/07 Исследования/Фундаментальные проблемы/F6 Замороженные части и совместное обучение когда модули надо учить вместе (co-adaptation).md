# F6 Замороженные части и совместное обучение: когда модули надо учить вместе (co-adaptation)

↑ [[07 Исследования/Фундаментальные проблемы/Фундаментальные проблемы|Фундаментальные проблемы]]

> Почему подключение замороженных модулей «как есть» не работает; совместное обучение конвейеров (детекция+трекинг, сквозные трекеры), частичная разморозка; конфликт градиентов (OneTrack).

## Механизм
1) Fragile co-adaptation (Yosinski et al., NeurIPS 2014): layers of a trained network co-adapt; cutting a network and re-training the top on frozen bottom layers (BnB) loses accuracy at middle cuts (layers 3-5 on ImageNet AlexNet, base top-1 0.625) even on the SAME task, and fine-tuning the copied layers (BnB+) fully recovers - the features were fine, the interface was not. The same happens across separately trained modules: a frozen detector expects its own input statistics; a frozen fly trained on Sintel optical flow outputs features shaped for Sintel. 2) Covariate shift at a module boundary: when an upstream module (enhancer, retina) changes the distribution entering a frozen downstream module, accuracy drops even if the image is 'better' for humans. IA-YOLO (AAAI 2022): Zero-DCE enhancement + YOLOv3 trained on normal images drops VOC_Dark_test 45.92 -> 33.57 mAP and ExDark 36.42 -> 34.41, while the jointly trained differentiable filter + YOLOv3 reaches 59.40 and 40.37. Surgical fine-tuning (Lee et al., ICLR 2023): for input-level shifts, tuning only the FIRST layers works best - the fix belongs at the boundary. 3) Task conflict when trained jointly: joint detection + association (MOTR) degrades detection because the two losses assign positives differently; OneTrack (ECCV 2024) traces it to partially conflicting classification gradients. MOTRv2 resolves it by importing a separately trained detector (YOLOX proposals as anchors) - i.e. decoupling can be better than co-training when objectives conflict. 4) Rule that follows: freeze where the interface is fixed and the objectives conflict; co-train (or at least fine-tune the boundary layers) where one module changes the input distribution of another. A pipeline of independently optimized modules is optimal only if each module's output is a sufficient statistic for the next - which the tracker evidence (DetA flat) shows is false for 'detector -> tracker': detector FN cannot be fixed downstream.

## Где видно у нас
Г3: frozen YOLO26 on photoreceptor frames -9.45 pp night recall at equal FP [-11.54; -7.68], pr+integration -15.13 pp, even non-biological tavg3 -1.97 pp; night blindness 0.1047 -> 0.1585 (pr) - the same pattern as Zero-DCE + frozen YOLOv3 (-12.35 mAP on VOC_Dark). This is an interface (covariate-shift) failure, not proof that the retina signal is useless; the plan's K5 (fine-tune detector on photoreceptor frames) and K4 (train retina jointly) are exactly the co-adaptation tests. Fly as motion source: frozen fly trained on Sintel - 52.77 px error vs DIS 4.87 px on BDD, ΔHOTA ~0: the fly never adapted to BDD statistics (K1). Fly identity: fly alone -0.052 below its own input - frozen fly features are not adapted to the identity task (K2). Retina-lamina in front of the fly fixed the fly's night drop (+0.016) but did nothing for DIS (+0.001) - the fly and its front-end are co-adapted (biologically), DIS is not. Tracker on frozen detector: HOTA 58.47 -> 59.27 with DetA 58.21 -> 58.17 and FN 15,763 >> IDSw 2,221; re-scoring weak candidates after the detector (tubelet 5 Hz, 30 Hz + motion) ~0 at equal FP - post-hoc modules on a frozen detector cannot recover what the detector's features discarded (rule 6.14). Fine-tuning artifacts: Ultralytics seed does not change anything when fine-tuning from the same weights (rule 6.12); confidence target without IoU multiplication gave ~0 (Г2: night -0.15 pp) - the detector's score is already co-adapted with its box quality (Spearman 0.73).

## Решения из литературы
Joint training of an image-processing front-end with the detector: IA-YOLO on low light - 59.40 mAP VOC_Dark_test and 40.37 ExDark vs YOLOv3 trained on hybrid data 52.28 / 37.03 (+7.12 / +3.34) and vs frozen-detector enhance-then-detect 33.57 / 34.41 (+25.8 / +5.96); cost +13 ms over YOLOv3. Against modern strong bases the gain is much smaller: project D8 - YOLA +1.7..+2.7 vs old bases; day->night adaptation with night labels available +0.2 AP50 (2PCNet). Surgical fine-tuning: for input-level corruptions (CIFAR-C, ImageNet-C) tuning only the first block matches or beats full fine-tuning [exact numbers not extracted - uncertain]. Fragile co-adaptation fix: fine-tuning the transferred layers recovers all of the BnB loss; transfer + fine-tune even gives +1.6% top-1 averaged over cut layers 1-7 (+2.1% if >= 5 layers kept). Detection-tracking: when co-training conflicts, decouple and pass a strong prior: MOTRv2 on BDD100K MOT val - MOTR 32.3 mMOTA / 44.8 mIDF1, MOTR* (better training) 35.5 / 48.2, MOTRv2 with frozen YOLOX proposals 43.6 / 56.5 (+8.1 / +8.3 over MOTR*); on DanceTrack 69.9 HOTA (73.4 with extras). OneTrack: masking attention between query groups with conflicting positive assignment + gradient coordination: +6.9 AMOTA val / +3.1 test on nuScenes camera tracking. Staged recipe used across these works: (a) train new module with downstream frozen; (b) unfreeze only boundary layers (stem/first stage of the detector for input-level change) at LR x0.1; (c) optional full joint fine-tuning with gradient-conflict monitoring (cosine between task gradients, PCGrad if negative).

## Что сделать с мухой
Three co-adaptation steps, cheapest first, each with the rest frozen: (1) Adapt the fly to BDD (K1/K2): train the 734 fly params + retina-lamina parameters (tau, sigma, gain) on BDD video with self-supervised next-frame/box-transfer loss (motion) or same/different-object loss (identity); detector and tracker frozen. Truncated BPTT through the fly ODE over 3-5 frames to fit 12 GB. (2) Adapt the detector's boundary to the fly front-end (K5): fine-tune ONLY the stem + first backbone stage of YOLO26 (surgical fine-tuning, input-level shift) on photoreceptor frames for 2 epochs; compare with fine-tuning the same layers on raw frames (ctl) and on tavg3 frames. If the -9.45 pp night gap closes to >= 0, the Г3 loss was interface, not signal. (3) Joint (K4): retina parameters + stem trainable together with the detection loss, rest of YOLO26 frozen; or the side-path variant (F4): raw frame to YOLO26 unchanged, fly features to P3 through a zero-init adapter, which avoids the interface problem altogether. Never feed processed frames to a fully frozen detector again (Г3 settled that).

## Тест до постройки
(1) Model-stitching / boundary-only probe on cached data: freeze everything except the YOLO26 stem (first conv + BN) and train ~0.2 epoch on photoreceptor frames; if night recall at equal FP recovers most of the -9.45 pp in this tiny run, the loss was interface (co-adaptation) and K5 is worth a full 2-epoch run; if it stays at -5 pp or worse, the signal is destroyed by the front-end. Also a 'BN-only' variant (recompute BN statistics of the first stages on processed frames, no gradient) - zero-cost test of pure covariate shift. (2) Information check independent of interface: linear probe of P3 features from processed vs raw frames for GT-cell presence at night (AUC); equal AUC => the information survives and only co-adaptation is missing. (3) For the fly motion source: oracle test - replace fly flow by DIS flow within the same downstream motion head (already ~ done: DIS 4.87 px, ΔHOTA ~0 with fly 52.77 px) - if even DIS-quality motion gives ΔHOTA ~0, adapting the fly to BDD motion has a low ceiling in HOTA; measure ΔHOTA(DIS vs no-motion) first. (4) Gradient-conflict check before joint training: cosine of gradients of detection loss and the fly auxiliary loss on shared parameters over 100 batches; consistently negative => decouple (MOTRv2 style) rather than co-train.

## Потолок
Co-adapting the front-end can at best recover the Г3 loss (+9.45 pp for pr, +1.97 pp for tavg3) to the raw baseline and then add whatever the front-end signal brings beyond raw; literature against strong bases suggests 0..+1 pp night (plan K4/K5 expectation 0..+1 pp; YOLA +1.7..+2.7 vs old bases). Night-specific threshold gap is 5.5 pp (21.0% vs 15.5%), so 0-18% of that gap [uncertain]. Fly adaptation to BDD (K1): motion error can drop from 52.77 px toward DIS 4.87 px, but its tracker ceiling is bounded by ΔHOTA(DIS) which is itself ~0 above geometry -> HOTA ceiling of motion improvement is small unless the fly beats DIS at night. Detector -> tracker co-training: DetA is the bottleneck (FN 15,763), so only detector-side co-adaptation can move HOTA materially.

## Где обязано помогать
Must help: night recall at equal FP (dev+test night baseline 0.7552) and night blindness (0.1047) - those are where Г3 lost most; age-0 objects; overexposure segments for the adaptation variant. No harm: day recall at equal FP (Г3 pr was -2.88 pp by day - must return to 0 +/- CI), val7 and 70 held-out videos mAP50 (rule 6.13: detector checks only on unseen videos).

## Отрицательный контроль
(1) Same fine-tuning schedule on RAW frames (ctl - exists) - separates 'more training' from 'front-end'; (2) same schedule on tavg3 frames (non-biological front-end with the same temporal pooling); (3) retina with randomized/shuffled parameters (or shuffled connectome for the fly part); (4) fine-tuning on photoreceptor frames with frames temporally shuffled (removes temporal integration benefit). The fly front-end is credited only if pr-fine-tuned > raw-fine-tuned AND > tavg3-fine-tuned on night with CI excluding 0 and no day loss.

## Вклад ветви
Track per epoch: night/day recall at equal FP on a fixed held-out slice; drift of stem weights ||W - W0||; BN running-mean shift of first stages; for joint training the cosine between detection and fly-aux gradients on shared params and the per-module gradient norm ratio; ablation by epoch (swap front-end to raw at eval) to see whether the detector became dependent on it.

## Минимальный эффект и стоимость
Paired video bootstrap with frozen detector: half-width ~0.8 pp night recall (tavg3 CI [-2.79; -1.22]) -> MDE ~1 pp per comparison. Fine-tuning adds run-to-run variance; Ultralytics seed is ineffective from the same weights (rule 6.12), so vary data order manually and run >= 2-3 per arm. Costs on RTX 5070 12 GB: BN-only recalibration ~minutes; stem-only 0.2-epoch probe ~15-20 min [uncertain]; K5 2-epoch fine-tune ~1 h per run (plan) -> 4 arms (raw, tavg3, pr, shuffled) x 2 runs ~ 8 h; K4 joint retina+detector 1 day code + ~3 h GPU per run; K1 fly self-supervised adaptation 3-5 h GPU + 1-2 days code; a full 12-epoch detector run ~4.3 h.

## Вердикт для проекта
MAIN. The single clearest failure pattern across the project is plugging separately trained, frozen modules together 'as is': Sintel-trained fly into BDD motion (52.77 vs 4.87 px), fly-alone features into identity (-0.052 vs input), processed frames into a frozen YOLO26 (-2..-15 pp), post-hoc re-scoring after a frozen detector (~0). Priority HIGH: (1) BN-only and stem-only probes on photoreceptor frames (hours) to separate interface loss from signal loss; (2) K1/K2 - train the fly itself on BDD with downstream frozen; (3) K5 then K4 only if (1) shows recovery. Doubt on novelty (stated briefly per project rules): staged/joint training of a front-end with a detector is standard (IA-YOLO), so the contribution can only be in the fly itself, not in the training recipe.
