# 🟢 Гейт продолжения треков: порог второй волны и вывод недавно потерянных треков по предсказанию

↑ [[02 Эксперименты/Направления/Пороги трекера|Пороги трекера]] · **Исход:** отрицательный · `track_continuation_v1`

Следствие [past_view_oracle_v1↗](obsidian://open?vault=ObsidianFlyVis&file=02%20%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fpast_view_oracle_v1): у ~1/3 реальных потерь на пороге объект уверенно виден в прошлых 5 кадрах, но стенд его не выдаёт. Варианты стенда (меняется одно условие): порог второй волны 0,05 и 0,01; вывод потерянных треков ≤ 3 / ≤ 6 кадров после последнего сопоставления по предсказанию Калмана; комбинация 0,05 + 3. Test 35, val7; HOTA TrackEval; бутстреп по видео.

## Вопрос
Возвращает ли более мягкая политика продолжения треков часть потерь на пороге без роста переключений ID?

## Гипотеза
Вывод недавно потерянных треков и продолжение на слабых кандидатах поднимают DetA; переключения ID растут мало.

## Ожидалось (до прогона)
Лучший вариант ≥ +0,3 HOTA на test, ДИ по видео > 0, тот же знак на val7; IDSw не хуже +5 %. Иначе потолок Д2 недостижим простой политикой — нужен признак «тот же объект» для продолжения (место мухи).

## Что сделано
scripts/gate_track_continuation.py: 6 вариантов × 42 видео, 8 процессов (Idle), ~20 мин.

## Получено
ΔHOTA к стенду по видео. test: coast3 -0,820 [-1,023; -0,606] (3/32), coast6 -2,201 [-2,513; -1,881] (1/34), combo -0,820 [-1,037; -0,607] (3/32); ночь coast3 -0,616 [-0,931; -0,280] (2/12). val7: coast3 -0,088 [-0,638; +0,761] (1/6), coast6 -0,934 [-1,773; +0,318] (1/6); ночь coast3 +0,813 [-0,688; +2,314] (1/1). IDSw test 2221 → coast3 2281. low05 и low01 совпали со стендом побайтно: при fuse_score = True стоимость второй волны 1 − IoU·балл, порог принятия 0,5 требует балла ≥ 0,5, а во вторую волну идут кандидаты < 0,25 — вторая волна ByteTrack на стенде фактически выключена, порог второй волны ни на что не влияет.

## Интерпретация
Вывод недавно потерянных треков по предсказанию Калмана вредит (test −0,8 при 3 кадрах, −2,2 при 6): предсказание расходится с объектом, а часть объектов действительно исчезает (заслонение, выход из кадра). Потолок Д2 (треть реальных потерь с уверенным прошлым видом) простой политикой продолжения не берётся — нужен признак «это всё ещё тот же объект здесь», то есть подтверждение по изображению. Попутная находка: вторая волна ByteTrack на стенде мертва из-за fuse_score (известное ранее ухудшение второй волны без слияния баллов — [раздел 0↗](obsidian://open?vault=ObsidianFlyVis&file=05%20%D0%9F%D0%BB%D0%B0%D0%BD%2F0.%20%D0%A2%D0%B5%D0%BA%D1%83%D1%89%D0%B5%D0%B5%20%D1%81%D0%BE%D1%81%D1%82%D0%BE%D1%8F%D0%BD%D0%B8%D0%B5%20%D0%BD%D0%B0%2013.09.2026) плана).

## Решение
Критерии не выполнены (лучший онлайн-вариант на test −0,8) → completed_negative. Варианты low05/low01 — нулевые по устройству трекера, не проверка гипотезы. Следующий кандидат для этого потолка — подтверждение продолжения по изображению (q_alive), где уже был отрицательный опыт с мухой (flyvis_event_features_v1) — сначала без мухи.

## Нельзя заявлять
Что порог второй волны не влияет: при fuse_score = True он не участвует; вторая волна без слияния баллов проверялась отдельно раньше.
