# 2026-10-08 00:09 — `fly_motion_photometric_v1`: эта реализация не сработала — проверка изображения целой рамки уменьшает вред мухи вдвое, но вредит сама (с DIS +0,18 вместо +2,40); узел — сама проверка

*Получено.* runs/motion_scheme_search/photo_summary.json (dev_photo.json, val7_photo.json), 24 отложенных видео, схема 5 Гц, HOTA: муха + проверка − без движения −0,489 [−0,995; −0,052], лучше 9/24; нулевое движение + проверка − без движения −0,660 [−1,065; −0,331], лучше 5/24; муха + проверка − нулевое + проверка 0,171 [−0,301; 0,610], лучше 15/24; DIS + проверка − без движения 0,177 [−0,722; 0,915], лучше 16/24; муха без проверки − без движения −1,094 [−2,304; −0,104], лучше 10/24. Проверка принимает ≈ 6 % поправок мухи (средний вес в журнале расчёта).

*Вывод.* Фотометрическая проверка вдвое уменьшает вред мухи (−1,09 → −0,49), но сама вредит трекеру: с нулевым движением −0,66, с DIS съедает почти весь его выигрыш (+0,18 против +2,40 без проверки на тех же видео). Узел провала — сама проверка: сравнение изображения целой рамки (нормированная корреляция, ½ разрешения) за 6 кадров на 5 Гц ненадёжно — меняются вид и размер объекта, частичные перекрытия; рамка Калмана часто совпадает «лучше», хотя хуже по положению. Вклад предложений мухи сверх контроля +0,17 — не значим.

*Решение.* Критерии не выполнены → completed_negative для этой реализации (правило 6.15: узел — проверка изображения целой рамки). Замены узла проверки: проверка по точкам внутри рамки с ошибкой «вперёд-назад» (Kalal et al., 2010, «медианный поток»), проверка на полной частоте кадров (30 Гц, малые изменения вида), масштаб рамки в проверке.
