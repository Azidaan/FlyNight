# 2026-09-16 02:40 — фовеация FlyVis: отрицательно по основному критерию; сработала точка остановки A1.

↑ [[06 Журнал/Дни/2026-09-16|2026-09-16]]

*Постановка (карточка [flyvis_foveation_readout_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fflyvis_foveation_readout_v1), записана до кода).* Единственное изменение против tiled-считывания — вход сети: глаз на каждый трек `XYWHByteTrack` (параметры замороженного стенда), квадратная вырезка со стороной max(2·max(w, h), 64) вокруг предсказания фильтра на кадр t (без мутации трекера), рендер в поле 391×391, рождение глаза с fade-in 1 с на вырезке кадра появления, далее 2 внутренних шага с линейной интерполяцией между вырезками; глаз удаляется при уходе трека из tracked. Считывание T4/T5 и all34 — то же, что в предыдущей карточке, для self (предсказанная рамка) и каждой детекции, пересекающей вырезку. Контроль — `base + DIS + has_eye`, поскольку наличие глаза есть состояние трекера, доступное на инференсе. Уточнение до опыта: при вырезке крупнее кадра сохраняется квадрат со стороной высоты кадра (без искажения аспекта).

*Реализация.* `tracking/foveated_eyes.py` (батч рекуррентных состояний с переменным составом; 6 тестов на настоящей сети — детерминизм, инвариантность к порядку батча, восстановление индекса детекции из выхода ByteTrack), `scripts/build_foveated_readout_cache.py`, режим `--fovea-root` в гейте считывания; пары хранят индексы детекций (пересобраны, хэш тождествен). Кэш: 7 видео, 1 304 499 строк, глаз/кадр 1,8–22, 21–298 мс/кадр на GPU (`runs/flyvis_fovea`, 391 МБ); дымовой и полный прогон `b1cac6a7` дали побайтово одинаковые строки. Коммит `024586d`.

*Получено (`runs/qmatch_readout_gate/fovea_30hz/report.json`, отложенные видео).* Покрытие глазами у положительных пар 0,78–0,94 (на сложном фоне 0,779 — ниже записанного порога 0,8). `base + DIS + eye` AP 0,944843; `+ fovea T4T5` 0,945237: Δ −0,000436, 95%-й интервал [−0,002667; +0,001196], по видео +0,0012 / −0,0027 / +0,0002; Brier 0,011516 против 0,011384 — хуже на каждом видео. Против `shuffled fovea`: +0,002093, интервал [+0,001009; +0,003450], положительно на каждом видео — фовеальные признаки несут реальную информацию. Против `tiled T4T5`: +0,001308, интервал [−0,000042; +0,002451] — фовеация лучше сетки. Против декодированного потока: −0,003430, интервал [−0,005749; −0,000751]. `all34`: +0,001872, интервал через ноль, Brier хуже.

*Нелинейная диагностика (карточка [flyvis_readout_nonlinear_diag↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fflyvis_readout_nonlinear_diag), не критерий).* HistGradientBoosting на тех же парах: `base + DIS + eye` AP 0,967989; `+ decoded` 0,967990; `+ fovea T4T5` 0,966360; `+ fovea all34` 0,967054; `+ shuffled` 0,965983; `+ tiled T4T5` 0,967031; `+ tiled all34` 0,966626; `+ fovea all34 + decoded` 0,966787. Ни один вариант FlyVis не выше базы; возражение «линейная модель слишком слаба» снято.

*Решение.* Критерии 2, 3, 5 карточки не выполнены (4 выполнен). Лучший из проверенных вариантов считывания и охвата (фовеация > сетка) не даёт условного прироста `q_match` над `base + DIS`, устойчивого на каждом отложенном видео — **условие точки остановки A1 (План целей 1.6) выполнено**. По правилу 1.6: линия A перестаёт быть кандидатом на основной метод; FlyVis закрывается как исследованная ветвь с отрицательным результатом (не новизна, не страховка); основной метод диссертации — линия B: `XYWHByteTrack` + раздельная событийная уверенность; цель 3, дообучение FlyVis и сборка линии A не начинаются. Полнокадровое считывание не строилось: оно строго грубее сетки, которая уже проиграла; это записано как оговорка. Изменение маршрута по 6.5 выносится на согласование с пользователем; до его ответа новые опыты по FlyVis не начинаются.

*Что не утверждается.* Бесполезность активности FlyVis для `q_alive`, `q_birth` и достоверности движения (не проверялось); иной дизайн глаза; 5-Гц режим для считывания.

*Проверено.* 11 тестов фовеации и гейта зелёные; строгий валидатор каталога — OK.
