# 🟢 Контекст соседних треков для различения ложных жизней (вариант (а)) — головы H0 / H1 (+ соседство) / H2 (+ соседство + муха), данные разработки

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** положительный · `life_context_neighbors_v1`

Разрешение автора 10.10: дешёвая диагностика контекста после [newval_error_analysis_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fnewval_error_analysis_v1) (ошибки — короткие жизни, неразличимые по нынешним признакам). Признаки соседства — только наблюдаемые, из выхода трекера (signatures.npz, outputs) по интервалу записи жизни; от сшивки и разметки не зависят: (1) одновременные — наибольшее и среднее перекрытие (IoU) с рамками других треков в тех же кадрах; среднее число рамок с IoU > 0,3; у наиболее перекрывающего соседа — длина записи, средняя уверенность детектора, совпадение класса; плотность (среднее число рамок в кадре); (2) предшественник и преемник — ближайшая запись, окончившаяся ≤ 30 кадров до начала (начавшаяся ≤ 30 кадров после конца) в пределах 2 размеров рамки: разрыв, расстояние, длина, уверенность, тот же номер трекера; признаки наличия. Перекрытие не трактуется как дубль заранее — вес выучивает голова. Головы — HistGradientBoosting, конфигурация 0 (life_filter_boost_v1), одинаковая процедура: H0 — нынешние признаки без мухи (751); H1 — H0 + соседство; H2 — H1 + муха (сигнатуры начала и конца). Обучение — жизни train 130 (метки с выхода перекрёстной сшивки — голова пары с другой половины train); порог — правило с ограничениями (потеря объектов ≤ 1 % и верных рамок ≤ 0,5 % в каждой из 5 частей по видео, прогнозы вне обучения внутри train 130; наибольшая средняя разность HOTA с ДИ > 0, иначе «ничего не удалять»); dev 35 — только проверка. Новые 97 видео не используются. scripts/life_context_neighbors.py.

## Вопрос
Добавляет ли контекст соседних треков информацию для различения ложных жизней, даёт ли это выигрыш полного трекера, и вносит ли муха вклад сверх той же головы с контекстом?

## Гипотеза
Соседство (перекрытие с длинным уверенным треком, близкий предшественник/преемник) отличает ложные короткие жизни (дубли, мерцание) от обрывков настоящих.

## Ожидалось (до прогона)
Критерии на dev 35 (до прогона): C1 — AP H1 − H0 > 0, ДИ по видео > 0; C2 — HOTA фильтра H1 − без фильтра > 0, ДИ > 0 (порог из train); C3 — AP H2 − H1 > 0, ДИ > 0 и HOTA H2 − H1 > 0, ДИ > 0. Ночь dev — отдельно. Остановка: C1 не выполнен → (а) остановить, перейти к (б) (цепочка и внешность — отдельно); C1 выполнен, C2 нет → остановить. Новые видео — только при C2 и C3 и отдельном согласовании загрузки и расчёта.

## Решение
C1 и C2 выполнены, C3 — нет. По заранее записанному правилу перехода к новым видео ради вопроса о мухе нет (C3 не выполнен). Фильтр с соседством — кандидат улучшения носителя; его независимая проверка на новых видео — отдельное решение автора (загрузка и расчёт согласуются отдельно). Следующее по разрешению автора — отдельно (б): связь жизни со сшитой цепочкой и внешность MASA, парно без мухи и с мухой, тем же протоколом.
