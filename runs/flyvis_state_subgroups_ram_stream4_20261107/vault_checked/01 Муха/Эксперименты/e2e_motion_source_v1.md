# 🟢 Сквозной трекер: рычаги надёжности предсказания (источник движения Калман/DIS, буфер IoU) и голова надёжности без мухи и с мухой — HOTA на обучающих видео

↑ [[01 Муха/Темы/Движение мухи|Движение мухи]] · **Исход:** отрицательный · `e2e_motion_source_v1`

Главный риск диссертации — нет сквозного результата «трекер с мухой лучше трекера без мухи». MotionSourceByteTrack (надстройка над XYWHByteTrack, в режиме по умолчанию байт-в-байт равна стенду — тест) имеет два рычага: (1) центр рамки при ассоциации из Калмана или из переноса DIS; (2) буфер IoU первой ассоциации (заимствовано: C-BIoU, Yang et al., WACV 2023). Этап 1 — статические варианты (всегда DIS; буфер 0,1/0,2/0,3), чтобы найти рычаг с запасом по HOTA. Этап 2 — тот же рычаг, управляемый головой надёжности предсказания (Н2): geometry+DIS против geometry+DIS+муха (с сетчаткой М1); переключение/буфер по вероятности ненадёжности. Выбор параметров — на dev (35 видео), отчёт — test (35) и val7; параметры трекера — стенда.

## Вопрос
Даёт ли сигнал надёжности предсказания (и вклад мухи в него) прирост HOTA/IDF1 в самом трекере?

## Гипотеза
Хотя бы один рычаг имеет запас по HOTA; управление им по голове надёжности лучше статического варианта, а голова с мухой — лучше головы без мухи.

## Ожидалось (до прогона)
Этап 1: лучший статический рычаг (выбран на dev) даёт HOTA test > стенда. Этап 2: адаптивный вариант с мухой > адаптивного без мухи > стенда на test, парный бутстреп по видео с ДИ > 0 для «с мухой − без мухи»; val7 — знак тот же.

## Что сделано
Карточка записана до результатов (30.09.2026, 01:4x MSK). tracking/motion_source_bytetrack.py (4 теста), scripts/eval_motion_source.py; этап 1 запущен 01:42 (5 конфигураций × 77 видео).

## Получено
Этап 1 (dev / test / val7, HOTA): стенд 61.336 / 58.469 / 54.573; всегда DIS 61.208 / 57.972 / 53.308; буфер 0,5 61.766 / 59.121 / 54.680 (test: ΔHOTA по видео +0.758 ДИ [+0.251; +1.532], ΔIDF1 ДИ [+0.669; +2.933]). Этап 2: адаптивный буфер 0,3 + 0,8p по голове без мухи 61.818 / 59.208 / 54.642 (над буфером 0,5 на test ДИ [-0.201; +0.206]); та же голова + муха без сетчатки: ΔHOTA test ДИ [-0.023; +0.020]; голова с мухой-ламиной (обучена на 119 train, test 26 роликов с кэшем): ΔHOTA test -0.014 ДИ [-0.037; +0.016], val7 ДИ [-0.034; +0.011].

## Интерпретация
Рычаг с запасом по HOTA — буфер IoU (заимствованный C-BIoU): +0,65 HOTA и +1,34 IDF1 на test с ДИ > 0. Надёжность предсказания управляет буфером с небольшой пользой (IDF1 dev +0,32 значимо, HOTA — нет). Муха (без сетчатки и с ламиной) в голове надёжности не меняет трекер: её сигнал избыточен относительно рассогласования DIS; рычаг «адаптивный буфер» к тому же слабо чувствителен к качеству головы.

## Решение
Этап 1 выполнен (буфер > стенда на test, ДИ > 0). Этап 2: «с мухой лучше, чем без мухи» не выполнен ни без сетчатки, ни с ламиной → completed_negative по главному критерию. Практический результат линии B — буфер IoU (+ отложенное рождение, [birth_deferred_train_v1↗](obsidian://open?vault=ObsidianFlyVis&file=02%20%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fbirth_deferred_train_v1)). Для мухи — функции без аналога у DIS (Н11).

## Ограничения
Истина только на опорных кадрах 5 Гц; признаки мухи на этапе 2 берутся из кэша фовеи, построенного на треках стенда (сопоставление по кадру и id) — точно только до первого расхождения треков; окончательная проверка — с глазами онлайн.

## Нельзя заявлять
Перенос на другие детекторы и наборы данных.
