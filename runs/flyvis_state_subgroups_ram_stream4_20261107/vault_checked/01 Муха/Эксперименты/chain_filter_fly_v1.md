# 🟢 Голова «удалить итоговую цепочку» после сшивки с MASA: фильтр без мухи против того же фильтра с мухой

Решение автора 08.10: проверить голову удаления итоговой цепочки после MASA с одинаковыми признаками и протоколом без мухи и с мухой; прежнюю голову совпадения рамки начала/конца (stitch_realness_fly_v1) для этой задачи не использовать. Выход — жадная сшивка «база + MASA», порог 0,6, пересобранная по тем же вероятностям (проверка на 036f07d5-92c52ed8: файл идентичен исходному, HOTA 63,158). Метка цепочки — правило оракула (1 — все учитываемые рамки ложные, 0 — есть верная, −1 — нет учитываемых рамок, не обучается). Признаки цепочки: число жизней, длительность, число рамок, уверенность детектора, площадь/пропорции/положение рамки, скорость, класс, вход глаза (748); с мухой — плюс среднее и σ сигнатуры мухи по началам и концам жизней (2040). Логистическая регрессия C = 0,1. Обучение — dev 35; порог — по общему HOTA на dev по предсказаниям вне обучения (5 частей по видео), сетка 0,3–0,9; проверка — test 35 и val7. scripts/chain_filter_head.py.

## Вопрос
Выбирает ли сигнатура мухи ложные цепочки для удаления лучше, чем тот же фильтр без мухи?

## Гипотеза
Фильтр без мухи забирает часть запаса оракула; муха добавляет сверх него (AP «совпадение рамки» с мухой +0,029 в [stitch_realness_fly_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fstitch_realness_fly_v1) — косвенный довод).

## Ожидалось (до прогона)
test: (1) успех FlyVis — HOTA «с мухой − без мухи» по видео > 0, ДИ > 0; val7 — тот же знак; (2) контроль потерь: потерянных объектов разметки с мухой не больше, чем без мухи, и не больше 1 % объектов с попаданиями (ночью — отдельно); (3) справочно: фильтр без мухи − без фильтра > 0 (если фильтр помогает, а муха сверх него нет — это улучшение носителя, не решение проблемы FlyVis).

## Интерпретация
(1) Успех FlyVis не подтверждён: на test фильтр с мухой хуже того же фильтра без мухи (−0,165 HOTA по видео, ДИ ниже 0; ночью −0,226, ДИ ниже 0); на val7 +0,29 (ДИ содержит 0, 7 видео). (2) Обучаемый фильтр работает не тем путём, что оракул: оракул поднимает DetA при неизменной AssA, а обученный фильтр без мухи снижает DetA (58,19 → 57,95) и поднимает AssA (60,69 → 61,75) — он удаляет и настоящие цепочки (верных рамок −1 942, потеряно 161 объект разметки из 2 366, 6,8 %); выигрыш идёт за счёт ассоциации (вероятно, убираются короткие обрывки настоящих объектов с отдельным номером — не проверено). (3) Пороги выбраны в разных точках плоской кривой dev (без мухи 0,3, с мухой 0,7; разброс по сетке ≈ 0,2 HOTA): с мухой фильтр удаляет меньше и теряет меньше объектов (72 против 161), но и выигрывает меньше. Сравнение смешивает различающую способность и выбор рабочей точки — различающая способность мухи для цепочек этим опытом не измерена.

## Решение
Критерий успеха FlyVis не выполнен; критерий потерь не выполнен (оба варианта > 1 %; с мухой потерь меньше). Узел провала — связь цели и метрики: метка «цепочка полностью ложная» не отвечает тому, что фильтр реально делает (удаление с выигрышем в ассоциации ценой обнаружения). Предложить автору (правило 6.15): (а) сравнение мухи и контроля при одинаковой рабочей точке — сохранённые вероятности, кривая HOTA и потерь от доли удалённых цепочек, AP головы на test; (б) раздельные цели «ложная цепочка» (DetA) и «обрывок настоящего объекта» (решать сшивкой, не удалением).

## Нельзя заявлять
Нельзя заявлять вклад FlyVis в фильтрацию цепочек; нельзя заявлять, что фильтр без мухи удаляет ложные цепочки — его выигрыш идёт через ассоциацию при потере 6,8 % объектов разметки. Обучение на dev 35 (963 положительные цепочки); test — из обучающей части BDD100K; val7 — 7 видео. Ошибка 09.10: в признаках цепочки (chain_task) строки трекера собирались по номеру для каждой жизни цепочки — у цепочек с повторно вернувшимся номером строки этого номера учтены дважды (счётные признаки завышены; средние и квантили почти не меняются); в compact-варианте life_features смешивали жизни одного номера. Влияние на выводы не измерено.
