# 🟢 Запас фильтрации готового выхода по меткам при IoU = 0,5 (вариант А): удаление целых ложных цепочек

↑ [[01 Муха/Темы/Прочее о мухе|Прочее о мухе]] · **Исход:** положительный · `output_filter_oracle_v1`

Диагностика перед обучаемой головой удаления (разбор [stitch_realness_fly_v1↗](obsidian://open?vault=ObsidianFlyVis&file=01%20%D0%9C%D1%83%D1%85%D0%B0%2F%D0%AD%D0%BA%D1%81%D0%BF%D0%B5%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%82%D1%8B%2Fstitch_realness_fly_v1), решение автора 08.10: вариант А, без обучения). Готовый выход не пересчитывается; из него по разметке удаляются рамки. Выходы: стенд без сшивки (runs/stitch_v2/gap150_dist5/stitch/geometry_2) и сшивка «база + MASA», жадная (…/base_masa_0.6). Ступени: 1 — без фильтра (воспроизведение исходного HOTA); 2 — удалить целые цепочки (итоговый id), у которых все учитываемые рамки ложные; 3 — удалить все ложные рамки. Ступень 3 считается заново для каждого выхода (прежние +2,83 из runs/oracle_ladder — другое вмешательство: кандидаты удалялись до трекера, трекер проходил заново). Диагностическое правило «ложная»: в кадре и классе — венгерское сопоставление при IoU ≥ 0,5, несопоставленная рамка > 50 % в области crowd — игнор (как предобработка TrackEval BDD100K); это не полное правило HOTA (пороги 0,05–0,95, согласованность номеров). Сверка на 036f07d5-92c52ed8: верных 2308 = CLR_TP, ложных 66 = CLR_FP, ступень 1 = исходный HOTA 62,392. Отчёт: HOTA, DetA, AssA, верные/ложные/пропущенные рамки (общие и по видео раздельно), сколько удалённых рамок имели IoU ≥ 0,3 / ≥ 0,1, ночь/день (cond из runs/oracle_ladder/report.json). Доля запаса (HOTA₂ − HOTA₁)/(HOTA₃ − HOTA₁) — по общей метрике, для каждого выхода, только при положительном знаменателе. scripts/output_filter_oracle.py.

## Вопрос
Есть ли запас HOTA у удаления целых ложных цепочек из готового выхода после сшивки с MASA?

## Гипотеза
Удаление полностью ложных цепочек поднимает HOTA выхода после MASA; заметная доля запаса ступени 3.

## Ожидалось (до прогона)
Основной критерий перехода к обучаемой голове (для выхода после MASA): ступень 2 − ступень 1 на test > 0, ДИ по видео > 0; на val7 — положительный знак. Запас только на стенде не считается доказательством запаса после MASA.

## Интерпретация
Запас фильтрации готового выхода по меткам при IoU = 0,5 есть, и он устойчив: удаление целых полностью ложных цепочек из выхода после MASA даёт +1,35 HOTA общей (test, 58,983 → 60,329), по видео +1,28 с ДИ выше 0 и 35/35 видео в плюс; val7 +0,56 общей, +0,68 по видео, 7/7. Это 45 % (test) и 38 % (val7) запаса удаления всех ложных рамок. Прирост почти весь в DetA (+2,5), AssA почти не меняется (+0,07), пропущенные и верные рамки не меняются — удаляются только ложные. Ночью доля запаса выше (58 % на test). Из удаляемых рамок 12 % (425 из 3649) имели IoU ≥ 0,3 с эталоном — на нижних порогах HOTA они засчитывались, но итог всё равно положительный. Оракул знает разметку; достижимая доля зависит от того, насколько голова различит полностью ложные цепочки.

## Решение
Переход к обучаемой голове удаления цепочек для выхода после MASA разрешён по критерию. Следующая карточка (до прогона): голова «цепочка полностью ложная» на готовом выходе после MASA; метка — по правилу этого опыта (опорные кадры, IoU 0,5, crowd — игнор, цепочки без учитываемых рамок — «неизвестно»); три варианта при одинаковом трекере: без фильтра / фильтр без мухи / фильтр с мухой; порог — на данных подбора; HOTA, DetA, AssA, FP/FN, потери настоящих объектов ночью; условие успеха мухи — HOTA «с мухой − без мухи» > 0, ДИ > 0. Вариант Б (удаление до сшивки) — отдельно.

## Нельзя заявлять
Это оракул по разметке: число показывает запас, а не достижимый результат. Формулировка — «запас фильтрации готового выхода по меткам при IoU = 0,5», не полное правило HOTA. test — из обучающей части BDD100K (детектор видел эти видео); val7 — 7 видео, ночных из них 2. Не относится к варианту Б (удаление до сшивки).
