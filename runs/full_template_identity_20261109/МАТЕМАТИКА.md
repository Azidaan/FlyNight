# Почему общая поддержка сдвигов уменьшает шаблон

1. Действующее условие

Пусть T(x) — уже заданное аффинное совмещение прошлой рамки с текущей, B = [l, u] — текущая прямоугольная рамка, S — неизменный набор поисковых сдвигов. Старая проверка оставляет точку только при l ≤ T(x) + s ≤ u для каждого s из S. Неравенства рассматриваются отдельно по двум координатам.

Нижняя граница одновременно требует T(x) ≥ max_s(l − s) = l − min_s(s). Верхняя требует T(x) ≤ min_s(u − s) = u − max_s(s). Поэтому пересечение в точности равно прямоугольнику [l − min_s(s), u − max_s(s)]. Если хотя бы одна нижняя граница больше верхней, пересечение пустое. Это алгебраическое равенство, а не приближённая оценка по видео.

При симметричных крайних сдвигах ±a по горизонтали и ±b по вертикали непрерывная доля площади равна max(w − 2a, 0) · max(h − 2b, 0) / (w · h). Это доля площади, а не обязательно такая же доля дискретных гексагональных ячеек. Ограничения прошлой рамкой и полем глаза дополнительно уменьшают фактическую поддержку.

2. Единственная изменяемая проверка

Новая опора сохраняет все ячейки внутри прошлой рамки, если их проекции доступны в поле текущего глаза при всех тех же сдвигах. Принадлежность всем сдвинутым текущим рамкам не требуется. Следовательно, прежние ячейки остаются подмножеством новой опоры. Внутри одного предъявления опора одинакова для всех 19 сдвигов: максимум не может выбрать меньший шаблон только ради большего сходства.

Масштабирование, положение рамки, сетка сдвигов, карты и функция корреляции не меняются. Новый шаблон всё ещё может содержать фон или закрытый участок. Алгебра не доказывает, что добавленные ячейки несут индивидуальные признаки машины.

3. Основание и контроль

В Bertinetto, Valmadre, Henriques, Vedaldi, Torr, Fully-Convolutional Siamese Networks for Object Tracking (2016), раздел 2.1, формула 2, целый пространственный шаблон сопоставляется с переведёнными окнами большего поискового поля через взаимную корреляцию. Первичный текст: https://arxiv.org/pdf/1606.09549. Заимствован принцип фиксированного шаблона в доступном поисковом поле; их обученная сеть и их трекер не реализуются. Перенос на FlyVis и текущие детекции является нашей гипотезой.

Сильнейшая альтернатива — добавленные ячейки дадут преимущество через геометрию, фон или обычную картинку. Поэтому протокол фиксирует одинаковый геометрический контроль с числом доступных ячеек, равные 34-канальные входные контроли и сравнение старой/полной опоры при одной и той же модели. Прирост числа ячеек не является успехом по личности.
